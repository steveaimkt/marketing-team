# 실습 입력 · 020 제품 개선 백로그 우선순위

아래 한 줄을 클로드에게 그대로 말하면 된다.

```
sample-data/A브랜드-리뷰-200건.csv 로 개선 백로그 우선순위 매겨줘
```

가용 인주를 같이 주면 「이번 분기 실행 라인」이 표에 그어진다.

```
sample-data/A브랜드-리뷰-200건.csv 로 백로그 우선순위 매겨줘. 분기 가용 4인주
```

## 이 실습이 쓰는 것

| 무엇 | 어디서 |
|---|---|
| 개선 요청 원재료 | `sample-data/A브랜드-리뷰-200건.csv` (용기·자극·배송 불만) |
| 페이지 문제 | `sample-data/A브랜드-상세페이지.md` 의 알려진 문제 3건 |
| Reach 모집단 | 분기 구매 고객 **1,800명** (`brand/profile.md` 없으면 이 값) |

## RICE 4요소 스케일 (이 표를 벗어나지 않는다)

| 요소 | 값 |
|---|---|
| **R**each | 분기당 영향 고객 **수** (실수치 · 비율 아님) |
| **I**mpact | 3(대폭) · 2(상) · 1(중) · 0.5(하) · 0.25(미미) |
| **C**onfidence | 100%(데이터) · 80%(유사 사례) · 50%(직감) |
| **E**ffort | 인주(person-week) · 최소 0.5 |

## 바꿔서 해 보기

- Reach 를 「분기 방문자 37,200」으로 바꿔 본다 → **순위가 통째로 뒤집힌다.**
  페이지 개선이 전부 위로 올라간다. 모집단을 섞으면 안 되는 이유가 여기 있다
- 가용 인주를 2로 줄여 본다 → 실행 라인이 2위에서 끊긴다
- 「정기구독 만들어줘」를 항목에 끼워 본다 → Effort 6인주라 점수가 낮게 나온다.
  **하고 싶은 것과 해야 하는 것이 갈리는 자리**다
