# 산출물 품질 체크리스트 (Certified Builder 표준)
> 모든 스킬 산출물이 지켜야 할 공통 기준. 스킬 제작·심사(커뮤니티 기여 스킬의 plugins/ 편입) 시에도 이 기준으로 심사한다.

## A. 산출물 공통 6항
- [ ] **결론 먼저** — 첫 3줄 안에 핵심 답이 나온다 (분석이면 판정, 제작이면 완성본)
- [ ] **숫자 근거** — 주장에는 수치·출처가 붙는다 (추정이면 "추정" 명시)
- [ ] **바로 실행 가능** — "~하세요"가 아니라 복붙 가능한 완성물 (카피면 완성 카피, 입찰이면 조정값)
- [ ] **브랜드 일관** — brand/profile.md·tone.md 기준과 충돌 없음
- [ ] **다음 액션** — 산출물 끝에 chains_to 기반 다음 스킬 추천 1~2개
- [ ] **표준 포맷** — 아래 B의 유형별 골격 준수

## B. 유형별 표준 골격
| 유형 | 골격 |
|---|---|
| 분석 리포트 | 판정 요약 3줄 → KPI 표 → 발견 사항 (근거 수치) → 액션 제안 (우선순위) |
| 제작물 (카피·콘텐츠) | 완성본 → 변형안 (A/B) → 사용 가이드 1줄 → 게이트 결과 블록 |
| 기획안 | 결론(권고안) → 근거 3 → 실행 계획 (담당·기한) → 리스크 1 |
| 진단 | 점수/등급 → 강점 2 · 약점 2 → 처방 (스킬 체인 제안) |

## C. 스킬 제작 심사 5항 (plugins/ 편입 심사용)
- [ ] 표준 YAML 헤더 완비 (id~version 15필드 — SPEC.md §2, id·chains_to 따옴표 필수)
- [ ] STEP이 재현 가능 — 같은 입력이면 누가 돌려도 같은 구조의 산출물
- [ ] profile.md 참조가 명시돼 있고 브랜드 재질문이 없다
- [ ] gate 판정이 정확하다 (대외 발행물인데 gate: false면 반려)
- [ ] 실제 실행 검증 1회 이상 (샘플 키트로 완주 로그 첨부)

## D. 금지 사항
- 근거 없는 성과 보장 표현 ("무조건 매출 상승")
- 사용자 데이터를 산출물에 무단 인용 (샘플/실데이터 모드 구분 명시)
- 스킬 안에서 다른 스킬 전문(全文) 복붙 — chains_to로 연결할 것
