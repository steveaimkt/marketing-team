# 마케팅 팀 · marketing-team

> **방법론 100개를 지휘하는 팀 15명.** 설치하면 그 자리에서 전원이 뜬다.
> 디렉터 1 · 팀장 10 · 스태프 4. 우리말로 부르면 담당 팀장이 받아
> 계획을 브리핑하고, 만들고, 규제 게이트를 통과시켜 **파일로 남긴다.**

---

## 외울 문장은 셋뿐이다

| 언제 | 말할 것 | 끝나는 조건 |
|---|---|---|
| 처음 받았을 때 | **「팀 점검하자」** | 15명이 실제로 뜨고 첫 산출물 파일이 생기면 |
| 우리 회사에 맞출 때 | **「팀 구축하자」** | 편성안 승인 + 첫 업무가 실제로 돌면 |
| 그다음부터 | **그냥 말하면 된다** | 끝나지 않음 |

```
리뷰 분석해줘          경쟁사 비교해줘        이번 달 광고 어땠어
상세페이지 써줘         예산 다시 짜줘         광고애널리틱스 돌려줘
```

명령어를 외우지 않는다. **부르는 말 454개**가 뒤에서 받고, 안 걸리면 3단 폴백이 받는다.
전체 명부는 [100-skills/ROUTING.md](100-skills/ROUTING.md).

## 설치 · 두 길

### ① 플러그인으로 · **이쪽을 권한다**

클로드 코드(데스크탑 앱·터미널·확장 어디서든) 안에서 두 줄이면 끝난다.

```
/plugin marketplace add steveaimkt/marketing-team
/plugin install marketing-team
```

그다음 작업할 폴더를 하나 열고 한마디 한다.

```
팀 점검하자
```

→ 담당 15명이 떴는지 확인하고, **그 폴더에 `brand/` · `outputs/` · `logs/` 를 만들어 준다.**
앞으로 산출물은 전부 그 폴더에 쌓인다.

| 왜 이쪽인가 | |
|---|---|
| 설치가 **두 줄** | 클론할 필요도, 폴더를 고를 필요도 없다 |
| 업데이트가 **한 줄** | `/plugin marketplace update` · 내가 채운 `brand/` 와 **충돌하지 않는다** |
| 여러 폴더에서 같은 팀 | 프로젝트마다 팀을 다시 깔지 않는다 |

**제품(팀·방법론)과 내 데이터(브랜드·산출물)가 분리돼 있기 때문**에 이게 가능하다.
경로 규칙은 [docs/공통규약.md §0](docs/공통규약.md).

### ② 폴더를 열어서 · 책 실습용

저장소를 클론하고 폴더를 연 다음 「팀 점검하자」.
`.claude/agents` · `.claude/skills` 가 상위 폴더를 가리키도록 연결돼 있어 그대로 뜬다.

방법론 100개 파일과 산출물이 **한 폴더에 다 보이는** 것이 장점이다. 실습에는 이쪽이 낫다.
다만 업데이트할 때 `git pull` 이 내가 채운 `brand/profile.md` 와 부딪힌다 — 오래 쓸 거면 ①로 간다.

> ⚠️ **윈도우에서 클론했다면 점검이 특히 중요하다.** 깃이 연결 고리를 텍스트 파일로 받아 오는 일이 있고,
> 그러면 담당이 하나도 안 걸린다. 「팀 점검하자」가 그것을 찾아 그 자리에서 고친다.

## 구조

```
사용자 (모든 ⏸ 승인의 최종 결재권자)
   │
디렉터 marketing-director        입구 하나 · 접수 → 브리핑 → 위임 → 게이트 → 조립 → 기록
   │
   ├─ 팀장 10   방법론 100개를 10으로 나눠 맡는다
   │   research 001~010 · product 011~020 · content 021~030 · social 031~040 · ads 041~050
   │   commerce 051~060 · analytics 061~070 · crm 071~080 · brand-sales 081~090 · ops 091~100
   │
   └─ 스태프 4
       staff-gate-auditor  규제 감사관 · 이 팀에서 ⛔ 를 찍는 유일한 담당
       staff-reviewer      관점 검수관 · 대표·재무·고객·법무·브랜드 5관점 병렬
       staff-skill-builder 방법론 제작관 · 만들기 전담, 실행하지 않는다
       staff-council       자문단 · 답이 갈리는 질문을 충돌하는 프레임워크로 압박
```

**팀장은 검토자도 겸한다.** 「광고 검토해줘」처럼 부르면 6관점으로 판정하고
**고칠 지점 3개까지만** 짚는다 — 대신 만들어 주지는 않는다 ([docs/검토-절차.md](docs/검토-절차.md)).

**멈춰 서는 자리가 32곳.** 대외로 나가는 산출물 32개는 발행 전 규제 검사를 통과해야 한다.
표시광고법이 공통이고, `brand/profile.md` 의 업종에 따라 화장품법·건강기능식품법이 자동으로 갈아 끼워진다.
**통과하지 못한 산출물은 전달되지 않는다.**

## 방법론 100개는 일부러 등록하지 않는다

방법론은 `100-skills/` 에 파일로 있지만 Claude Code 에 스킬로 **등록되지 않는다.** 의도된 설계다.

| 방식 | 매 세션 고정 비용 |
|---|---|
| 100개를 전부 스킬로 등록 | **약 14,700 토큰** (카테고리당 ~1,475 × 10) |
| 이 패키지 (담당 15 + 스킬 4) | **약 3,700 토큰** |

명부 한 장만 상시로 보고, **본문은 매칭된 순간에만 연다.**
그 명부를 여는 자리가 `방법론찾기` 스킬이다.

## 검사

```bash
node scripts/verify.mjs          # 플러그인으로 설치해도 그대로 뜨는가
node scripts/validate-skills.mjs # 방법론 100개가 계약대로 생겼는가
```

`verify.mjs` 가 보는 것은 **"폴더로 열면 되는데 플러그인으로 설치하면 안 되는"** 함정들이다.

| 검사 | 왜 |
|---|---|
| `plugin.json` 의 `repository` 가 문자열인가 | 객체면 플러그인 전체가 로드되지 않는다 |
| `agents/` 에 하위 폴더가 없는가 | 하위 폴더의 담당은 플러그인에서 통째로 사라진다 |
| `agents/` 의 모든 `.md` 에 frontmatter 가 있는가 | 없으면 그 문서가 유령 담당으로 등록된다 |
| `skills/` 가 한 단계인가 | 2단계 아래는 스캔되지 않는다 |
| 담당·스킬이 가리키는 문서가 실재하는가 | 없는 파일을 가리켜도 아무 에러가 안 난다 |

## 폴더

| 경로 | 무엇 |
|---|---|
| `agents/` | 담당 15명. **평탄하게 둔다** — 하위 폴더를 만들지 않는다 |
| `skills/` | 방법론찾기 · 팀-구축 · 팀-점검 · 브랜드프로필 |
| `docs/` | 공통규약 · 검토 절차 · 팀 헌장. **에이전트가 아닌 문서는 전부 여기** |
| `100-skills/` | 방법론 100개 카탈로그 (사본 · `scripts/sync-skills.mjs` 로 갱신) |
| `brand/` | 브랜드 프로필 · 톤 · 팀 편성 (빈 템플릿으로 배포) |
| `sample-data/` | 브랜드 정보가 없어도 완주하게 하는 샘플 |
| `outputs/` `logs/` | 산출물과 원장이 떨어지는 곳 |
