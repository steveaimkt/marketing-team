# 마케팅 팀 · marketing-team

> **스킬 100개를 지휘하는 팀 15명.** 설치하면 그 자리에서 전원이 뜬다.
> 디렉터 1 · 팀장 10 · 스태프 4. 우리말로 부르면 담당 팀장이 받아
> 계획을 브리핑하고, 만들고, 규제 게이트를 통과시켜 **파일로 남긴다.**

---

## 두 가지만 하시면 됩니다

| | 하는 일 | 결과 |
|---|---|---|
| **①** | 설치하고 **`1-시작하기`** | 스킬 100개를 **바로 씁니다.** 「리뷰 분석해줘」 하면 됩니다 |
| **②** | **`2-브랜드-등록하기`** 로 우리 회사 정보 | 그 정보로 100개를 골라 **내 에이전트가 조립됩니다** |

②는 정보를 다 받으면 **그 자리에서 조립까지 이어집니다.** 따로 부르지 않습니다.
조립되면 100개가 우리 것 **15~30개**로 줄고, 반복 업무는 체인이 되어 이름으로 불립니다.

### 두 모드 · 채운 만큼 올라갑니다

| 모드 | 켜지는 조건 | 어떻게 도나 |
|---|---|---|
| **① 스킬** | 기본 | 스킬 하나를 완주한다. 브랜드가 비면 샘플로 돈다 |
| **② 내 에이전트** | 브랜드 정보를 채우면 **자동 조립** | 우리 스킬·체인·기본값으로 돈다. 실적이 쌓인다 |

**「어떤 모드로 쓰시겠어요?」를 묻지 않습니다.** 채우면 올라갑니다.

### 스킬 다섯

| 스킬 | 언제 |
|---|---|
| `1-시작하기` | 설치 직후 · 주기 점검 |
| `2-브랜드-등록하기` | 우리 회사 정보 → **내 에이전트 자동 조립** |
| `3-내-에이전트-만들기` | 다시 조립할 때 (보통 ②에서 자동으로 돈다) |
| `스킬-100-보기` | 무엇을 시킬 수 있는지 볼 때 |
| `마케팅-디렉터` | 실제 업무 요청을 받아 **직접 실행**하는 자리 (자동) |

```
리뷰 분석해줘          경쟁사 비교해줘        이번 달 광고 어땠어
상세페이지 써줘         예산 다시 짜줘         광고애널리틱스 돌려줘
```

명령어를 외우지 않는다. **부르는 말 454개**가 뒤에서 받고, 안 걸리면 3단 폴백이 받는다.
전체 명부는 [100-skills/ROUTING.md](plugins/marketing-team/100-skills/ROUTING.md).

## 설치

### ① 코워크 · Cowork

```
사이드바 Customize → Plugins → Add marketplace
→  steveaimkt/marketing-team
→  목록에 뜬 marketing-team 을 Install
```

설치하면 **Skills 탭에 5개, Agents 탭에 2명**이 뜬다.
그다음 **`1-시작하기`** 를 누른다.

### ② 클로드 코드 · Claude Code

```
/plugin marketplace add steveaimkt/marketing-team
/plugin install marketing-team@marketing-team
```

작업할 폴더를 하나 열고 **`1-시작하기`**. 그 폴더에 `brand/` · `outputs/` · `logs/` 를 만들어 준다.
앞으로 산출물은 전부 그 폴더에 쌓인다.

### ③ 폴더를 열어서 · 클로드 코드 전용

저장소를 클론해 폴더를 열어도 된다. 열고 나서 **`1-시작하기`**. `.claude/agents` · `.claude/skills` 가 상위 폴더를 가리키도록
연결돼 있어 그대로 뜬다. 스킬 파일과 산출물이 **한 폴더에 다 보이는** 것이 장점이라 책 실습에는 이쪽이 낫다.

다만 **코워크에서는 이 방법이 없다.** 코워크에는 「내 폴더를 연다」가 없어서 플러그인이라야 한다.
그리고 오래 쓰면 `git pull` 이 내가 채운 `brand/profile.md` 와 부딪힌다.

> ⚠️ **윈도우에서 클론했다면 점검이 특히 중요하다.** 깃이 연결 고리를 텍스트 파일로 받아 오는 일이 있고,
> 그러면 담당이 하나도 안 걸린다. `1-시작하기` 가 그것을 찾아 그 자리에서 고친다.

| | 코워크 | 클로드 코드 |
|---|---|---|
| 플러그인 설치 | ✅ | ✅ |
| 클론해서 폴더 열기 | ❌ | ✅ |

**제품(팀·스킬)과 내 데이터(브랜드·산출물)가 분리돼 있어서** 플러그인이 성립한다.
경로 규칙은 [docs/공통규약.md §0](plugins/marketing-team/docs/공통규약.md).

## 구조

```
사용자 (모든 ⏸ 승인의 최종 결재권자)
   │
디렉터  ← 메인 대화에서 직접 돈다 (스킬)
   │     접수 · 라우팅 · 브리핑 ⏸ · 실행 · 조립 · 기록
   │     스킬 100개를 직접 굴린다. 실행자를 따로 두지 않는다
   │
   └─ 판정 담당 2  ← 내가 나를 검사할 수 없는 자리에만
       staff-gate-auditor  대외 발행물 규제 검사 · ⛔ 유일 권한
       staff-reviewer      대표·재무·고객·법무·브랜드 5관점 (sonnet)
```

**서브에이전트는 「독립성이 필요한 판정」에만 씁니다.** 실행은 전부 메인에서 합니다.
여러 사람이 나눠 맡고 승인 흐름·스케줄이 필요해지는 것은 **OS 층의 일**입니다.

**팀장은 검토자도 겸한다.** 「광고 검토해줘」처럼 부르면 6관점으로 판정하고
**고칠 지점 3개까지만** 짚는다 — 대신 만들어 주지는 않는다 ([docs/검토-절차.md](plugins/marketing-team/docs/검토-절차.md)).

**멈춰 서는 자리가 32곳.** 대외로 나가는 산출물 32개는 발행 전 규제 검사를 통과해야 한다.
표시광고법이 공통이고, `brand/profile.md` 의 업종에 따라 화장품법·건강기능식품법이 자동으로 갈아 끼워진다.
**통과하지 못한 산출물은 전달되지 않는다.**

## 스킬 100개는 일부러 등록하지 않는다

스킬은 `100-skills/` 에 파일로 있지만 Claude Code 에 스킬로 **등록되지 않는다.** 의도된 설계다.

| 방식 | 매 세션 고정 비용 |
|---|---|
| 100개를 전부 스킬로 등록 | **약 14,700 토큰** (카테고리당 ~1,475 × 10) |
| 이 패키지 (담당 15 + 스킬 4) | **약 3,700 토큰** |

명부 한 장만 상시로 보고, **본문은 매칭된 순간에만 연다.**
그 명부를 여는 자리가 `스킬-100-보기` 스킬이다.

## 검사

```bash
node scripts/verify.mjs          # 플러그인으로 설치해도 그대로 뜨는가
node scripts/validate-skills.mjs # 스킬 100개가 계약대로 생겼는가
```

`verify.mjs` 가 보는 것은 **"폴더로 열면 되는데 플러그인으로 설치하면 안 되는"** 함정들이다.

| 검사 | 왜 |
|---|---|
| `plugin.json` 의 `repository` 가 문자열인가 | 객체면 플러그인 전체가 로드되지 않는다 |
| `agents/` 에 하위 폴더가 없는가 | 하위 폴더의 담당은 플러그인에서 통째로 사라진다 |
| `agents/` 의 모든 `.md` 에 frontmatter 가 있는가 | 없으면 그 문서가 유령 담당으로 등록된다 |
| `skills/` 가 한 단계인가 | 2단계 아래는 스캔되지 않는다 |
| 담당·스킬이 가리키는 문서가 실재하는가 | 없는 파일을 가리켜도 아무 에러가 안 난다 |

## 폴더

```
.claude-plugin/marketplace.json   마켓플레이스 카탈로그
plugins/marketing-team/           ← 플러그인 본체 (설치되는 것은 이 폴더다)
  agents/       판정 담당 2명 · 평탄하게 둔다 (하위 폴더 금지)
  skills/       스킬-100-보기 · 3-팀-짜기 · 1-시작하기 · 2-브랜드-등록하기
  docs/         공통규약 · 검토-절차 · 팀-헌장 · 도메인-금기 · 자문-프레임워크
  100-skills/   스킬 100개 카탈로그
  brand-templates/  빈 템플릿 원본 — 작업 폴더의 brand/ 와 이름이 겹치면 안 된다
  sample-data/  브랜드 정보가 없어도 완주하게 하는 샘플
  scripts/      verify · validate-skills · build-leads · sync-skills
.claude/                          클론해서 폴더로 열 때의 연결 고리
brand/ outputs/ logs/ inputs/     클론 모드의 작업 폴더
```

> **왜 한 겹 더 들어가 있나** · 마켓플레이스는 「저장소 어디에 플러그인이 있는지」를 가리켜야 한다.
> 저장소 루트 자체를 가리키면(`"source": "./"`) **코워크가 동기화에 실패한다**(2026-08-22 실측).
> 그래서 플러그인을 `plugins/marketing-team/` 에 두고 거기를 가리킨다.
> `scripts/verify.mjs` 가 이 규칙을 매번 검사한다.
