# 042 네이버 쇼핑광고 진단

> 합산 ROAS 하나에 속지 않는다. 브랜드/일반 키워드를 분리 집계해 착시를 해부하고, 일반 키워드에서 키워드·소재·입찰 3개 항목 진단으로 조정안을 낸다.
> 계승: 교육 파트너 6-3 naver-ads-analyzer 의 브랜드/일반 분리 집계(합산 1.54 → 브랜드 7.41 vs 일반 0.71 착시 해부) + 데이터랩 교차검증 사분면. 네이버 데이터랩·검색광고 데이터를 넣으면 실측으로 바뀐다 → `docs/데이터-가져오기.md`.

> **내 일이 아닌 것**: **네이버 한 매체**를 깊게 본다. 여러 매체 취합은 045, 예산 이동은 046.
> 나누는 말은 `docs/헷갈리는-쌍.md` 에 있다.

## Contract
- 🔴 **집계 단위를 먼저 결정하고 산출물 첫 줄에 적는다.** 리포트에 어떤 열이 있는지로 정한다.
  · `키워드` 열이 있으면 **키워드형**(파워링크·검색광고) → 브랜드/일반으로 나눈다
  · `키워드` 가 없고 `광고그룹`·`소재`·`상품` 열이 있으면 **쇼핑검색형** → 광고그룹과 상품으로 나눈다
  · 둘 다 있으면 **가장 작은 단위**로 간다. 어느 쪽으로 나눴는지를 밝히지 않은 리포트는 다음 달과 비교할 수 없다.
- ⛔ **쇼핑검색형에 브랜드/일반 키워드 분리를 강행하지 않는다.** 그 계정에는 내가 산 키워드가 없다.
  대신 **광고그룹 사이의 편차**와 **상품별 클릭률·클릭당비용**으로 같은 착시를 해부한다.
- **합산 ROAS 단독 보고 금지**: ROAS 를 늘 3개 나란히 낸다. **키워드형 리포트는** 합산·브랜드·일반 3개를 낸다.
  **쇼핑검색형은** 합산, 전환이 발생한 단위, 전환 0 단위 3개로 같은 자리를 채운다.
- 결과 기준은 `brand/profile.md` §4 **손익분기 ROAS**다. "일반 키워드 ROAS < BEP = 적자" 결론, profile 미작성 시 BEP 1.0 폴백 + `[추정]` 태그.
- 브랜드 키워드 판별 규칙(자사명·제품명 포함)을 산출물에 명시한다. 같은 입력이면 같은 분리 결과가 나온다.
- 조정 제안(입찰 하향·소재 교체·LP 개선·축소)마다 대상 키워드·근거 수치·예상 효과를 병기한다.
- 조정 실행은 사용자 승인 후 광고시스템에서 수동으로 한다 (본 스킬은 읽기·분석 전용).

## Phases
1. **기준 로드**: profile.md §4 손익분기 ROAS·목표 ROAS + §1 브랜드명·제품명(브랜드 키워드 판별 시드) 자동 참조.
2. **데이터 확보와 유형 결론**: `docs/데이터-가져오기.md` 모드 결과: 검색광고 REST API(공식 MCP 없음, API_KEY·SECRET_KEY·CUSTOMER_ID 서명 호출) 연결 시 실데이터, **미연결 시 광고주센터 → 보고서 → 대용량 다운로드 CSV 업로드 폴백**. 🔴 **파일을 열면 열 이름부터 읽어 집계 단위를 결정하고 산출물 첫 줄에 적는다**(Contract 첫 항). **쇼핑검색형은 상품이 가장 작은 단위이므로 키워드 분리 대신 상품·광고그룹 단위로 같은 로직을 적용한다.**
3. **분리 집계 · 정한 단위로 나눈다**: 합산과 나란히 놓고 착시를 해부한다.
   · **키워드형**: 자사명·제품명 포함 = 브랜드, 그 외 = 일반. ("브랜드 ROAS가 높은 건 광고 실력이 아니라 이미 살 사람의 방어 입찰")
   · **쇼핑검색형**: 광고그룹별, 그다음 상품별. ("합산이 본전선을 넘으면 전환 0인 상품이 안 보인다. 매출을 만든 광고비가 전체의 몇 %인지 반드시 적는다")
4. **3개 항목 진단**: 항목은 같고 읽는 법이 유형마다 다르다.
   · ① **효율**: BEP 미달 랭킹(지출 큰 순). 키워드형은 일반 키워드, 쇼핑검색형은 상품.
   · ② **검색어 적합도**: CTR 저조. 키워드형이면 소재 문구가 약한 것이고, **쇼핑검색형이면 살 생각이 없는 사람에게 붙고 있는 것**이다(검색어를 내가 고르지 않았다). 고칠 자리가 광고가 아니라 상품명이다.
   · ③ **입찰**: 같은 입찰가에서 실제 CPC가 벌어지면 입찰 문제가 아니다. **노출순위와 CPC를 나란히 놓아** 검색어 적합도 문제인지 나눈다. 쇼핑검색형에서 CPC가 비싼 상품은 입찰을 내릴 자리가 아니다.
5. **수요 교차검증 (선택)**: 데이터랩 MCP 연결 시 카테고리 대표 키워드(5자 이하) 13개월 트렌드로 사분면 결과: 🔴 수요↓수익↓=중단 / 🟡 수요↑수익↓=컷 금지·진단(가격·LP·리뷰) / 🟢 수요↑수익↑=확대(시즌 피크 예산 집중). 미연결 시 이 단계는 생략하고 명시.
6. ⏸ **조정안 확정**: 키워드별 조치(하향/교체/개선/축소) 리스트를 승인받고 → 체인: 046 ROAS 진단 (매체 간 이동).

7. **파일로 남긴다**: 위 산출물을 아래 「⛔ 착지」의 세 파일로 저장하고 경로를 알린다. 화면에만 띄우고 끝내지 않는다. 마케터가 다음 날 다시 열 수 있어야 한다.
   > 쓰기 권한이 없으면 **실패로 처리하지 않는다.** 산출물은 그대로 화면에 내고 맨 아래에 "`outputs/{날짜}/042-naver-shopping-ads/042-naver-shopping-ads.md` 로 저장하려 했으나 권한이 없어 남기지 못했습니다" 를 적는다. 못 한 일을 못 했다고 말하는 것도 산출물의 일부다.

> **`.html` 에는 그래프를 넣는다.** 표만 있는 화면은 어디가 새는지 한눈에 안 보인다.
> · **① 단위별 광고비와 전환매출** 막대: 지출 큰 순으로, 쓴 돈과 번 돈을 나란히 놓는다
> · **② 단위별 ROAS** 막대: ROAS 내림차순으로 놓고 손익분기와 목표를 가로 점선 두 줄로 얹고 값을 적는다
>   막대는 세 가지로만 칠한다(목표 위 / 사이 / 손익분기 아래). 아래 한 줄에 **손익분기 아래가 몇이고 그 광고비가 얼마인지** 적는다

  예 · 「ROAS 1.4는 광고비의 16%가 만든 숫자다」 · 「입찰가는 모두 500원인데 클릭당비용은 4배 벌어졌다」
  · 「성수기를 두 달 앞두고 껐다」

### ③ 광고그룹별 광고비와 전환매출 (차트)
### ④ 일별 추이 (차트) — 세팅이 바뀐 구간을 갈라 **구간 요약**을 아래에 붙인다
  「11/24~11/27 · 일평균 노출 24,500 · 클릭률 0.18% · 전환 0 · 전체 비용의 31%」 처럼 한 줄씩
### ⑤ 검색 수요와 집행 시기 (차트 · 데이터랩 연결 시) — 수요 피크와 집행기가 어긋났는지 본다
  🔴 차트마다 **아래에 해석 한 줄**을 붙인다. 「위 막대 = 광고비 · 아래 막대 = 전환매출. 지출 1위 …는 회수가 0이다」

### ⑥ 분리 집계표 — 정한 단위로 나눈다
**키워드형** | 그룹 | 키워드 수 | 광고비 | 매출 | ROAS | 결론 | → 합산 / 브랜드 / 일반 세 줄
**쇼핑검색형** | 광고그룹 | 노출수 | 클릭수 | 클릭률 | CPC | 광고비 | 순위 | 전환 | ROAS | 월 검색량 |

### ⑦ 3개 항목 진단 (대상·지출·ROAS·병목·조치) — 대상은 ①에서 정한 단위다
### ⑧ 수요 교차검증 사분면 (데이터랩 연결 시) — 🔴중단 {n}개 / 🟡진단 {n}개 / 🟢확대 {n}개

### ⑩ 다음 액션 — 무엇을 언제까지 · 누가 하나
  참고본처럼 **절로 세운다.** 맨 끝 한 줄로 흘리지 않는다.

  · PC·모바일 분리 자료는 최근 31일까지만 남는다

>    첫 판에는 그 가운데 **하나만** ⑥의 닫는 줄로 옮긴다.

>   결론 카드에는 비중과 함께 **회수가 0인 광고비 실액**을 작은 글씨로 붙인다(「165,352원 회수 0」)

>   전환매출이 0인 상품이 7개라 오른쪽 끝에서 7줄이 한자리에 겹친다. **이 자료로는 그릴 수 없다.**

## Anti-Patterns
- **합산 ROAS로 "잘 되고 있다" 보고**: 브랜드 키워드가 평균을 끌어올린 착시. 분리 없는 보고는 규격 위반.
- **브랜드 ROAS를 성과로 자랑**: 자사명 검색은 어차피 살 사람. 광고 실력 지표는 일반 키워드 ROAS다.
- **적자 키워드 일괄 컷**: 수요 상승기(🟡) 키워드를 끄면 시즌 매출을 잃는다. 컷 전에 수요 교차검증.
- **쇼핑검색형에 키워드 분리 강행**: SHOPPING 캠페인엔 입찰 키워드가 없다. Contract 첫 항의 유형 결론을 건너뛰면 여기서 걸린다.
- **CTR 저조를 유형 구분 없이 「소재 문구가 약하다」로 읽는 것**: 쇼핑검색형에서는 검색어를 내가 고르지 않았으므로 상품명 문제다.
- **92일 이전 데이터 API 조회 시도**: /stats는 최근 92일만. 과거 분석은 광고주센터 CSV 다운로드 경로로.

## 활용
- **월간 광고 결산**: 매월 초 지난달 CSV로 분리 리포트 → "브랜드 빼면 얼마?"를 경영 보고 첫 줄로.
- **대행사 성과 검증**: 대행사가 보고하는 합산 ROAS를 본 스킬로 분리 재집계하고, 일반 키워드 효율로 재계약을 판단한다.
- **시즌 예산 설계**: 데이터랩 사분면에서 🟢 확대 키워드의 피크 월을 확인해 046 재배분 시나리오의 근거로 전달.
- **연관 키워드 확장 리서치**: 광고 데이터가 없어도 검색광고 API /keywordstool 경로로 월 검색량·연관 키워드 확장은 가능하다. 신규 캠페인 설계 입력으로 쓴다.
- **입찰 전 시뮬레이션**: /estimate 예상 입찰가 조회로 신규 키워드의 진입 CPC를 추정하고, BEP ROAS 역산으로 감당 가능한 CPC 상한을 먼저 계산한다.

> 실연동 메모 (connections.md 🟡): 검색광고 API 키 3종(API_KEY·SECRET_KEY·CUSTOMER_ID)은 manage.searchad.naver.com → 도구 → API 사용 관리에서, 데이터랩 키 2종(CLIENT_ID·CLIENT_SECRET)은 developers.naver.com에서 발급한다. 발급처가 서로 다르다.
> /stats 성과 조회는 최근 92일 한정이다. 과거 분석은 광고주센터 보고서 CSV 다운로드 경로로.
> 쇼핑검색(SHOPPING)형 계정은 산출물 ②·③의 "키워드" 열이 "상품/광고그룹" 열로 치환된다. 분리 원리는 동일하다.
