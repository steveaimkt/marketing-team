# 🛠 스킬 제작: 경쟁 계정 주간 변화 기록

## ⏸ 범위 확정

| 항목 | 내용 |
|---|---|
| 처음 요청 | "경쟁사 모니터링 전체를 스킬로" |
| **좁힌 범위** | **인스타 3계정의 주간 변화만** (신규 게시물·팔로워 증감·해시태그 변화) |
| 뺀 것 | 웹사이트 변경 · 가격 변동 · 광고 소재 → **003 이 이미 한다** |
| **그릇 판정** | **스킬** (절차 고정 · 판단 개입 낮음) |

> 003 경쟁사 상시 모니터링과 겹치는 부분을 먼저 뺐다.
> **있는 스킬과 겹치면 새로 만들 이유가 없다.**

## 데이터·레퍼런스

| 항목 | 상태 |
|---|---|
| 입력 로우데이터 | 인스타 계정 3개 URL ✅ |
| 잘된 결과물 | 지난 4주 수기 시트 **3장** ✅ |
| **공통 구조** | 「계정 / 신규 게시물 수 / 눈에 띈 것 1줄 / 팔로워 증감」 4열 |

## 구조 설계

**스텝 5개**
1. 계정 3개 최근 7일 게시물 수집 (입력: URL → 출력: 게시물 목록)
2. 게시물 유형 분류 (제품·정보·이벤트·기타)
3. 전주 대비 변화 산출 (게시 빈도·유형 구성·팔로워)
4. **눈에 띈 것 1줄** 작성 (계정당 1개)
5. 4열 시트 형식으로 산출

**사람 게이트 1개** ⏸
> Phase 4 뒤 · "눈에 띈 것이 이게 맞나요?" · 기본값 = 게시 빈도가 가장 크게 변한 계정만

**판단 룰 (숫자)**
| 룰 | 값 |
|---|---|
| 「눈에 띈 것」 판정 | 게시 빈도 **±50%** 또는 유형 구성 **±30%p** |
| 팔로워 이상 | 주간 **+5%** 초과 시 ⚠️ (이벤트·구매 의심) |
| 수집 실패 | 3계정 중 1개라도 실패하면 **그 사실을 산출물에 적는다** |

**안전 규칙 3종**
- ✅ 읽기 전용 (원본 시트 미수정 · 사본에 append)
- ✅ 계정명 마스킹 불필요 (공개 계정)
- ✅ 발행 없음 (내부 기록용)

## 어디를 봐야 하나

**요청 범위를 절반 이하로 잘랐다.** "경쟁사 모니터링 전체"에서
"인스타 3계정 주간 변화"로. 나머지는 **003 이 이미 한다.**
새 스킬을 만들기 전에 겹치는 것부터 빼는 게 이 스킬의 첫 일이다.

**routing-eval 5줄 중 3줄이 「잡으면 안 되는」 질문이다.** 새 스킬을 만들면
비슷한 질문을 다 가져가서 기존 스킬이 안 불린다.
**오발동 검사를 안 하면 스킬을 늘릴수록 라우팅이 나빠진다.**

**판단 룰이 숫자다.** "변화가 크면"이 아니라 "±50%".
"적당히 좋으면"은 룰이 아니다. **숫자가 없으면 매번 다른 결과가 나오고,
다른 결과가 나오면 사람이 다시 확인하게 되어 자동화가 아니게 된다.**
