# 100 내 마케팅 OS 설계

이 OS 의 종착점. 스킬 99개를 하나씩 쓰는 단계를 지나 **내 업무에 배선하는 방법**을 다룬다.
설명의 대상이 곧 이 패키지 자신이라, **실물에 없는 구조를 지어내지 않는 것**이 이 스킬의 계약이다.

> **내 일이 아닌 것** · 업무를 진단해 무엇을 자동화할지 고르는 것은 **마케팅 업무 자동화 진단(091)**,
> 없는 스킬을 만드는 것은 **나만의 스킬 만들기(092)**. 여기는 **있는 것을 배선하는 자리**다.

## Contract
1. 구조 해설은 **실제 파일**을 근거로 한다 — `skills/마케팅-CMO/` · `agents/staff-*.md` ·
   `100-skills/ROUTING.md` · `gates/` · `docs/`. 없는 파일·없는 담당을 그리지 않는다.
2. 라우팅 원리는 **Progressive Disclosure** 로 설명한다 — 상시로 보는 것은 `ROUTING.md` 한 장,
   개별 `SKILL.md` 는 매칭된 순간에만 연다.
3. 배선의 모든 요소는 **실존 식별자**로 매핑한다 — 스킬은 `ROUTING.md` 의 번호로,
   체인은 각 스킬의 `chains_to` 로.
4. `mutating: true`(발송·발행·집행) 7개와 `gate: true` 32개의 **승인 지점이 배선표에 반드시 들어간다.**
   자동화 설계에서 사람 게이트를 없애지 않는다.
5. 정기 실행 제안은 **수동으로 돌려 산출물이 안정된 스킬**에 한한다. 첫 설계부터 전 자동화를 권하지 않는다.

## 게이트 (대화형에서만 멈춘다)

| 멈추는 곳 | 묻는 것 | 기본값 |
|---|---|---|
| Phase 3 | `my-playbook.md` 가 없으면 「091 을 먼저 할까요?」 | **091 을 먼저** 권한다 · 업무를 모르면 배선을 못 한다 |
| Phase 4 | 보유 스킬로 못 채우는 자리 | **비워 두고 092 로 표시.** 없는 스킬을 있는 것처럼 배치하지 않는다 |
| Phase 5 ⏸ | 「이 배선으로 갈까요?」 | 제시만 · **정기 실행을 걸지 않는다** |

## Phases

1. **구조 해설 — 셋이 일한다** — 실물 그대로 그린다.

   ```
   사용자 (모든 ⏸ 승인의 최종 결재권자)
      │
   CMO  ← 메인 대화에서 직접 돈다 (에이전트가 아니라 스킬이다)
      │    받고 · 판단하고 · 직접 만들고 · 파일로 남긴다
      │    스킬 100개를 직접 굴린다. 실행자를 따로 두지 않는다
      │
      ├─ CCO(규제)  staff-gate-auditor   발행 전 검사 · ⛔ 를 찍는 유일한 담당
      └─ CSO(검수)  staff-reviewer       CEO·CFO·고객·CLO·CBO 5관점
   ```

   **왜 판정 둘만 밖에 있나** — 만든 자가 자기 것을 검사하면 통과시킨다.
   실측(2026-08-22 · 같은 상세페이지): CMO 자체 판정 2건 vs CCO 독립 검사 8건·반려.
   **왜 100개를 다 안 올리나** — 전부 등록하면 매 세션 상시 약 14,700 토큰이다.

2. **업무 한 건의 생애** — 다섯 게이트를 사용자 예시 1건으로 시연한다.

   ```
   G1 무슨 일인지 + 필요한 데이터  ⏸ → G2 계획·말린다  ⏸ → G3 실행·CCO·파일 착지
   → G4 보고(나왔나/알게 됐나/부족한가) → G5 다음과 피드백  ⏸
   ```

   **왜 브랜드를 재질문 안 하나** — `brand/profile.md` 하나를 100개 스킬이 전부 읽는다.

3. **내 업무 로드** — `brand/my-playbook.md`(091 산출물)에서 주력 업무·주간 루틴을 읽는다.
   없으면 3문답(주간 반복 업무 / 병목 하나 / 팀 규모)으로 약식 수집하고 091 을 권한다.

4. **배선 설계** — 업무를 세 층으로 매핑한다.
   - **주력 분야 2~4** — 업무 비중 상위 카테고리 (예: 콘텐츠 021~030 · 광고 041~050)
   - **스킬 체인 1~3종** — 업무 흐름과 일치하는 연쇄 (예: 주간 발행 → 021 → 022 → 027)
   - **정기 실행 후보 0~2건** — 수동 안정화가 끝난 것만. 발행·발송은 수동 유지
   - **승인 정책표** — 어디서 ⏸ 멈추고 누가 결재하나

5. ⏸ **배선 승인** — 제시하고 사용자가 확정·조정한다 (분야 증감 · 체인 교체 · 정기 실행 보류).

6. **운영 가이드 산출** — 요일별 루틴 · 에스컬레이션 규칙(⛔ 2회면 사용자 판단) ·
   성장 경로(같은 스킬 3회 → `brand/my-skills/` 로 전용화, 없는 업무 → 092).
   `my-playbook.md` 갱신을 제안하고, 확정 체인 1종을 함께 한 번 돌려 본다.

> ⛔ **착지 · 여기로 쓴다** — `outputs/{날짜}/100-orchestration/100-orchestration.md`
> 경로를 새로 만들지 않는다. 위 줄을 그대로 쓰고 `{날짜}` 만 오늘로 바꾼다.
> 아티팩트·스크래치패드·화면 출력은 착지가 아니다. **파일이 없으면 안 한 것이다.**

## Anti-Patterns
- **없는 조직을 그린다** — 팀장·스태프·오케스트레이터는 v0.6.0 에서 사라졌다.
  실물은 **CMO 하나 + 판정 둘**이다. 근거는 항상 `agents/` 와 `skills/` 의 실제 파일.
- **전 스킬 동시 가동 설계** — 100개를 다 쓰는 팀은 없다. 분야 2~4 로 시작해 이력으로 넓힌다.
- **게이트 없는 자동화** — 정기 실행에서 발행·발송 승인을 빼면 OS 가 아니라 폭주 기관차다.
- **진단 없는 처방** — `my-playbook.md` 도 약식 문답도 없이 범용 배선을 내놓는 것.
- **설명만 하고 설계 안 함** — Phase 1~2 에서 끝내지 않는다. 산출물은 **그 사용자의 배선표**다.

```
내 마케팅 OS 설계해줘
```

**보유 스킬로 못 채우는 자리는 비워 둔다.** 없는 스킬을 배치하면
배선표는 완성되고 실행은 안 된다. 빈자리는 092 로 만들 대상이다.

## 활용
- **완주자의 졸업** — 091 진단 → 092 첫 스킬 제작 → 100 배선. 도구 사용자에서 운영자로.
- **1인 마케터** — 혼자서 분야 3개 + 주간 루틴을 배선하면 「1인 100역」이 된다.
  검수는 CSO(검수) 의 5관점이 대신 압박한다.
- **팀 도입** — 승인 정책표를 실제 결재선으로 치환하면 그대로 조직 운영 규정이 된다.
