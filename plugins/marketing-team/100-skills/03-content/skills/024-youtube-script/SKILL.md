# YouTube 스크립트

> 주제 + 증명 소재 → 훅-시연-데이터-CTA 6섹션 10분 스크립트 (타임코드·화면 지시 포함).
> 계승: 유튜브 스크립트 제작 에이전트 `script-creator`의 TYPE-A 6섹션 구조·TC 계산 공식·구어체 나래이션 규칙 + marketing-os `youtube-content-brief`의 데이터 근거 앵글 도출.

## Contract
- 스크립트는 6섹션 고정 비율을 따른다: HOOK 6% · PAIN 8% · KEY 7% · DEMO 20% · BRIDGE 40% · CTA 20%.
- 첫 30초(HOOK) 안에 영상의 최종 결과물을 먼저 보여준다 — 과정 설명으로 시작 금지.
- 총 글자 수 = 목표 분 × 253자 ±10% (10분 = 약 2,530자). 섹션별 TC는 글자 수로 검산한다.
- 모든 주장 옆에 시연 장면 지시 또는 데이터 근거가 붙는다. 근거 없는 수치는 [추정] 태그.
- 산출물은 compliance-gate 통과 전에는 전달되지 않는다.

## 게이트 (대화형에서만 멈춘다)

> ⚠️ **이 스킬은 재료가 없어도 멈추지 않는다 — 형식을 바꾼다.** (위 「형식은 증거가 정한다」)
> 없는 수치를 지어내면 산출물 전체가 거짓말이 되므로, 지어내는 대신 **증거가 필요 없는 형식**으로 간다.
> 대시보드·cron 에서는 아래 기본값으로 완주하고 산출물에 그 사실을 밝힌다.

| 멈추는 곳 | 묻는 것 | 기본값 (답 없으면) |
|---|---|---|
| Phase 2 | 증거가 없으면 **먼저 증거를 요청한다**(아래 HANDOFF) · 그다음 형식을 묻는다 | **요청을 낸 채로 과정 공유형 진행** · 요청은 산출물 맨 아래에 열어 둔다 · **멈추지 않는다** |
| Phase 3 | 경쟁 채널 데이터가 없으면 "타깃 페인포인트로 앵글을 잡을까요?" | `[추정]` 태그 + 페인포인트 기반 |
| Phase 6 뒤 | "총 길이가 목표에서 벗어났습니다. 어느 섹션을 줄일까요?" | DEMO 를 줄인다 (HOOK·CTA 는 안 건드린다) |

## 형식은 증거가 정한다 · 셋 중 하나로 반드시 완주한다

⛔ **증거가 없다고 대본을 안 쓰지 않는다. 형식을 바꾼다.**
성과 증명형은 「이렇게 해서 이렇게 됐다」를 보여주는 형식이라 **수치를 지어내면 허위 광고**가 된다
(표시광고법). 유튜브는 **내려도 캡처가 남는다.** 그런데 **못 만든다는 뜻은 아니다.**

| 형식 | 언제 | 증거 | 무엇이 다른가 |
|---|---|---|---|
| **① 성과 증명형** | Before/After 수치·화면이 있다 | 필수 | 결과를 먼저 던진다 · 가장 강하다 |
| **② 과정 공유형** | 지금 하고 있는 중이다 | **불필요** | **결과를 약속하지 않는다** · 「이렇게 하고 있습니다」 |
| **③ 문제 해설형** | 우리 사례가 아직 없다 | **불필요** | 「왜 안 되는가」를 설명 · 남의 사례·공개 자료로 성립 |

### ⛔ 형식을 바꾸기 전에 · **증거를 먼저 요청한다**

증거가 없을 때 **첫 마디는 「형식 바꿀까요?」가 아니다.** 「이것만 주시면 됩니다」다 —
`docs/공통규약.md §0-c D2·D3`. ①이 가장 강한 형식인데, 요청도 안 해 보고 내려갈 이유가 없다.

```
① 여기까지 했습니다   앵글·6섹션 구성·타임코드 틀까지 잡아 뒀습니다
② 여기서 막혔습니다   Before/After 증거가 없어 「이렇게 해서 이렇게 됐다」를 못 씁니다
③ 이렇게 뚫습니다     HANDOFF → 사용자 (아래)
```

```
HANDOFF → 사용자
- 여기까지 했습니다 : 앵글 · 6섹션 구성 · 글자 수 배분까지 (증거 자리만 비어 있음)
- 이것만 해주시면   : ⓐ 시작·종료 화면 2장 — 날짜가 보이게 (채널 분석 / 광고 관리자 /
                      주문 관리 / 문의함 어디든, 캡처 5분)  ⓑ 그 기간이 언제부터 언제까지
                      ⓒ 그때 같이 바꾼 것이 있으면 한 줄 — 없으면 「없음」
- 그러면 제가       : 성과 증명형 10분 대본을 그대로 이어서 냅니다 (가장 강한 형식)
- 지금 대신         : 과정 공유형 8분 대본을 먼저 드립니다 ·
                      **결과를 약속하지 못해 설득력이 한 단계 낮습니다**
```

**⏸ 요청을 낸 뒤에 형식을 묻는다.** 묻고 기다리지는 않는다 — 답이 없으면 **②로 진행한다.**

```
  ① 위 세 가지를 주시면  성과 증명형으로 다시 만듭니다 (가장 강함)
  ② 과정 공유형으로      오늘 찍을 수 있습니다 · 증거가 오면 ①로 다시 만듭니다
  ③ 문제 해설형으로      우리 사례가 없어도 됩니다

답이 없으면 ② 로 진행하고, 위 요청은 산출물 맨 아래에 그대로 남깁니다.
```

⛔ **②·③ 으로 갔어도 요청을 지우지 않는다.** 산출물 맨 아래에 이 줄을 반드시 남긴다 —

> **증거가 오면 성과 증명형으로 다시 만듭니다.** 필요한 것: 시작·종료 화면 2장(날짜 보이게) · 기간 · 같이 바꾼 것.

**갈아탄 순간 요청이 사라지면 사용자는 ①을 영영 못 받는다.**

### ②·③ 의 섹션 구성 (증명형과 다르다)

```
② 과정 공유형 (8분)
   HOOK 0:00~0:15    무엇을 하려는지 · 결과를 약속하지 않는다
   WHY  0:15~1:30    왜 이걸 하는가 · 문제 정의
   PLAN 1:30~4:00    무엇을 어떻게 할 것인가 (여기가 본론)
   NOW  4:00~6:30    지금까지 한 것 · 화면 있으면 그대로
   OPEN 6:30~7:30    아직 모르는 것 · **이게 신뢰를 만든다**
   CTA  7:30~8:00    「결과 나오면 또 올리겠습니다」

③ 문제 해설형 (8분)
   HOOK 0:00~0:15    흔한 오해 하나를 던진다
   CASE 0:15~2:00    공개 사례·업계 통계 (출처 명시)
   WHY  2:00~5:00    왜 그런 일이 생기는가 (구조 설명)
   HOW  5:00~7:00    그래서 무엇을 봐야 하는가
   CTA  7:00~8:00    우리 얘기는 여기서 한 줄만
```

⛔ **②·③ 에서 성과를 암시하지 않는다.** 「이렇게 하면 됩니다」는 ①의 문장이다.
②는 「이렇게 하고 있습니다」, ③은 「이런 구조입니다」다. **형식을 바꿨으면 문장도 바꾼다.**

⚠️ **③ 은 출처를 반드시 단다.** 남의 사례를 근거로 쓰는 형식이라 출처가 빠지면 도용이 된다.

## Phases
1. **브랜드 컨텍스트 로드** — `brand/profile.md` + `brand/tone.md` 자동 참조 (톤·포지셔닝·금기어).
2. **증명 포인트 확정** — 이 영상이 증명할 것 1개(핵심 메시지)와 증거 목록(Before/After 수치·시연 결과물·데이터) 정리. **증거가 비면 먼저 HANDOFF 로 요청한다** ⏸ (위 「증거를 먼저 요청한다」) — 요청을 낸 뒤에야 형식을 묻는다.
3. **앵글 도출** — 경쟁 영상·채널 데이터가 있으면 갭(경쟁은 다루는데 나는 없는 주제)과 강점 교집합으로 앵글 결정. 데이터 미연결 시 타겟 페인포인트 기반 추정([추정] 태그).
4. **6섹션 설계** — HOOK(결과물 시연+무료 공개 예고) → PAIN(구체 수치로 문제 공감) → KEY(해결책 3가지 예고+구독 유도) → DEMO(시스템 설명, 비유 활용) → BRIDGE(단계별 실행 튜토리얼) → CTA(Before/After 대조+자료 배포+다음 행동).
5. **나래이션 작성** — 구어체("~거든요/~잖아요" 혼용) + 구체 수치 + 일상 비유. 감정 곡선: 문제(진지)→해결(밝게)→성과(신나게). 화면 지시 마커 삽입: `<!-- 슬라이드: -->` / `<!-- 화면녹화: -->`.
6. **TC 계산 + 검산** — 섹션별 글자 수 ÷ 253 = 분. SCREEN 구간은 행동 여유 ×1.2. 누적 TC를 섹션 헤더에 표기하고 총량 ±10% 검산.
7. **컴플라이언스 게이트** — [gates/compliance-gate.md](../../../gates/compliance-gate.md) 3 STEP 실행 (과장 성과·보장성 표현 집중 스캔), 게이트 결과 블록 부착.
8. **체인 제안** — 025 썸네일·제목 A/B (HOOK 소재 전달) → 026 쇼츠/릴스 대본 팩 (이 스크립트가 롱폼 원본).

9. **파일로 남긴다** — 위 산출물을 `outputs/{날짜}/024-youtube-script/024-youtube-script.md` 로 저장하고 경로를 알린다. 화면에만 띄우고 끝내지 않는다 — 마케터가 다음 날 다시 열 수 있어야 한다.
   > 쓰기 권한이 없으면 **실패로 처리하지 않는다.** 산출물은 그대로 화면에 내고 맨 아래에 "`outputs/{날짜}/024-youtube-script/024-youtube-script.md` 로 저장하려 했으나 권한이 없어 남기지 못했습니다" 를 적는다. 못 한 일을 못 했다고 말하는 것도 산출물의 일부다.

> ⛔ **착지 · 여기로 쓴다** — `outputs/{날짜}/024-youtube-script/024-youtube-script.md`
> 경로를 새로 만들지 않는다. 위 줄을 그대로 쓰고 `{날짜}` 만 오늘로 바꾼다.
> 아티팩트·스크래치패드·화면 출력은 착지가 아니다. **파일이 없으면 안 한 것이다.**

## Anti-Patterns
- **과정부터 시작하는 오프닝** — "안녕하세요, 오늘은…"은 이탈 1순위. HOOK은 결과물이 먼저다.
- **주장만 있고 증거 없는 섹션** — "정말 편해집니다"에 시연도 수치도 없으면 성과 증명형이 아니다. 근거를 붙이거나 문장을 뺀다.
- **요청도 안 해 보고 형식부터 내리기** — 증거는 「주세요」 한 번이면 오는 경우가 많다. **①이 가장 강한 형식**인데 요청을 건너뛰면 매번 한 단계 낮은 대본만 나온다. 그리고 ②로 갔어도 요청은 산출물에 남긴다.
- **형식을 바꿔 놓고 문장은 안 바꾸기** — 과정 공유형인데 "이렇게 하면 됩니다"라고 쓰면 결과를 약속한 것이다. **②는 「하고 있습니다」, ③은 「이런 구조입니다」**다.
- **문어체 나래이션** — "~하였습니다" 낭독체는 TTS·실녹음 모두 어색하다. 말하듯 쓴다.
- **비율 무시 BRIDGE 축소** — 시청 지속의 몸통은 40% 튜토리얼. 설명(DEMO)만 길어지면 이탈 곡선이 꺾인다.
- **TC 없는 납품** — 글자 수 검산 없는 스크립트는 촬영 현장에서 반드시 초과한다. 253자/분 공식으로 검산 후 전달.

## 실습해 보기

```
유튜브 대본 써줘. 주제 〈리뷰 200건을 하루 만에 분석한 방법〉, 증거는 3시간→12분
```

**증거를 안 주면 먼저 요청하고, 그래도 없으면 형식을 바꾼다.**
성과 증명형은 증명할 것이 있어야 성립하지만, **유튜브 대본 자체는 증거 없이도 만든다** —
과정 공유형·문제 해설형이 그 자리다. 다만 **순서를 지킨다: 요청 → 형식 전환 → 요청 유지.**
⛔ 바꾸지 않는 것은 하나 — **없는 수치를 만들지 않는다.**
