# 실습 입력 · 019 A/B 테스트 설계

아래 한 줄을 클로드에게 그대로 말하면 된다.

```
sample-data/A브랜드-메타광고-30일.csv 기준으로 상세페이지 A/B 테스트 설계해줘
```

## 이 실습이 쓰는 것

| 무엇 | 어디서 |
|---|---|
| 기준 전환율 | `sample-data/A브랜드-메타광고-30일.csv` · 신제품_런칭_전환 캠페인 30일 집계 · 클릭 13,686 / 전환 418 = **3.05%** |
| 일 트래픽 | 같은 캠페인 · 클릭 13,686 ÷ 30일 = **456/일** |
| 바꿀 것 | `sample-data/A브랜드-상세페이지.md` 의 알려진 문제 · "첫 화면에 가격과 용량이 안 보인다" |

## 이 실습은 실패를 보여 준다

돌려 보면 **표본이 안 나온다.** 14주가 걸린다는 답이 온다.
그게 오류가 아니라 결과다. 이 스킬이 존재하는 이유의 절반이 거기 있다.

**표본수를 계산하지 않고 시작한 테스트는, 결과가 나와도 그 결과를 믿을 수 없다.**
"일주일 돌려보고 이긴 쪽으로 가자"가 왜 안 되는지를 이 실습이 숫자로 보여 준다.

## 바꿔서 해 보기

- 「MDE 를 상대 30%로 올려서」라고 붙여 본다 → 14주가 3.5주로 줄어든다
- 「4개 캠페인 트래픽을 합쳐서」라고 바꿔 본다 → 6주로 줄어든다 (일 트래픽이 456명이 아니라 2,022명이라서, 대신 캠페인마다 의도가 다른 트래픽이 섞인다)
- 일 트래픽을 「2,000」이라고 줘 본다 → 같은 설계가 훨씬 빨리 성립한다

## ⚠️ 이 스킬이 하지 않는 것

**테스트를 켜지 않는다.** 결론도 하지 않는다.
결과 데이터를 읽고 "어느 쪽이 앞섰나"를 결정하는 건 **047** 의 일이다.
019 는 데이터가 생기기 전에 끝난다.
