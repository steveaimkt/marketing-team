# 실습 입력 · 007 설문 설계

## ⚠️ 이 스킬은 두 번에 나눠 돈다

```
1차 (설계)  → 사람이 설문을 돌린다 → 2차 (분석)
```

**1차 · 설계만**
```
설문 설계해줘. 목적 〈왜 재구매를 안 하는지 알고 싶다〉
```

**2차 · 응답 받아 온 뒤**
```
설문 응답 분석해줘. 〈응답 CSV〉 첨부
```

1차만 돌려 봐도 된다. 설문지가 나온다.

## 목적을 「가설」로 바꾸는 것이 핵심

```
❌ "고객을 알고 싶다"        — 검증할 수 없다
✅ "30대는 가격보다 성분을 먼저 본다"  — 문항으로 물어볼 수 있다
```

Phase 2 에서 이걸 먼저 확인한다. 가설이 안 나오는 목적은 여기서 구체화한다.

## 가설은 어디서 가져오나

`brand/profile.md` 가 비어 있으므로 `sample_fallback`(`sample-data/A브랜드-리뷰-200건.csv`)의
실제 분류·건수에서 가설을 뽑는다. 수분 세럼(57건) 리뷰만 보면:

| 분류후보 | 저평점(≤2점) 건수 | 실제 문구 |
|---|---|---|
| 배송 | 9건 | "주문하고 닷새 만에 왔어요" |
| 자극 | 5건 (같은 태그 중 4건은 반대로 "민감성인데 트러블 없었어요" 5점) | "바르고 살짝 따가웠습니다" |
| 펌프 잔량 | 5건 | "용기 끝까지 못 써서 아깝습니다" |

**"자극" 태그는 반응이 갈린다** — 같은 민감성 피부인데 누구는 따갑고 누구는 괜찮다.
리뷰에는 피부 타입 자가 진술이 없어 이유를 못 밝힌다. **이 빈틈이 설문으로 넘어간다**
(`example/output.md` 의 H1·인구통계 문항 참조). ⚠️ 리뷰 200건 CSV는 Phase 1~4(가설 소스)까지만
쓰고, Phase 5~6(세그먼트 교차 분석)에는 쓰지 않는다 — 인구통계가 없어서 교차표를 못 만든다.
