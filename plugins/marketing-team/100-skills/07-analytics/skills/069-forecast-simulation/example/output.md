## 기준선

```
가중 공식 = 최근 7일 평균 × 50% + 전체 90일 평균 × 50%
최근 7일(07-23~07-29) 평균 = 54,547,000 ÷ 7 = 7,792,429
전체 90일 평균 = 671,377,000 ÷ 90 = 7,459,744
일평균 매출 = 7,792,429 × 0.5 + 7,459,744 × 0.5 = 7,626,087
8월(31일) 기준선 = 236,408,682
과거 주간 변동폭(12개 구간) ±σ = ±10.1%  →  오차 범위 212,522,000 ~ 260,295,000
```

> 90일 구간 중 가장 컸던 단일일(05-12, 13,412,000원)도 평균의 1.8배에 그쳐 **제외가 필요한
> 3배 이상급 스파이크는 없었다.** (이전 버전이 언급한 "07-11 기획전 3.2배"는 이 파일에 없는

## 어디를 봐야 하나

**기준선부터 틀려 있었다.** 이전 버전은 일평균 3,351,000원이라고 적었지만, 같은 파일을
python3 로 다시 집계하면 7,626,087원이다. 2.2배 차이가 시나리오 3안·민감도 표까지
전부 끌고 내려간다. **기준선 하나가 파일 전체를 오염시키는 지점**이 여기다.

**광고비 기준선을 067에서 그대로 가져왔다.** 이 CSV 자체엔 광고비 열이 없다. 지어내는 대신
**옆 스킬의 실측값을 이어 쓰고 [추정] 을 붙였다.** 데이터가 없다고 멈추지 않으면서도
숫자의 출처를 감추지 않는 방법이다.

**민감도 순위는 그대로다.** 기준선이 2.2배 커져도 "전환율·객단가가 광고비보다 강하다"는
결론은 안 바뀐다. 절대 금액이 커졌을 뿐 우선순위는 그대로라는 것도 재검증에서 확인해야 할
부분이다.

**"07-11 기획전 3.2배" 같은 구체적인 사건은 파일에 없으면 적지 않는다.** 이전 버전엔 이 문장이
있었지만 실제 90일 데이터 어디에도 3배 이상 스파이크가 없다. 그럴듯한 사건을 지어내는 것과
실제로 있었던 것을 구분하는 게 이 스킬의 존재 이유다.
