# 발화 점검 · smoke

> **정적 검사로 원리적으로 못 잡는 것이 있다.** `verify.mjs` 는 「파일 안에 그 문자열이 있나」를
> 볼 뿐이다. 스킬이 **실제로 열리는가**, 화면에 **그 문장이 나오는가**는 사람이 밟아야 안다.
>
> 실제로 두 번 당했다 —
> **① 디렉터 스킬이 발화 자체를 안 했다** (description 을 명령형으로 바꿔 해결).
> 문서는 완벽했고 verify 는 🔴 0 이었다.
> **② 서브에이전트가 있는데 「제한돼 있다」고 짐작하고 안 불렀다.**
>
> 릴리스마다 아래를 밟고, 결과를 `logs/smoke-{버전}.md` 로 남긴다.

## 어디서 밟나 · 두 판이다

| 판 | 어디서 | 왜 |
|---|---|---|
| ① 개발 확인 | 저장소 폴더 (`.claude/` 심링크 경유) | 빠른 반복 |
| ② **배포 확인** | **로컬 마켓플레이스로 설치한 빈 폴더** | ①은 **거짓 통과**가 난다 |

> ⚠️ **①에서 통과 판정을 내지 않는다.** 심링크로 새 스킬이 즉시 뜨는데 설치본은 옛 이름일 수 있다.
> 둘 다 켜져 있으면 같은 스킬이 두 벌 등록돼 어느 쪽이 열렸는지 알 수 없다.
> **②를 밟기 전에는 태그를 찍지 않는다.**

---

## 1. 입구 · 서로 가로채지 않는가

세 트리거가 전부 「마케팅팀 ~」으로 시작하므로 **가로채기 위험이 구조적으로 있다.**
셋을 **각각** 새 대화에서 친다.

| 입력 문장 | 열려야 하는 스킬 | 화면에 반드시 있어야 하는 것 |
|---|---|---|
| `마케팅팀 업무 시작하자` | **`AI-마케터`** | ⏸ · 「어떤 일부터」 |
| `마케팅팀 구축하자` | **`마케팅팀-구축하기`** | 작업 폴더 생성 안내 |
| `마케팅팀 업무 리스트 보여줘` | **`마케팅팀-업무리스트`** | 카테고리 10줄 |
| `업무 리스트 보여줘` | **`마케팅팀-업무리스트`** | 짧게 말해도 걸려야 한다 |

⚠️ **셋 다 「마케팅팀」으로 시작한다. 갈리는 것은 끝말이다.**

```
… 업무 시작하자      → AI-마케터          일을 한다
… 업무 리스트 보여줘  → 마케팅팀-업무리스트   목록만 본다
… 구축하자          → 마케팅팀-구축하기     설치·브랜드 등록
```

**「업무」가 둘에 들어 있다.** 매번 셋 다 밟아 서로 안 가로채는지 확인한다.
(2026-08-22 실측 — 겹침 0건)
서로 가로채면 준비 스킬이 업무 요청을 받거나 그 반대가 된다.

## 1-b. 남의 스킬이 가로채지 않는가

**제품 밖에서 오는 실패다.** 사용자 환경에 개인 스킬이 있으면 같은 문장을 먼저 채 간다.

```
실제 사례 (2026-08-22) — ~/.claude/skills/시장조사
  description 에 「리뷰 분석해줘」가 있어 AI-마케터를 가로챘다
  낸 것: input/ · output/ · LEDGER.md · 크래프트볼트   ← 전부 그 스킬의 규약
  마케팅팀 규약(outputs/{날짜}/{번호}-{슬러그}/)은 하나도 안 지켜졌다
```

**증상이 「AI 마케터가 규약을 어겼다」로 보인다.** 진짜 원인은 AI 마케터가 아예 안 열린 것이다.
산출물 경로가 통째로 낯설면 **먼저 이것부터 의심한다.**

| 확인 | 어떻게 |
|---|---|
| 충돌 목록 | `grep -l "리뷰 분석\|경쟁사\|상세페이지" ~/.claude/skills/*/SKILL.md` |
| 판정 | 산출물이 `outputs/{날짜}/{번호}-{슬러그}/` 밖에 떨어지면 **다른 스킬이 돈 것** |

## 2. 다섯 게이트 · 실제로 밟는가

입력 — `상세페이지 써줘`

| 확인 | 통과 기준 |
|---|---|
| G1 | 되짚기 한 번 · **필요한 데이터를 먼저** 말한다 · ⏸ |
| G2 | 계획 한 화면 · **말린다/더 싼 길/리스크** 중 해당하는 것 · ⏸ |
| G3 | 실행 · **AI 규제검토자 판정 블록**이 나온다 |
| G4 | 무엇이 나왔나 / 알게 됐나 / **부족한가** 셋 다 |
| G5 | 다음 제안 · **가장 큰 하나** · ⏸ |

## 1-c. 코워크에서 막히지 않는가

**코워크에는 터미널이 없다.** 승인을 요구하며 멈추면 첫 화면에서 막힌다.

| 확인 | 통과 기준 |
|---|---|
| `마케팅팀 구축하자` | **터미널 승인을 요구하지 않는다.** 파일을 직접 읽어 센다 |
| `100개 스킬 다 등록된 거야?` | 「등록 안 하는 것이 설계」를 **먼저 설명**한다. `node` 부터 찾지 않는다 |

> 실측 (2026-08-22) — 둘 다 `node verify.mjs` 승인을 먼저 요구했다. 고친 뒤 재확인 필요.

## 2-b. 실패했을 때 회수되는가

**실측 — 스킬 100개 중 10%가 파일을 안 남긴다.** 그때 결과물은 대화창에 살아 있다.

| 확인 | 통과 기준 |
|---|---|
| 「방금 거 저장해줘」 | 직전 산출물을 **그대로** 올바른 경로에 쓴다. **다시 만들면 실패** |
| 「저장 안 된 거 있어?」 | 원장 vs 실제 파일 대조 · **몇 건인지 먼저** 말한다 · 0건이면 「0건」이라고 말한다 |
| 규칙 밖 경로 | `outputs/2026-08-22/ads/…` 같은 것을 찾아 옮길지 묻는다 |

## 3. 완주 조건 · 파일이 실제로 남는가

| 확인 | 통과 기준 |
|---|---|
| 파일 착지 | `outputs/{날짜}/{번호}-{슬러그}/` 에 실물이 있다 |
| 규제 게이트 | 같은 폴더에 `gate.md` 가 있다 |
| 원장 1행 | `logs/build-log.md` 에 행이 늘었다 |

⚠️ 화면에만 뜨고 파일이 없으면 **실패다.** 「저장하지 못했습니다」라고 적혀 있어도 실패다.

## 4. 담당 둘 · 짐작하지 않고 실제로 부르는가

| 확인 | 통과 기준 |
|---|---|
| AI 규제검토자 | 발행물에서 **호출된다.** 「AI 규제검토자 미호출」·「제한돼 있습니다」가 나오면 **실패** |
| AI 사업검토자 | 「이 예산안 검토해줘」에 경영·재무·고객·법무·브랜드 중 지정한 관점으로 판정이 온다 |

> 폴백은 허용하되 **⚠️ 로만 착지한다.** 서브에이전트를 못 불렀는데 ✅ 가 나오면 실패다.

## 5. 직함 · 화면에 옛 이름이 없는가

| 확인 | 통과 기준 |
|---|---|
| 표기 | 화면에 **디렉터 · 감사관 · 검수관**이 한 번도 안 나온다 |
| 병기 | **`AI 규제검토자` · `AI 사업검토자`** 로 괄호가 붙어 있다 |

## 6. 샘플 · 브랜드 정보 없이도 완주하는가

`brand/` 가 빈 폴더에서 `리뷰 분석해줘`.

| 확인 | 통과 기준 |
|---|---|
| 완주 | 멈추지 않고 끝까지 간다 |
| 태그 | `[샘플]` 이 붙는다 |
| 안내 | 끝에 「우리 회사 걸로 바꾸려면 `마케팅팀-구축하기`」 한 줄 |

**밟지 않은 항목을 ✅ 로 적지 않는다.** 「미실행」이라고 적는다.

릴리스마다 결과를 **`scripts/smoke-results/v{버전}.md`** 로 남긴다 (`logs/` 는 gitignore 대상이라 사라진다).
지난 기록 — [3ce48f7](smoke-results/3ce48f7.md) · 실행 98% · 자연어 94%
**커밋 해시로 이름 짓는다.** 같은 버전명이 서로 다른 동작을 대표하면 안 된다.
