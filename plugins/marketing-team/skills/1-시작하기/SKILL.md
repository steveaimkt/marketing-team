# 팀 점검 · 있다고 말하지 않고 세어 본다

> **없는 것을 있다고 말하지 않는다.** 개수를 세고, 안 되는 것은 안 된다고 말한다.

> ⚠️ **경로 규칙은 `docs/공통규약.md §0` 이다.**
> `100-skills/` · `docs/` · `sample-data/` 는 **패키지 안** (플러그인이면 `${CLAUDE_PLUGIN_ROOT}` 아래, 폴더로 열었으면 현재 폴더).
> `brand/` · `outputs/` · `logs/` · `inputs/` 는 **언제나 현재 작업 폴더**다.

## 0. 작업 폴더부터 만든다 · 플러그인으로 설치했다면 특히

**팀은 패키지 안에 살고, 산출물은 내가 일하는 공간에 떨어진다.** 둘은 다른 곳이다.

「내가 일하는 공간」이 어디인지는 환경마다 다르다.

| | 작업 공간 |
|---|---|
| **코워크** | 지금 이 대화가 파일을 만드는 곳 |
| **클로드 코드** | 지금 열어 둔 폴더 |
| **폴더로 클론해 열었다면** | 그 저장소 폴더가 곧 작업 공간이다 |

거기에 이 넷이 있는지 본다. 없으면 **묻고 만든다** (⏸).

```
brand/     내 브랜드 정보 · 팀 편성      ← 없으면 빈 템플릿을 만든다
outputs/   산출물이 떨어지는 곳
logs/      실적 원장 · 팀 소집 로그
inputs/    내 파일을 넣어 두는 곳
```

- 넷 다 이미 있으면 그냥 넘어간다.
- 없으면 만든다. 빈 템플릿은 **패키지의 `brand-templates/` 에서 복사해 온다** (`${CLAUDE_PLUGIN_ROOT}/brand-templates/`).
  템플릿 정본은 그 한 곳뿐이다 — 두 벌을 두면 조용히 어긋난다.
- ⚠️ **패키지 안에 쓰지 않는다.** 거기 쓰면 플러그인을 업데이트할 때 산출물이 통째로 날아간다.

만들고 나면 한 줄로 알린다 — 「이 폴더가 앞으로 산출물이 쌓일 곳입니다: {경로}」

## 1. 어디서 도는지부터 가른다

**터미널을 쓸 수 있는지**로 갈린다. 물어보지 말고 스스로 판단한다.

| | 검사 방법 |
|---|---|
| **클로드 코드** (터미널 있음) | 2-A · 스크립트를 돌린다 |
| **코워크** (터미널 없음) | 2-B · 파일을 직접 읽어 센다 |

둘 다 **보는 항목은 같다.** 세는 방법만 다르다.

## 2-A. 스크립트로 · 클로드 코드

    node "${CLAUDE_PLUGIN_ROOT}/scripts/verify.mjs"

`${CLAUDE_PLUGIN_ROOT}` 를 붙이는 이유는, 설치판에서 **현재 폴더가 패키지가 아니기 때문**이다.
폴더로 클론해 열었으면 `node scripts/verify.mjs` 도 된다. 둘 다 실패하면 2-B 로 간다.

## 2-B. 파일을 읽어서 · 코워크

스크립트 없이 같은 것을 센다. **파일을 세는 것뿐이라 어디서든 된다.**

| # | 세는 것 | 통과 기준 | 어긋나면 |
|---|---|---|---|
| 1 | `agents/` 의 `.md` 개수 | **15** | 아래 「담당이 안 뜬다」 |
| 2 | `agents/` 에 하위 폴더가 있나 | **없어야 한다** | 하위 폴더의 담당은 스캔되지 않는다 → 최상위로 |
| 3 | `agents/` 의 모든 `.md` 첫 줄이 `---` 인가 | 전부 | frontmatter 없는 문서는 **유령 담당**이 된다 → `docs/` 로 |
| 4 | `skills/` 의 폴더마다 `SKILL.md` 가 있나 | 4개 전부 | 없는 폴더는 등록되지 않는다 |
| 5 | `100-skills/` 의 `SKILL.md` 개수 | **100** | 실제 개수를 그대로 말한다 |
| 6 | `100-skills/ROUTING.md` 가 열리나 | 열려야 한다 | 명부가 없으면 스킬을 못 찾는다 |
| 7 | `.claude-plugin/plugin.json` 의 `repository` | **문자열** | 객체면 **플러그인 전체가 로드되지 않는다** |

**7번을 특히 본다.** 이것 하나 때문에 플러그인이 통째로 안 뜬 적이 있다.

## 2-C. 눈으로 · 실제로 등록됐는가

파일이 있는 것과 **런타임에 등록된 것**은 다르다. 마지막으로 이것을 본다.

| 어디 | 어떻게 |
|---|---|
| 클로드 코드 | `/agents` 에 15명 · `/skills` 에 4개 |
| 코워크 | **Customize → Plugins → marketing-team** 을 열면 Skills·Agents 탭에 뜬다 |

| 증상 | 원인 | 대처 |
|---|---|---|
| 담당이 하나도 안 뜬다 | 플러그인 자체가 로드 실패 | 2-B 의 7번부터 |
| 팀장 10명만 없다 | 하위 폴더에 있다 | 최상위로 올린다 |
| 모르는 담당이 섞여 있다 | `agents/` 에 규약 문서가 들어 있다 | `docs/` 로 옮긴다 |
| 스킬을 불러도 안 걸린다 | 스킬 100개는 **등록되지 않는다.** 원래 그렇다 | 「스킬-100-보기」가 명부를 열어 찾는다. 번호로 불러도 된다 (「046 돌려줘」) |
| 폴더로 열었는데 안 뜬다 | `.claude/agents` 연결이 텍스트 파일로 풀렸다 (주로 윈도우) | 그 파일을 지우고 `agents` 폴더를 `.claude/` 안으로 복사한다 |

> 스킬 100개는 스킬로 등록되지 않는다. 의도된 설계다.
> 100개를 다 등록하면 매 세션 약 1만 5천 토큰이 항상 실린다.
> 대신 명부 한 장(`100-skills/ROUTING.md`)만 보고, 본문은 매칭된 순간에 연다.

## 3. 무엇이 있는지 **세어서** 보여준다

> **여기가 독자가 스킬 100개를 확인하는 유일한 자리다.**
> 메뉴에는 4개만 보인다. 100개가 실제로 있다는 것을 **숫자로 보여주는 것이 이 절의 일**이다.
> 세지 않고 「100개가 있습니다」라고 말하지 않는다. 실제 개수를 세어 말한다.

```
담당 15명
  디렉터 1   · 입구 하나
  팀장 10    · 스킬 100개를 10으로 나눠 맡는다
  스태프 4   · 규제 감사관 · 관점 검수관 · 스킬 제작관 · 자문단

스킬 100개
  001~010 시장조사   011~020 제품기획   021~030 콘텐츠
  031~040 소셜       041~050 광고       051~060 커머스
  061~070 데이터     071~080 CRM        081~090 브랜드·세일즈
  091~100 운영
  · 게이트 32개 (대외 발행물 · 발행 전 규제 검사)
  · 상태변경 7개 (예약·발행·예산 · 실행 전 ⏸ 승인)
  · 체인 15종 (「{체인 이름} 돌려줘」)
```

## 4. 브랜드 정보 · 안 채워도 된다

`brand/profile.md` 를 본다. **여기서 멈추지 않는다.**

- **비어 있다** → 정상이다. 이렇게 알린다.
  「안 채우셔도 다 됩니다. `sample-data/` 로 돌고 산출물에 **[샘플]** 이 붙습니다.
  내 브랜드로 바꾸면 그때부터 **[실데이터]** 가 됩니다.」
- **채워져 있다** → 브랜드명·업종을 한 줄로 확인시킨다

## 5. 첫 업무를 같이 돌린다 · 생략 불가

**설명으로 끝내지 않는다.** 하나를 실제로 돌려 산출물 파일을 보여준다.

무엇을 돌릴지 묻되, 답이 없으면 `001 키워드 리서치` 로 간다 (입력이 가장 적고 결과가 눈에 보인다).
끝나면 **산출물 경로**와 **첫 줄의 출처 태그**를 같이 보여준다.

## 주기 점검으로 쓸 때

이미 `brand/my-team.md` 가 있으면 위 1~2만 돌리고 아래를 센다.

| 세는 것 | 어디서 | 신호 |
|---|---|---|
| 누가 실제로 일했나 | `logs/build-log.md` | 90일 무호출 팀장 → 대기 검토 |
| 승인이 막혀 있나 | ⏸ 에서 멈춘 채 끝난 건 | 3건 이상이면 브리핑이 너무 무겁다 |
| 게이트가 도나 | `게이트` 열 | 대외 발행물인데 열이 비어 있으면 게이트를 건너뛴 것 |
| 결과가 파일로 남았나 | `outputs/` | 원장에는 있는데 파일이 없으면 착지 실패 |

고칠 지점은 **3개 이내**로 돌려준다. 열 개를 적으면 하나도 안 고쳐진다.

## 다음은

첫 스킬까지 돌려 봤으면 여기서 끝이 아니다. **다음 두 개를 순서대로 권한다.**

1. **`2-브랜드-등록하기`** — 우리 회사 정보를 넣는다. 그 순간부터 산출물이 `[샘플]` 에서 `[실데이터]` 로 바뀐다
2. **`3-팀-짜기`** — 지금 하는 업무에 맞는 팀만 켠다

그다음부터는 **그냥 말하면 된다.** 무엇을 시킬 수 있는지 보고 싶으면 `스킬-100-보기`.
