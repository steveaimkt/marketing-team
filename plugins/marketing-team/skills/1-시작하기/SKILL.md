# 점검 · 있다고 말하지 않고 세어 본다

> **사용법이 궁금한 것이라면 `0-사용가이드` 가 그 자리다.**
> 여기는 **실제로 세고, 없으면 만들고, 안 되면 고치는** 자리다.

> **없는 것을 있다고 말하지 않는다.** 개수를 세고, 안 되는 것은 안 된다고 말한다.

> ⚠️ **경로 규칙은 `docs/공통규약.md §0` 이다.**
> `100-skills/` · `docs/` · `sample-data/` 는 **패키지 안** (플러그인이면 `${CLAUDE_PLUGIN_ROOT}` 아래, 폴더로 열었으면 현재 폴더).
> `brand/` · `outputs/` · `logs/` · `inputs/` 는 **언제나 현재 작업 폴더**다.

## 0. 작업 폴더부터 만든다 · 플러그인으로 설치했다면 특히

**팀은 패키지 안에 살고, 산출물은 내가 일하는 공간에 떨어진다.** 둘은 다른 곳이다.

「내가 일하는 공간」이 어디인지는 환경마다 다르다.

| | 작업 공간 |
|---|---|
| **코워크** | 지금 이 대화가 파일을 만드는 곳 |
| **클로드 코드** | 지금 열어 둔 폴더 |
| **폴더로 클론해 열었다면** | 그 저장소 폴더가 곧 작업 공간이다 |

거기에 이 넷이 있는지 본다. 없으면 **묻고 만든다** (⏸).

```
brand/     내 브랜드 정보 · 팀 편성      ← 없으면 빈 템플릿을 만든다
outputs/   산출물이 떨어지는 곳
logs/      실적 원장 · 팀 소집 로그
inputs/    내 파일을 넣어 두는 곳
```

- 넷 다 이미 있으면 그냥 넘어간다.
- 없으면 만든다. 빈 템플릿은 **패키지의 `brand-templates/` 에서 복사해 온다** (`${CLAUDE_PLUGIN_ROOT}/brand-templates/`).
  템플릿 정본은 그 한 곳뿐이다 — 두 벌을 두면 조용히 어긋난다.
- ⚠️ **패키지 안에 쓰지 않는다.** 거기 쓰면 플러그인을 업데이트할 때 산출물이 통째로 날아간다.

만들고 나면 한 줄로 알린다 — 「이 폴더가 앞으로 산출물이 쌓일 곳입니다: {경로}」

## 1. 어디서 도는지부터 가른다

**터미널을 쓸 수 있는지**로 갈린다. 물어보지 말고 스스로 판단한다.

| | 검사 방법 |
|---|---|
| **클로드 코드** (터미널 있음) | 2-A · 스크립트를 돌린다 |
| **코워크** (터미널 없음) | 2-B · 파일을 직접 읽어 센다 |

둘 다 **보는 항목은 같다.** 세는 방법만 다르다.

## 2-A. 스크립트로 · 클로드 코드

    node "${CLAUDE_PLUGIN_ROOT}/scripts/verify.mjs"

`${CLAUDE_PLUGIN_ROOT}` 를 붙이는 이유는, 설치판에서 **현재 폴더가 패키지가 아니기 때문**이다.
폴더로 클론해 열었으면 `node scripts/verify.mjs` 도 된다. 둘 다 실패하면 2-B 로 간다.

## 2-B. 파일을 읽어서 · 코워크

스크립트 없이 같은 것을 센다. **파일을 세는 것뿐이라 어디서든 된다.**

| # | 세는 것 | 통과 기준 | 어긋나면 |
|---|---|---|---|
| 1 | `agents/` 의 `.md` 개수 | **2** (판정 전담) | 아래 「담당이 안 뜬다」 |
| 2 | `agents/` 에 하위 폴더가 있나 | **없어야 한다** | 하위 폴더의 담당은 스캔되지 않는다 → 최상위로 |
| 3 | `agents/` 의 모든 `.md` 첫 줄이 `---` 인가 | 전부 | frontmatter 없는 문서는 **유령 담당**이 된다 → `docs/` 로 |
| 4 | `skills/` 의 폴더마다 `SKILL.md` 가 있나 | 4개 전부 | 없는 폴더는 등록되지 않는다 |
| 5 | `100-skills/` 의 `SKILL.md` 개수 | **100** | 실제 개수를 그대로 말한다 |
| 6 | `100-skills/ROUTING.md` 가 열리나 | 열려야 한다 | 명부가 없으면 스킬을 못 찾는다 |
| 7 | `.claude-plugin/plugin.json` 의 `repository` | **문자열** | 객체면 **플러그인 전체가 로드되지 않는다** |

**7번을 특히 본다.** 이것 하나 때문에 플러그인이 통째로 안 뜬 적이 있다.

## 2-C. 눈으로 · 실제로 등록됐는가

파일이 있는 것과 **런타임에 등록된 것**은 다르다. 마지막으로 이것을 본다.

| 어디 | 어떻게 |
|---|---|
| 클로드 코드 | `/agents` 에 2명 · `/skills` 에 6개 |
| 코워크 | **Customize → Plugins → marketing-team** 을 열면 Skills·Agents 탭에 뜬다 |

| 증상 | 원인 | 대처 |
|---|---|---|
| 담당이 하나도 안 뜬다 | 플러그인 자체가 로드 실패 | 2-B 의 7번부터 |

| 모르는 담당이 섞여 있다 | `agents/` 에 규약 문서가 들어 있다 | `docs/` 로 옮긴다 |
| 스킬을 불러도 안 걸린다 | 스킬 100개는 **등록되지 않는다.** 원래 그렇다 | 「스킬-100-보기」가 명부를 열어 찾는다. 번호로 불러도 된다 (「046 돌려줘」) |
| 폴더로 열었는데 안 뜬다 | `.claude/agents` 연결이 텍스트 파일로 풀렸다 (주로 윈도우) | 그 파일을 지우고 `agents` 폴더를 `.claude/` 안으로 복사한다 |
| 버전이 옛것이다 | ① 마켓플레이스가 낡음 | **2-D 세 층 진단** |
| 설치했는데 목록에 없다 | ③ 대화가 옛 목록을 붙잡고 있다 | **새 대화**를 연다 |
| 됐다 안 됐다 한다 | ③ 대화마다 로드 시점이 다르다 | 같음 |
| 「더 이상 마켓플레이스에 없습니다」 | ①–② 끈이 끊김 | **2-D** 의 마지막 절차 |

> 스킬 100개는 스킬로 등록되지 않는다. 의도된 설계다.
> 100개를 다 등록하면 매 세션 약 1만 5천 토큰이 항상 실린다.
> 대신 명부 한 장(`100-skills/ROUTING.md`)만 보고, 본문은 매칭된 순간에 연다.

## 2-D. 세 층 진단 · 「업데이트가 안 돼요」일 때

버전이 옛것이거나, 스킬이 안 보이거나, 됐다 안 됐다 하면 **어느 층이 어긋난 것**이다.
층은 셋이고 **위에서 아래로만 흐른다.**

```
① 마켓플레이스   저장소에서 「무엇이 있는지」를 받아 온 목록   계정에 저장
      ↓
② 플러그인       그 목록에서 골라 실제로 설치한 것            계정에 저장
      ↓
③ 대화          대화를 열 때 설치된 것을 읽는다               대화마다
```

### 층마다 이렇게 판정한다

**③ 대화** — **지금 이 스킬이 돌고 있으면 정상이다.** 더 볼 것 없다.
(이 스킬조차 안 불렸다면 사용자가 다른 경로로 들어온 것이니, 「새 대화를 열어 보라」고 안내한다.)

**② 플러그인** — 설치된 버전을 읽는다.

```
${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json  →  version
```

**① 마켓플레이스** — 저장소의 최신 버전과 비교한다. 같은 파일의 `repository` 값에서 주소를 만든다.

```
repository:  https://github.com/{소유자}/{저장소}.git
       ↓
raw.githubusercontent.com/{소유자}/{저장소}/main/plugins/{플러그인}/.claude-plugin/plugin.json
```

네트워크가 막혀 못 읽으면 **판정하지 않는다.** 「확인 불가」로 적고 넘어간다. 추측하지 않는다.

### 판정표

| 설치본 vs 저장소 | 어긋난 층 | 사용자에게 |
|---|---|---|
| **같다** | 없음 | 「최신입니다 (vX.Y.Z)」 |
| **설치본이 낮다** | ① 또는 ② | 「저장소는 vA, 설치본은 vB 입니다. **마켓플레이스를 먼저 동기화**한 뒤 플러그인을 업데이트하세요」 |
| **저장소를 못 읽음** | 확인 불가 | 「설치본은 vB 입니다. 최신인지는 확인하지 못했습니다」 |

⚠️ **순서를 반드시 함께 말한다.** 「업데이트하세요」만 하면 사용자는 플러그인 버튼부터 누르고,
그 버튼은 **낡은 목록과 비교**하기 때문에 「새것 없음」으로 뜬다. 거기서 대부분 막힌다.

### 「더 이상 마켓플레이스에 없습니다」가 뜬다면

①과 ②의 **끈이 끊긴 것**이다. 마켓플레이스를 먼저 지웠을 때 생긴다 —
플러그인은 남아 있는데 출처가 사라져 고아가 된다.

```
① 플러그인 제거
② 앱을 완전히 종료했다 다시 켠다      ← 계정 상태를 다시 읽는다
③ 마켓플레이스 동기화
④ 플러그인 설치  →  ⑤ 새 대화
```

**지울 때는 아래층부터.** 위층(마켓플레이스)을 먼저 지우면 끊긴다.

## 3. 개수를 말한다

> **여기가 스킬 100개를 「세는」 자리다.** 목록을 늘어놓는 것은 `스킬-100-보기` 의 일이다.
> 세지 않고 「100개가 있습니다」라고 말하지 않는다. **실제 개수를 세어 말한다.**

```
스킬        6 개 (등록됨)
판정 담당    2 명 (staff-gate-auditor · staff-reviewer)
스킬 카탈로그 {실제로 센 수} 개 · 게이트 {n} · 상태변경 {n} · 체인 {n}
```

개수가 어긋나면 **그 숫자를 그대로 말하고** 2-B 의 해당 항목으로 돌아간다.
「무엇이 있는지 보고 싶다」는 요청이면 **`스킬-100-보기` 로 보낸다.** 여기서 펼치지 않는다.

## 4. 브랜드 정보 · 상태만 확인한다

`brand/profile.md` 와 `brand/my-agent.md` 가 있는지만 본다. **설명하지 않는다.**

| 상태 | 한 줄로 |
|---|---|
| 둘 다 없다 | 「샘플로 돕니다. 내 것으로 바꾸려면 `2-브랜드-등록하기`」 |
| 프로필만 있다 | 「조립이 안 끝났습니다. `3-내-에이전트-만들기` 로 1~2분」 |
| 둘 다 있다 | 「{브랜드명} · 상시 스킬 {n}개로 돌고 있습니다」 |

## 5. 첫 업무를 같이 돌린다 · 생략 불가

⚠️ **검사만 하고 끝내지 않는다.** 실제로 하나를 돌려 산출물 파일을 보여준다.

### 먼저 · 어느 데이터로 갈지 여기서 한 번만 묻는다

**이 질문은 여기서 한 번뿐이다.** 개별 스킬을 돌릴 때는 다시 묻지 않는다.

```
결과물을 하나 만들어 보겠습니다. 어느 쪽으로 할까요?

  ① 샘플로 둘러본다      가상의 A브랜드(화장품 D2C) 데이터로 바로 돕니다
                        준비할 것 없습니다 · 결과에 [샘플] 이 붙습니다

  ② 내 데이터로 한다     파일을 inputs/ 에 넣어 주시면 그걸로 돌립니다
                        CSV·엑셀·리뷰 붙여넣기 다 됩니다
```

| 답 | 어떻게 |
|---|---|
| **①** 또는 무응답 | 샘플로 **바로** 돈다. 끝에 「내 데이터로 하려면 `inputs/`」 한 줄 |
| **②** | 「어떤 파일이 있으세요?」 → `inputs/` 에 넣는 법을 안내하고 **기다린다** |
| **② 인데 지금 파일이 없다** | 「그럼 먼저 샘플로 보여드릴게요」 → ①로 가되 **나중에 다시 돌리자**고 남긴다 |

**②를 고르고 파일을 넣었으면 `inputs/` 우선순위가 알아서 잡는다** (`마케팅-디렉터 §②-b`).
그래서 다음부터는 묻지 않아도 맞는 데이터로 돈다.

⚠️ **「데이터 있으세요?」로 묻지 않는다.** 그건 없는 사람을 밀어낸다.
**「어느 쪽으로 할까요?」** 로 묻는다 — 둘 다 정상 경로다.

- `0-사용가이드` 에서 넘어왔고 **하고 싶은 일이 함께 넘어왔으면** 그것으로 돌린다.
- 없으면 **묻지 않고 `001 키워드 리서치`** 로 간다 (입력이 가장 적고 결과가 눈에 보인다).
- 브랜드 정보가 없어도 **멈추지 않는다.** 샘플로 완주하고 `[샘플]` 을 붙인다.
- 끝나면 **산출물 파일 경로**와 **첫 줄의 출처 태그**를 함께 보여준다.

주기 점검으로 부른 경우(이미 몇 번 써 본 사용자)에는 **이 절을 건너뛴다.**
설치 직후 처음 도는 경우에만 한다.

## 주기 점검으로 쓸 때

이미 `brand/my-agent.md` 가 있으면 위 1~2만 돌리고 아래를 센다.

| 세는 것 | 어디서 | 신호 |
|---|---|---|
| 상시 스킬이 실제로 돌았나 | `logs/build-log.md` | 90일 무호출이면 상시에서 내릴지 묻는다 |
| 승인이 막혀 있나 | ⏸ 에서 멈춘 채 끝난 건 | 3건 이상이면 브리핑이 너무 무겁다 |
| 게이트가 도나 | `게이트` 열 | 대외 발행물인데 열이 비어 있으면 게이트를 건너뛴 것 |
| 결과가 파일로 남았나 | `outputs/` | 원장에는 있는데 파일이 없으면 착지 실패 |

고칠 지점은 **3개 이내**로 돌려준다. 열 개를 적으면 하나도 안 고쳐진다.

## 마치며

고칠 것이 있었으면 **무엇을 고쳤는지** 한 줄로 말한다. 없었으면 「이상 없습니다」로 끝낸다.

```
점검 완료 · 스킬 6 · 담당 2 · 카탈로그 {n} · 버전 {v}
{고친 것이 있으면 여기 한 줄}

무엇을 시킬 수 있는지 보시려면 「스킬-100-보기」,
처음 써 보시는 것이라면 「0-사용가이드」 가 첫 결과물까지 안내합니다.
```

처음 도는 경우라면 위 5에서 **첫 산출물이 이미 하나 나와 있어야 한다.**
그것 없이 「점검 완료」로 끝내지 않는다.
