# 마케팅팀 구축하기 · 쓸 수 있게 만든다

> ⚠️ **경로 규칙은 `docs/공통규약.md §0` 이다.**
> `100-skills/` · `docs/` · `sample-data/` · `brand-templates/` 는 **패키지 안**
> (플러그인이면 `${CLAUDE_PLUGIN_ROOT}` 아래, 폴더로 열었으면 현재 폴더).
> `brand/` · `outputs/` · `logs/` · `inputs/` 는 **언제나 현재 작업 폴더**다.

**네 걸음이고, 멈추는 곳은 두 번뿐이다.** 설명하지 않는다 — 검사하고, 받고, 넘긴다.
「이게 뭔가」·「무엇을 시킬 수 있나」는 `마케팅팀-업무리스트` 가 맡는다. 여기서 다시 설명하지 않는다.

## ① 제대로 깔렸나 · 세어 본다

**있다고 말하지 않고 센다.**

⛔ **터미널부터 찾지 않는다. 파일을 직접 읽어 센다.**
**코워크에는 터미널이 없다.** 승인을 요구하며 멈추면 사용자는 첫 화면에서 막힌다.
`ls` · `find` · `node` 없이 **파일을 열어 보는 것만으로 아래 7개가 전부 세어진다.**

> 클로드 코드에서 **더 꼼꼼히 보고 싶을 때만** `node "${CLAUDE_PLUGIN_ROOT}/scripts/verify.mjs"` 를
> 제안한다. **먼저 세어서 결과를 보여준 뒤에** 권한다. 승인을 기다리며 멈추지 않는다.

| # | 세는 것 | 통과 |
|---|---|---|
| 1 | `agents/` 의 `.md` 개수 | **2** (판정 전담) |
| 2 | `agents/` 에 하위 폴더가 있나 | **없어야** — 있으면 그 담당은 스캔되지 않는다 |
| 3 | `agents/` 의 모든 `.md` 에 frontmatter | 전부 — 없으면 **유령 담당** |
| 4 | `skills/` 폴더마다 `SKILL.md` | **3개** — `마케팅팀-구축하기` · `AI-마케터` · `마케팅팀-업무리스트` |
| 5 | `100-skills/` 의 `SKILL.md` | **100** |
| 6 | `100-skills/ROUTING.md` 가 열리나 | 열려야 한다 |
| 7 | `.claude-plugin/plugin.json` 의 `repository` | **문자열** — 객체면 플러그인 전체가 로드 실패 |

**개수가 어긋나면 그 숫자를 그대로 말한다.** 「100개가 있습니다」라고 지어내지 않는다.

> ⚠️ **스킬 100개는 등록되지 않는다. 의도된 설계다.** 전부 등록하면 매 세션 약 1만 5천 토큰이 항상 실린다.
> 명부 한 장만 보고 본문은 매칭된 순간에 연다. 그래서 `/` 목록에 **셋만** 보이는 것이 정상이다.

### 「업데이트가 안 돼요」면 · 세 층을 가른다

```
① 마켓플레이스   저장소에서 받아 온 목록      계정에 저장
      ↓
② 플러그인       그 목록에서 설치한 것        계정에 저장
      ↓
③ 대화          열 때 설치된 것을 읽는다      대화마다
```

| 판정 | 어떻게 |
|---|---|
| **③** | **이 스킬이 돌고 있으면 정상.** 더 볼 것 없다 |
| **②** | `plugin.json` 의 `version` 을 읽는다 |
| **①** | 같은 파일의 `repository` 에서 raw 주소를 만들어 저장소 최신과 비교. 못 읽으면 **판정하지 않는다** |

| 결과 | 사용자에게 |
|---|---|
| 같다 | 「최신입니다 (vX.Y.Z)」 |
| 설치본이 낮다 | 「저장소는 vA, 설치본은 vB. **마켓플레이스를 먼저 동기화**한 뒤 플러그인을 업데이트하세요」 |
| 못 읽음 | 「설치본은 vB. 최신인지는 확인하지 못했습니다」 |

⚠️ **「업데이트하세요」만 말하지 않는다.** 사용자는 플러그인 버튼부터 누르고,
그 버튼은 낡은 목록과 비교하므로 「새것 없음」으로 뜬다. **거기서 대부분 막힌다.**

| 증상 | 층 | 대처 |
|---|---|---|
| 담당이 하나도 안 뜬다 | 플러그인 로드 실패 | ①의 7번부터 |
| 설치했는데 `/` 목록에 없다 | ③ | **새 대화**를 연다 |
| 되다가 안 되다가 한다 | ③ | 같음 |
| 「더 이상 마켓플레이스에 없습니다」 | ①–② 끊김 | 플러그인 제거 → **앱 재시작** → 마켓플레이스 동기화 → 재설치 → 새 대화 |
| 폴더로 열었는데 안 뜬다 | `.claude/` 연결이 텍스트 파일로 풀림 (윈도우) | 그 파일을 지우고 `agents`·`skills` 를 `.claude/` 안으로 복사 |

**⛔ 마켓플레이스를 먼저 지우지 않는다.** 플러그인이 출처를 잃고 고아가 된다. 지울 때는 아래층부터.

### 「처음부터 다시 하고 싶어요」 · 완전 초기화

「지웠다 다시 깔았는데 옛날 것이 그대로다」는 **캐시가 남아서**다.
플러그인을 제거해도 **버전별 사본과 설치 기록이 남는다** (실측 2026-08-26 · 3.4MB · 466개 파일).
그래서 재설치해도 같은 버전을 다시 집는다.

**⚠️ 먼저 가른다 — 무엇을 리셋하려는 것인가.**

| 하고 싶은 것 | 해야 할 일 |
|---|---|
| **내 데이터만 새로** (처음 쓰는 것처럼) | **새 폴더를 하나 잡고 「구축하자」.** 그것뿐이다 |
| **최신 버전 받기** | 마켓플레이스 동기화 → 플러그인 업데이트 |
| **찌꺼기까지 전부** | 아래 순서 |

⛔ **대부분은 첫 줄이면 된다.** 플러그인은 읽기 전용이라 내 데이터를 갖고 있지 않다 —
지웠다 깔아도 달라지는 것이 없다. **기억은 작업 폴더에 있다.**

**그래도 전부 밀어야 하면 · 순서를 지킨다**

```
① 플러그인 제거
② 마켓플레이스 제거          ← 여기를 건너뛰면 낡은 목록이 남아 옛 버전을 다시 집는다
③ 앱 재시작
④ 캐시·설치 기록 삭제 (아래)
⑤ 마켓플레이스 다시 추가 → 플러그인 설치
⑥ 새 대화
```

④는 **터미널이 있어야 한다.** 코워크에는 없으므로 ①②③⑤⑥만 하고,
그래도 옛 버전이면 클로드 코드에서 ④를 하거나 지원에 문의한다.

```
~/.claude/plugins/cache/marketing-team/           버전별 사본 (제일 큰 찌꺼기)
~/.claude/plugins/data/marketing-team-*/          플러그인 데이터
~/.claude/plugins/installed_plugins.json          "marketing-team@marketing-team" 항목
~/.claude/plugins/known_marketplaces.json         "marketing-team" 항목
```

⛔ **뒤 두 JSON 은 다른 플러그인 기록도 함께 들어 있다. 파일째 지우지 않는다** —
해당 항목만 뺀다. 지우기 전에 **두 파일을 복사해 둔다.**

⚠️ **작업 폴더는 이 절차로 지워지지 않는다.** `brand/` · `outputs/` · `logs/` 는 그대로 남는다.
**그것이 맞다** — 제품을 밀어도 내 데이터는 남아야 한다.
작업 데이터까지 버리려면 그 폴더를 직접 지우거나, **새 폴더에서 시작한다** (이쪽을 권한다).

## ② 작업 공간을 만든다

**팀은 패키지 안에 살고, 산출물은 내가 일하는 공간에 떨어진다.** 둘은 다른 곳이다.

| | 작업 공간 |
|---|---|
| 코워크 | 「Work in a project or folder」로 고른 폴더 · 안 골랐으면 지금 이 작업이 파일을 만드는 곳 |
| 클로드 코드 | 지금 열어 둔 폴더 |
| 폴더로 클론했으면 | 그 저장소 폴더 |

거기에 넷이 없으면 **묻고 만든다** (⏸).

```
brand/     내 브랜드 정보 · 우리 보완
outputs/   산출물이 떨어지는 곳
logs/      실적 원장
inputs/    내 파일을 넣어 두는 곳
```

### 어디에 만드나 · 여기 바로냐, `marketing-team/` 안이냐

**지금 폴더를 보고 기본값을 정한 뒤 ⏸ 로 묻는다.** 고정하지 않는다 —
데스크탑에 넷을 흩뿌리면 지저분하고, 전용 폴더에 한 겹을 더하면 군더더기다.

| 지금 폴더가 | 기본값 | 왜 |
|---|---|---|
| 비어 있거나 **이 일 전용**으로 보인다 | **여기 바로** | 한 겹이 늘면 경로만 길어진다 |
| 데스크탑·홈·**다른 것이 이미 많은 곳** | **`marketing-team/` 안** | 넷이 흩어지면 나중에 못 찾는다 |

```
여기에 작업 공간을 만듭니다. 어디에 둘까요?

  ① marketing-team/ 폴더를 만들고 그 안에      ← 데스크탑이라 이걸 권합니다
       marketing-team/brand · outputs · logs · inputs
  ② 여기 바로
       brand · outputs · logs · inputs
⏸
```

⚠️ **①을 골랐으면 반드시 한 줄 알린다** — 작업 폴더는 **넷이 있는 곳**이다.

```
✅ ~/Desktop/marketing-team/ 에 만들었습니다.
   앞으로는 데스크탑이 아니라 **이 폴더를 열고** 일해 주세요.
   여기서 일하지 않으면 산출물이 다른 곳에 쌓입니다.
```

이 말을 빠뜨리면 사용자가 계속 상위 폴더를 열고, **작업 공간을 못 찾아 또 만든다.**

### 무엇을 어디로 복사하나 · 이 표대로만 한다

⛔ **「빈 템플릿을 복사한다」로 끝내지 않는다.** 무엇을 어디에 놓을지 안 적으면
실행할 때마다 달라진다 — **실측 (2026-08-25) · `profile.md` 가 빠지고
`build-log-summary.md` 가 미리 생겼다.** 가장 중요한 것이 빠진 채 완주했다.

| 템플릿 (`brand-templates/`) | → 어디 | 언제 |
|---|---|---|
| `profile.md` | `brand/profile.md` | **항상** — ⚠️ 빠지면 사용자가 자기 정보를 넣을 양식이 없다 |
| `tone.md` | `brand/tone.md` | **항상** |
| `my-playbook.md` | `brand/my-playbook.md` | **항상** |
| `build-log.md` | `logs/build-log.md` | 없을 때만 (있으면 헤더만 본다 · 아래 「원장을 세운다」) |
| `build-log-summary.md` | — | ⛔ **미리 만들지 않는다.** 롤오버가 만든다 |
| `skill-notes.md` | — | ⛔ **미리 만들지 않는다.** 사용자가 「계속 이렇게」라고 할 때 생긴다 |
| `업무-스킬-분해표.md` | — | ⛔ 참고 문서다. 복사하지 않는다 |

**셋(`profile`·`tone`·`my-playbook`)을 복사했으면 셋이라고 말한다.**
하나라도 못 했으면 어느 것을 왜 못 했는지 적는다. 조용히 넘어가지 않는다.

⚠️ **이미 있으면 덮어쓰지 않는다.** 사용자가 채운 것이 사라진다.

⚠️ **패키지 안에 쓰지 않는다.** 거기 쓰면 플러그인을 업데이트할 때 산출물이 통째로 날아간다.

### 원장을 세운다

```
없으면        brand-templates/build-log.md 를 복사한다
있으면        헤더를 본다
```

**헤더가 정본과 다르면** — 구형은 `| 일시 | 방법론 | 담당 | 산출물 | 게이트 | 보완 |` 6열이다.
⛔ **말없이 고치지 않는다.** 지난 기록이 사라진다. **보여주고 묻는다.**

```
원장이 옛 형식입니다 (6열). 지금 규약은 8열이라 저장 누락 점검이 안 돕니다.

  지금        일시 | 방법론 | 담당 | 산출물 | 게이트 | 보완
  정본        일시 | 스킬 ID | 요청 | 데이터 모드 | 산출물 경로 | 게이트 | 보완 횟수 | 상태

  옮기면 logs/build-log-{오늘}.bak.md 로 백업하고, 기존 {N}행은 아는 값만 채웁니다.
  (요청·데이터 모드·상태는 빈칸으로 두고 「구형 이관」이라 표시합니다)

⏸ 옮길까요? 그냥 두면 새 행부터 8열로 쌓입니다 — 점검은 새 행만 봅니다.
```

열 순서는 정본 그대로 (`docs/공통규약.md §H`).

## ③ 우리 회사 정보 · 6묶음 · 건너뛸 수 있다

⏸ **먼저 묻는다. 이 질문은 여기서 한 번뿐이다.**

```
결과물을 만들기 전에, 우리 회사 정보를 넣으시겠어요?

  ① 지금 넣는다      3분 · 100개가 우리 것 15~30개로 줄고 [실데이터] 로 나옵니다
  ② 나중에           샘플(가상의 A브랜드)로 바로 보여드립니다 · [샘플] 이 붙습니다
```

**②를 골라도 전 과정이 완주된다.** 나중에 「브랜드 정보 넣을래」 하면 그때 채운다.

①이면 **한 번에 하나씩** 묻는다. 모르면 비우고 넘어간다.

| # | 묶음 | 꼭 필요한 것 | 비면 |
|---|---|---|---|
| 1 | **기본** | 브랜드명 · **업종** · 핵심 제품 3 | 업종이 없으면 규제 사전이 공통(표시광고법)만 걸린다 |
| 2 | **고객** | 핵심 타깃 · 사는 이유 3 · 떠나는 이유 3 | 페르소나·카피가 일반론이 된다 |
| 3 | **채널** | 실제로 굴러가는 채널만 | 없는 채널을 적으면 안 도는 계획이 나온다 |
| 4 | **숫자** | 마진율 → **손익분기 ROAS(=1÷마진율)** · 월 예산 | 광고 판정이 전부 `[추정]` |
| 5 | **경쟁** | 경쟁사 3곳과 고른 기준 | 비교표의 기준이 흔들린다 |
| 6 | **금기** | 절대 쓰지 않는 표현 | 게이트가 공통 규정만 본다 |

> ⚠️ **4번을 특히 챙긴다.** 손익분기 ROAS 는 흑자·적자를 가르는 기준선이다.
> 없으면 ROAS 2.0이 좋은 건지 나쁜 건지 아무도 모른다.

**업종을 받으면 규제가 갈아 끼워진다** — 화장품법·건강기능식품법·식품표시광고법·약사법·금소법.
우리만의 금기는 `brand/compliance-custom.md` 에 적는다.

받은 값은 `brand/profile.md` (톤은 `brand/tone.md`) 로 쓴다.
**이미 있으면 처음부터 다시 받지 않는다** — 지금 값을 표로 보여주고 **고칠 곳만** 손댄다.

## ④ 첫 결과물을 만든다 · 생략 불가

⚠️ **여기서 멈추면 아무것도 안 남는다.**

**별도의 조립 단계는 없다.** 프로필을 채운 순간 스킬 100개가 그 값을 읽고 돈다 —
손익분기 ROAS, 업종 규제 사전, 기본 채널, 페르소나가 자동으로 들어간다.

스킬 하나를 지금 돌린다. 사용자가 말한 것으로, 없으면 `001 키워드 리서치` 로 간다
(입력이 가장 적고 결과가 눈에 보인다).

**산출물 파일이 하나 나와야 끝난다.** 경로와 출처 태그를 함께 보여준다.

## 마치며

```
준비 완료 · 스킬 {n} · 담당 {n} · 카탈로그 {n} · 버전 {v}
첫 결과물: {경로}

앞으로는 그냥 말하면 됩니다 —  "리뷰 분석해줘"  "이번 달 광고 어땠어"
무엇을 시킬 수 있는지  「스킬 목록 보여줘」
```

③을 건너뛴 경우에만 한 줄 더 — 「우리 회사 정보를 넣으면 `[실데이터]` 로 바뀝니다.」
**여러 개를 늘어놓지 않는다.**

## 주기 점검으로 쓸 때

이미 `brand/profile.md` 가 차 있으면 ③을 건너뛰고 ①만 돌린 뒤 아래를 센다.

**먼저 기계를 돌린다. 사람이 세면 안 센다.**

```
node ${CLAUDE_PLUGIN_ROOT}/scripts/ledger-stats.mjs
```

> 📒 **세션이 열릴 때 이미 한 번 본다.** SessionStart 훅이 7일에 한 번 조용히 재고,
> 롤오버가 필요하거나 신호가 있을 때만 알린다 (`docs/공통규약.md` 「원장이 시스템을 고친다」).
> 사용자가 그 알림을 보고 왔으면 **여기서 전체를 다시 돌려** 처방까지 낸다.

한 번에 부피·스킬별 집계·진단 신호가 나온다. 아래 표는 그 출력을 읽는 법이다.

| 기계가 내는 신호 | 무슨 뜻인가 | 무엇을 묻나 |
|---|---|---|
| 🔕 무호출 | 90일째 안 돌았다 | 상시에서 내릴지 묻는다 |
| 🔁 재작업 | 평균 보완 2회 이상 — **한 번에 안 나오는 스킬**이다 | 그 스킬의 `inputs`·브리핑이 부실하다 |
| ⛔ 차단 | 차단률 30% 이상 | 표현 규칙을 프롬프트에 미리 넣는다 |
| 📄 샘플 | 샘플률 80% 이상 | 실데이터가 안 붙어 있다 — 프로필·MCP 확인 |
| 💾 저장실패 | 착지가 실패했다 | 회수 가능한지 본다 (아래 저장 누락 점검) |
| 🗣 라우팅 | **같은 말이 다른 스킬로 갈렸다** | 부를 말이 겹친다 — 트리거를 가른다 |
| 📁 착지실패 | 원장엔 있는데 **파일이 없다** | 「저장 안 된 거 있어?」로 회수한다 |
| 🚪 게이트기록 | 게이트는 탔는데 **`gate.md` 가 없다** | 판정 근거가 안 남았다 |
| 🟡 롤오버 필요 | 800행 초과거나 연도가 바뀌었다 | 아래 「원장 롤오버」로 간다 |

기계가 못 세는 것은 손으로 본다.

| 세는 것 | 어디서 | 신호 |
|---|---|---|
| 승인이 막혀 있나 | ⏸ 에서 멈춘 채 끝난 건 | 3건 이상이면 브리핑이 무겁다 |
| 게이트가 도나 | `게이트` 열 | 발행물인데 비어 있으면 건너뛴 것 |
| 결과가 파일로 남았나 | `outputs/` | 원장엔 있는데 파일이 없으면 **착지 실패** |

⛔ **스크립트가 없거나 노드가 없으면** 그 사실을 말하고 손으로 센다. **조용히 건너뛰지 않는다** —
안 세고 「이상 없음」이라고 하면 점검을 한 것이 아니다.

고칠 지점은 **3개 이내**로 돌려준다. 열 개를 적으면 하나도 안 고쳐진다.

### 저장 누락 점검 · 「저장 안 된 거 있어?」

**가장 조용히 새는 자리다.** 화면에 결과가 예쁘게 나오면 파일이 없는 줄 모른다.
그래서 **묻지 않아도 주기 점검에서 이것부터 센다.**

1. `logs/build-log.md` 의 **최근 8주** 행을 읽어 **`{번호}-{슬러그}` 와 날짜**를 뽑는다
   (원장을 통째로 읽지 않는다 — 날짜로 grep 하거나 tail 로 끊는다. `docs/공통규약.md §A`.
   더 오래된 것은 대화 기록이 없어 어차피 회수가 안 된다. 「최근 8주만 봤다」고 말한다)
2. `outputs/{날짜}/{번호}-{슬러그}/` 에 실물이 있는지 하나씩 본다
3. 없는 것을 목록으로 낸다 — **몇 건인지 먼저 말하고** 목록은 그다음

```
원장 12건 · 실제 파일 10건 → 2건이 비었습니다

  2026-08-20  광고 주간 리포트(045)
  2026-08-18  상세페이지 카피(051)          ⚠️ 발행물인데 gate.md 도 없습니다

  대화 기록이 남아 있으면 「방금 거 저장해줘」로 옮길 수 있고,
  아니면 다시 돌려야 합니다. 다시 돌릴까요?
```

**규칙 밖 경로도 함께 본다** — `outputs/` 안에 `{날짜}/{번호}-{슬러그}/` 가 아닌 것이 있으면
그것도 착지 실패다. 옮기고 원장을 고칠지 묻는다.

```
outputs/2026-08-22/ads/…            ← 카테고리 축은 없앴다
outputs/인수인계_문서.md              ← 날짜 폴더가 없다
```

⛔ **0건이면 「0건」이라고 말한다.** 조용히 넘어가면 점검을 한 건지 알 수 없다.

### 원장 롤오버 · 「원장이 두꺼워졌습니다」

원장은 지우지 않고 쌓는다. 그래서 언젠가 반드시 커진다.
문제는 디스크가 아니라 **매 작업 앞에서 읽는 비용**이다 — 원장이 두꺼우면 일이 느려진다.

**여기가 세는 유일한 자리다.** 그리고 **세는 것은 기계다** — 위 `ledger-stats.mjs` 가 이미 판정해 준다.

```
✅ 부피 정상        아무 말도 하지 않는다
🟡 롤오버 필요      ⏸ 로 제안한다 (800행 초과 또는 연도 변경)
```

```
원장이 1,240행입니다 (2026-01-04 ~ 2026-12-28).
작업할 때마다 이걸 다 읽으면 느려집니다.

  2026년 행 1,240건  →  logs/archive/build-log-2026.md
  logs/build-log.md  →  헤더만 남기고 2027년부터 새로 쌓습니다
  logs/build-log-summary.md  →  스킬별 최종 실행일·누적 건수로 갱신 (90일 점검이 이걸 봅니다)

  옮기는 것이지 지우는 것이 아닙니다. 아카이브는 그대로 남습니다.

⏸ 옮길까요?
```

승인받으면 순서대로 한다.

1. `logs/archive/` 가 없으면 만든다
2. **데이터 행만** 잘라 `logs/archive/build-log-{연도}.md` 로 옮긴다 — 헤더·스키마는 원장과 **같게** 복사한다
3. `logs/build-log.md` 는 머리말과 표 헤더만 남긴다
4. 요약 원장을 갱신한다 — **손으로 집계하지 않는다.** 기계가 아카이브까지 합쳐 다시 센다

   ```
   node ${CLAUDE_PLUGIN_ROOT}/scripts/ledger-stats.mjs --summary
   ```
5. 옮긴 행 수와 아카이브 경로를 말한다. **몇 건을 어디로 옮겼는지 말하지 않으면 지운 것과 구별되지 않는다**

⛔ **묻지 않고 옮기지 않는다.** ⛔ **행을 지우지 않는다.** ⛔ **아카이브의 열 순서를 바꾸지 않는다.**

> 롤오버 뒤에도 지난 기록은 찾을 수 있다 — 「작년에 뭐 했지」는 `logs/archive/` 를 grep 하면 된다.
> 정본 규칙은 `docs/공통규약.md` 「원장 롤오버」.
