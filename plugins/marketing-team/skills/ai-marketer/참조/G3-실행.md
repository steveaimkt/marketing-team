# G3 실행, 실행 기록, 형식, 착지, 원장

> `skills/ai-marketer/SKILL.md` 본체의 참조 파일이다. 본체에는 규칙이 한 줄씩 있고, 여기에는 **예시, 근거, 드문 경우**가 원문 그대로 있다.
> **언제 여는가**: run-receipt 가 거부했을 때, 체인이나 조합의 저장 위치를 정할 때, 같은 날 다시 돌릴 때, 원장 상태를 무엇으로 적을지 정할 때
> ⛔ 열었으면 통째로 읽고 나서 한다. 기억으로 하지 않는다.
> 절 번호(§0, §G2 같은 것)는 2026-09-23 이전 본체 기준이다. 본체의 같은 이름 절을 가리킨다.

### G3, 실행

⛔ **담당은 G1 에서 이미 정해졌다. 여기서 다시 고르지 않는다.**

계획대로 완주한다. 안쪽에서 일어나는 일은 §3 에 있다.
컨텍스트 주입, 입력 찾기, 스킬 본문 완주, 규제 게이트, 파일 착지, 원장 기록.

**계획과 달라지면 멈추고 말한다.** 「2번 스킬에 필요한 데이터가 없어 1번만 했습니다」.
말없이 줄이지 않는다.

⛔ **담당은 안 바꾼다. 그러나 전제가 무너지면 G2 로 되돌린다.** 입력이 G1 에서 말한 것과 다르거나,
결론선이 바뀌거나, 앞 단계 결론이 뒤 단계 전제를 부수면 그 자리에서 멈춘다. 절차는 `docs/G3-분기절차.md` §6.

#### ⛔ 산출물보다 먼저 `run.json`을 연다

G1에서 스킬·입력·데이터 기간을 정하고 G2에서 착지 경로가 정해졌으면, **산출물을 쓰기 전에**
같은 폴더에 `run.json` 초안을 쓴다. 반복 실행은 산출물 순번과 맞춰 `run-2.json`으로 쓴다.
정본은 `docs/실행-영수증.md`다.

1. 요청 원문, 스킬 번호, 데이터 모드, 입력 경로와 기간, 프로필, 예정 산출물을 초안에 적는다.
   `required_reviews`는 생략해도 된다. `start`가 `review:`·`gate:` 정본에서 **산출물별로 자동 생성**한다
2. `node "${CLAUDE_PLUGIN_ROOT}/scripts/run-receipt.mjs" start "{run.json}"`으로 입력·프로필·스킬 지문을 봉인한다
3. 산출물과 검토 보고서가 생길 때마다 `review`로 **검토 당시 산출물**을 봉인한다
4. 원장 1행 뒤 `finalize`가 통과해야 G4로 간다

계획에 `steps` 가 있으면 단일 스킬도 각 단계 앞뒤에 `step-start --step N`과 `step-done --step N`을 호출한다.
중단됐으면 `resume`이 알려 주는 첫 미완료 단계부터 이어 간다. 완료된 단계를 처음부터 다시 만들지 않는다.

⛔ **사용자 요청문을 셸 인수로 넘기지 않는다.** 요청문은 JSON 초안에만 쓴다.
⛔ **조회(grep, ls)와 스크립트 실행(node)을 한 셸 명령에 섞지 않는다.** 실행 보호가 혼합 명령·파이프를 막는다. 한 줄에 하나씩 부른다.
터미널이 없으면 초안에 `unverified-no-shell`을 남기고, G4에서 `docs/실행-영수증.md §4` 의 한 줄로 밝힌다.
그때 대외 발행물은 지난 `gate.md`를 재사용하지 않고 현재 전문을 다시 검사한다.

#### ⛔ G3 는 파일이 생기기 전까지 끝나지 않는다

**실측 (2026-08-22, 스킬 100개 실행), 27%가 파일을 안 남겼다.** 화면에만 내거나,
아티팩트로 발행하려 하거나, 스크래치패드에 뒀다. 셋 다 **다음 주에 열면 없다.**

```
✗  화면에 표를 다 쓴다 → 파일에 쓸 것이 안 남는다 → 안 쓴다
✗  아티팩트로 발행, 스크래치패드에 저장
✓  스킬 본문의 「⛔ 착지, 여기로 쓴다」 경로에 쓴다 → 있는지 확인한다 → G4 에 옮긴다
```

| | |
|---|---|
| **경로** | 스킬 본문 끝의 **「⛔ 착지」 블록**에 적혀 있다. **그대로 쓰고 `{날짜}` 만 바꾼다** |
| **파일** | 산출물 **전문**, 표 전체, 20안 전부, 24섹션 전부 |
| **실행 증거** | 같은 폴더의 `run.json`, 입력·산출물·검토가 같은 실행인지 대조 |
| **화면** | 경로, 결론 3줄, 부족한 것. **길어야 15줄** |
| **원장** | `logs/build-log.md` 한 줄 |

화면이 길어지고 있으면 **거꾸로 하고 있는 것**이다. 멈추고 파일부터 쓴다.
쓰기가 실패했으면 **첫 줄에 적는다**. 「저장하지 못했습니다, 사유 {무엇}」. 대신 길게 쓰지 않는다.

### ⭐ 초안을 먼저 쓰고, 계획에서 정한 형식으로 완성한다

**형식은 G2 에서 정한다.** 초안 뒤에 같은 형식을 다시 확인하지 않는다.
`docs/공통규약.md §H` 가 정본이고, 영수증 절차는 `docs/실행-영수증.md` 를 따른다.

| 요청 범위 | 실행 방식 |
|---|---|
| **최종 파일까지** | 처음부터 `run.json` 에 `"단계": "최종"` 과 최종 파일·보존할 `.md` 초안을 적어 `start` 한다. 초안을 먼저 쓰고 승인된 형식으로 완성한 뒤 검토·기록·`finalize` 를 마친다 |
| **초안만** | G2 의 `형식` 과 예정 산출물을 `.md` 로 맞추고 봉인한다. `"단계": "초안"` 으로 시작해 초안을 검토·기록하고 완료한다. 최종 파일은 만들지 않는다 |
| **실행 뒤 다른 형식 요청** | 원본을 유지하고 변환을 별도 계획·승인·새 영수증으로 시작한다. 기존 영수증의 `형식` 이나 `단계` 만 고쳐 재사용하지 않는다 |

⛔ **초안을 건너뛰거나 지우지 않는다.** 최종이 `.md` 면 그 파일이 초안과 최종을 겸한다.
다른 형식이면 같은 폴더에 초안을 남겨 나중에 내용을 다시 만들지 않고 변환할 수 있게 한다.

**🎨 이미지 스킬(025·031·043·052)은 생성할 대상과 장수를 확인한다.**
이미 승인한 범위는 다시 묻지 않고, 아직 정하지 않았다면 프롬프트를 보여 준 뒤 확인한다 (`docs/G3-분기절차.md` §4).

### 실행 (G3)

**내가 한다.** 스킬을 열기 전에 **셋을 겹쳐 읽는다.**

| 순서 | 무엇 | 어디 |
|---|---|---|
| 1 | 스킬 본문, Contract → Phases → Output Format | `100-skills/…/SKILL.md` (원본) |
| 2 | 카테고리 금기·검토 관점 | `docs/도메인-금기.md` 의 해당 번호대 |
| 3 | **프로필에서 뽑은 값**, 손익분기 ROAS, 기본 채널·금기 표현 | `brand/profile.md` (② 에서 읽은 것) |
| 4 | **기준본** · 저자가 돌려 확인한 같은 번호의 결과물 (있을 때만) | `sample-data/참고결과/{번호}-{슬러그}/` |

**4 는 모양의 본이다.** 절 구성·표의 열·근거를 밝히는 깊이를 맞추고, **숫자와 문장은 베끼지 않는다.**
없으면 그냥 간다. 이것 때문에 멈추지 않는다.

**3의 값을 다시 묻지 않는다.** 마진율이 프로필에 있으면 손익분기 ROAS 를 계산해 쓴다.
원본과 충돌하면 프로필이 이긴다. **단 게이트·안전 규칙은 예외다.**
프로필은 규제를 **강화만** 할 수 있다. 「우리는 써도 된다」는 설정이 아니라 사고다.

같은 값을 두 번 물었으면 끝에 한 줄, 「`brand/profile.md` 에 넣어 두면 다음부터 안 묻습니다.」

체인이면 순서대로 태우고, **앞 산출물의 파일 경로를 다음 입력으로 그대로 주입**한다.
사용자가 같은 내용을 두 번 설명하지 않는다.

⛔ **체인이면 `⏸ 사람` 자리와 스킬의 「체인 전용 멈춤」에서 실제로 멈춘다.** 한 턴에 끝까지 돌지 않는다 (`docs/G3-분기절차.md` §8).

**데이터 파일 둘 이상을 한 결론에 합칠 때는 먼저 기간표를 만든다** (`docs/G3-분기절차.md` §7).
같은 정의의 지표 합계가 다르면 **`[자료 충돌]`로 표시하고 파일 사이 합산·나눗셈을 멈춘다.**
기준 자료를 정하기 전에는 각 파일 안에서 확인한 값만 쓴다.

### 착지 (G3)

**경로는 스킬 본문 끝의 「⛔ 착지, 여기로 쓴다」 블록에 있다.** 100개 전부에 박혀 있다.
**그대로 쓰고 `{날짜}` 만 오늘로 바꾼다.** 계산하지 않는다.

```
outputs/{날짜}/043-meta-ad-copy/043-meta-ad-copy.md   ← 스킬에 적힌 그대로
    + gate.md          발행물이면 AI 규제검토자 결과
    + run.json         입력·스킬·산출물·검토 지문
    + 첨부·원자료       있으면 같이
```

| 예외 | 어디에 |
|---|---|
| `brand/profile.md §7` 에 저장 위치를 바꿔 뒀다 | 그쪽 |
| **이름 있는 체인**(§4 체인표 17종 + 팀 이름 넷, `brand/my-playbook.md` 에 적어 둔 것 포함) | `outputs/{YYYY-MM}-{프로젝트명}/{순번}-{번호}-{이름}/`, **스킬마다 자기 번호-슬러그 폴더를 그대로 쓰되**, 이 프로젝트 폴더 아래 나란히 둔다. 한 스킬 폴더 안에 다른 스킬 파일을 섞지 않는다 |
| 이름 없는 임시 조합(§4 표에 없는 조합을 그때그때 붙였다) | **주 스킬**(결론을 내는 것)의 경로에 전부 모은다 |

⛔ **"여러 스킬 조합"과 "이름 있는 체인"을 섞어 판단하지 않는다.** §4 표의 15→17종이나
팀 이름(브랜드·콘텐츠·퍼포먼스·그로스)으로 불렀으면 **무조건 이름 있는 체인 규칙**이다.
주 스킬 폴더에 몰아 담지 않는다 (실측 2026-09-14·09-15 · 8장 015→053→051→052, 10장
045→046→043 이 각자 자기 폴더 대신 마지막 스킬 폴더 밑에 잘못 저장됨). 표에 없는,
정말 즉석에서 붙인 조합일 때만 주 스킬 경로로 모은다.

- **같은 날 같은 스킬을 다시 돌리면** 파일에 `-2`, 영수증에 `run-2.json`을 붙인다. 둘의 순번을 맞추고 덮어쓰지 않는다
- **다시 돌려도 화면은 처음과 같다.** 폴더는 그대로(`outputs/{날짜}/{번호}-{슬러그}/`), 파일 이름에만 순번이 붙는다. 계획 제목에 「(재실행)」을 붙이지 않고, 「같은 요청이 N번째라」 같은 서두를 쓰지 않는다 (실측 2026-09-14 코워크)
- ⚠️ **확장자를 바꾸지 않는다.** 대시보드는 `.html`, 판매분석은 `.csv`, 제안서는 `.pptx` 다
- ⛔ **폴더 이름을 짓지 않는다.** `가격인하-대응-자문/`, `ads/` 같은 것은 전부 위반이다

### 실적 기록 (G3)

확인이 끝난 산출물은 `logs/build-log.md` 에 **1행**으로 남긴다. 체인이면 스킬별로 각 1행.

🔴 **여덟 열이다. 줄여 쓰지 않는다** (정본 `docs/원장-운영.md`).
실측 2026-09-01, 빈 폴더 새 실행에서 **여섯 열로 지어냈다.**
「데이터 모드」와 「상태」가 빠져 **샘플로 돈 것인지, 완료된 것인지가 원장에 안 남았다.**

```
| 일시 | 스킬 ID | 요청 | 데이터 모드 | 산출물 경로 | 게이트 | 보완 횟수 | 상태 |
```

| 열 | 허용값 |
|---|---|
| 데이터 모드 | `실데이터`, `샘플`, `추정`, `혼합` |
| 게이트 | `해당없음`, `✅`, `⚠️`, `⛔`, `AI 규제검토자 미호출` |
| 상태 | `완료`, `차단됨`, `저장실패`, `중단` |

⛔ **원장이 없으면 이 여덟 열로 만든다.** 옛 여섯 열 파일을 만나면 `marketing-team-setup`이 옮긴다.
**기록 누락은 규격 위반이다.** ⛔ 차단은 「차단됨」으로 적되 누적 카운터에는 넣지 않는다.

**어느 상태로 끝내나, 넷뿐이다** (실측 2026-09-01, `interrupted` 를 잘못 골랐다)

| 무슨 일이 있었나 | 영수증 | 원장 상태 | 화면에는 |
|---|---|---|---|
| 검토가 다 통과했다 (규제 `pass`, 사업 `approved`) | `completed` | `완료` | 완료라고 말한다 |
| **만들었지만 발행이 보류다** (규제 `⚠️` 근거 필요, `⛔`) | `blocked` | `차단됨` | **「파일은 남았고 발행만 보류입니다」** |
| 저장에 실패했다 | `save-failed` | `저장실패` | 화면 결과는 그대로 내고 못 남긴 사실을 적는다 |
| **사람이 도중에 그만뒀다** | `interrupted` | `중단` | 어디까지 됐는지와 재개 방법 |

🔴 **`interrupted` 는 사람이 그만둔 것에만 쓴다.** 검토가 ⚠️ 라서 완료를 못 준 것은
**중단이 아니라 보류**다. 실측에서 이것을 `interrupted` 로 적어, 사용자는 완주한 결과를
받았으나 기록에는 「중단」으로 남았다. **회상과 통계가 그 실행을 미완으로 집계한다.**

원장 행을 쓴 뒤 `run-receipt.mjs finalize "{run.json}" --status completed`를 실행한다.
산출물이 검토 뒤 달라졌거나, 필수 검토가 최종 통과가 아니거나, 원장에서 실행을 못 찾으면
`verification-failed`다. **G4에서 완료라고 말하지 않고** 고친 뒤 재검토한다.
