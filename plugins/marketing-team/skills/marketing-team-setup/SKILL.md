# 마케팅 팀 구축하기 · 쓸 수 있게 만든다

> ⚠️ **경로 규칙은 `docs/공통규약.md §0` 이다.**
> `100-skills/` · `docs/` · `sample-data/` · `brand-templates/` 는 **패키지 안**
> (플러그인이면 `${CLAUDE_PLUGIN_ROOT}` 아래, 폴더로 열었으면 현재 폴더).
> `brand` · `outputs` · `logs` · `inputs` 는 **언제나 현재 작업 폴더**다.

**3단계고, 멈추는 곳은 두 번뿐이다** (우리 회사 정보를 넣었으면 ③-d 마무리에서 한 번 더). 설명하지 않는다. 검사하고, 받고, 넘긴다.
「이게 뭔가」, 「무엇을 시킬 수 있나」는 `marketing-team-tasks` 가 맡는다. 여기서 다시 설명하지 않는다.

## ⓪ 여는 화면 · 무엇을 할지 먼저 보인다

**첫 화면에서 무언가를 요구하지 않는다.** 무엇을 할지 3가지로 보이고 **건너뛸 수 있다고 먼저 말한다.**
사용자가 첫 화면에서 요구를 받으면 거기서 닫는다.

⭐ **①을 먼저 확인하고, 그 값을 넣어 이 화면을 낸다.** 확인하기 전에 내지 않는다.

```
마케팅 팀을 구축하겠습니다. 3단계면 끝납니다.

  ① 설치 점검   진입 스킬 {n} · 판정·세팅 담당 {n} · 업무 스킬 {n}
  ② 작업 공간   brand · inputs · outputs · logs
  ③ 회사 정보   제품 · 고객 · 채널 · 숫자 · 경쟁 · 금기

③까지 채우면 스킬 100개가 우리 회사 기준으로 돌아갑니다.
③은 건너뛰어도 됩니다. 샘플로 돌리거나, 스킬만 단독으로 쓰실 수 있습니다.

다 되면 「마케팅 팀 업무 시작하자」 하고 불러 주세요.
```

⛔ **여기서 멈추고 묻지 않는다.** 보여 주고 바로 ②로 간다.
멈추는 곳은 **③의 세 가지 선택**과 **③-b** 뿐이다. 우리 회사 정보를 넣었을 때만 **③-d** 에서 한 번 더 멈춘다.

⛔ **①이 확인하는 7가지 가운데 3가지만 낸다.** 나머지 4가지(폴더 구조·머리말·명부·설정)는
**어긋났을 때만** 한 줄로 말한다. 다 맞았으면 7줄을 늘어놓지 않는다.

⛔ **숫자를 지어내지 않는다.** 어긋나면 어긋난 값을 그대로 넣는다 (①).

## ① 제대로 깔렸나 · 하나씩 확인한다

**있다고 말하지 않고 확인한다.**

⛔ **터미널부터 찾지 않는다. 파일을 직접 읽어 확인한다.**
**데스크톱 앱에는 터미널이 없다.** 승인을 요구하며 멈추면 사용자는 첫 화면에서 막힌다.
`ls` · `find` · `node` 없이 **파일을 열어 보는 것만으로 아래 7개를 전부 확인할 수 있다.**
**② 작업 공간과 `CLAUDE.md` 를 볼 때도 같다.** 없는 파일을 `ls` 로 보면 명령이 「실패」로 뜨고,
사용자는 설치가 깨진 줄 안다 (실측 2026-10-29 코워크 · 아직 없는 게 정상인 `ls CLAUDE.md` 가 Exit code 2).
셸을 꼭 써야 하면 없는 것이 실패로 끝나지 않게 쓴다 (`[ -e CLAUDE.md ] && echo 있음 || echo 없음`).

> 클로드 코드에서 **더 꼼꼼히 보고 싶을 때만** `node "${CLAUDE_PLUGIN_ROOT}/scripts/verify.mjs"` 를
> 제안한다. **먼저 확인해 결과를 보여준 뒤에** 권한다. 승인을 기다리며 멈추지 않는다.

| # | 확인하는 것 | 통과 |
|---|---|---|
| 1 | `agents/` 의 `.md` 파일 수 | **3** (결론 둘 · 세팅 하나) |
| 2 | `agents/` 에 하위 폴더가 있나 | **없어야** 한다. 있으면 그 담당은 스캔되지 않는다 |
| 3 | `agents/` 의 모든 `.md` 에 frontmatter | 전부. 없으면 **유령 담당** |
| 4 | `skills/` 폴더마다 `SKILL.md` | **3개**: `marketing-team-setup` · `ai-marketer` · `marketing-team-tasks` |
| 5 | `100-skills/` 의 `SKILL.md` | **100** |
| 6 | `100-skills/ROUTING.md` 가 열리나 | 열려야 한다 |
| 7 | `.claude-plugin/plugin.json` 의 `repository` | **문자열**. 객체면 플러그인 전체가 로드 실패 |

**숫자가 어긋나면 그 숫자를 그대로 말한다.** 「100개가 있습니다」라고 지어내지 않는다.

> ⚠️ **스킬 100개는 등록되지 않는다. 의도된 설계다.** 전부 등록하면 매 세션 약 1만 5천 토큰이 항상 실린다.
> 명부 한 장만 보고 본문은 매칭된 순간에 연다. 그래서 `/` 목록에 **셋만** 보이는 것이 정상이다.

### 브라우저 도구는 따로 붙는다 · 7개 항목에 넣지 않는다

**이 플러그인은 `.mcp.json` 으로 브라우저 도구(`playwright`)를 함께 낸다.** 플러그인을 설치할 때
클로드가 「이 MCP 서버를 붙일까요?」를 한 번 묻고, 승인하면 그때 붙는다. **따로 설치할 것은 없다.**

⛔ **①의 7개 항목에 넣지 않는다.** 7개는 플러그인 안을 확인하는 것이고 브라우저 도구는 밖에서 붙는다.
「여덟 항목」이라고 말하지 않는다.

| | |
|---|---|
| **무엇이 달라지나** | 공개된 웹 페이지를 직접 읽는다 · `[추정]` 이 실측으로 바뀐다 |
| **어느 스킬이** | `001` 키워드 수요 조사 · `002` 경쟁사 분석 · `003` 경쟁사 상시 조사 · `005` 트렌드 조사 · `038` 소셜 언급 분석 |
| **못 붙었으면** | 그 스킬들은 **그대로 돈다.** 자료를 손으로 받는 길로 돌아갈 뿐이다 |

### 문서 스킬 · 있으면 더 되고 없어도 완주한다

`.pptx`·`.docx`·`.xlsx`·`.pdf` 는 **앤트로픽 공식 스킬**이 맡는다. **대부분 이미 깔려 있다.**
점검에서 없으면 **한 줄로만 알린다.** ⛔ 설치를 강요하지 않는다.

```
발표자료를 .pptx 로 받거나 PDF·워드 문서를 읽으려면 공식 문서 스킬이 필요합니다.
  /plugin marketplace add anthropics/skills
  /plugin install document-skills@anthropic-agent-skills
없어도 전 과정이 완주됩니다. 그때는 .md 로 나갑니다.
```

**`.pptx`·`.docx` 를 짓는 도구도 함께 본다.** 공식 스킬은 `.pptx` 를 `pptxgenjs` 로, `.docx` 를 `docx` 로 짓는다.
둘 다 node 도구이고 **작업 폴더 맨 위 `node_modules`** 에 있어야 산출물 스크립트가 찾는다.
컴퓨터 전체에 깐 것(전역 설치)은 `outputs/` 안 스크립트가 찾지 못한다 (실측 2026-10-15).
공식 스킬에 「미리 깔려 있다」고 적힌 것은 클로드 웹 환경 이야기다. 사용자 컴퓨터에는 대개 없다.

| 확인하는 것 | 어떻게 · 파일을 열어 본다 | 열리면 |
|---|---|---|
| `pptxgenjs` | 작업 폴더의 `node_modules/pptxgenjs/package.json` | 「있음 (v`version`)」 |
| `docx` | 작업 폴더의 `node_modules/docx/package.json` | 같음 |

⛔ `node -v`·`npm ls` 로 확인하지 않는다. AI 마케터가 켜진 대화에서는 실행 보호 훅이 막는다.
파일이 안 열리면 「없음」이다. 터미널이 있으면 `ls node_modules/pptxgenjs` 도 돈다.
⛔ **우리가 설치하지 않는다.** `npm install` 은 훅이 막는다. 사용자 컴퓨터에 까는 일은 사용자가 한다.

없으면 아래를 **그대로** 낸다. `{작업 폴더}` 만 지금 작업 폴더 경로로 바꾼다.
이 문구가 정본이다. `084` 와 `docs/공통규약.md §H` 가 여기를 가리킨다.

```
발표자료(.pptx)와 워드 문서(.docx)를 파일로 받으려면 도구 두 개를 작업 폴더에 한 번 깔아 주세요.
공식 문서 스킬이 이 두 도구로 파일을 만듭니다.

  1. 터미널을 엽니다
       클로드 코드: 지금 대화하는 창 말고 터미널 창을 하나 더 엽니다
       데스크톱 앱: 맥은 「터미널」 앱, 윈도우는 「PowerShell」을 엽니다
  2. 작업 폴더로 갑니다
       cd "{작업 폴더}"
  3. 아래 한 줄을 붙여 넣고 엔터를 누릅니다
       npm install pptxgenjs docx

「npm 을 찾을 수 없다」고 나오면 node 가 없는 것입니다.
nodejs.org 에서 LTS 버전을 받아 깔고 3번을 다시 하세요.

깔지 않아도 다른 업무는 그대로 됩니다. 발표자료와 문서는 .md 개요로 나갑니다.
```

⛔ **①의 7개 항목에 넣지 않는다.** 브라우저 도구와 같다. 플러그인 밖에서 붙는다.

**안 붙어도 멈추지 않는다.** 사용자가 승인을 안 했거나 `node` 가 없으면 안 붙는다.
그때 **구축을 멈추지 않는다.** 위 넷을 부를 때 「브라우저 도구가 없어 손으로 주셔야 한다」고 그 자리에서 말한다.

🔴 **로그인이 필요한 페이지는 읽지 않는다.** `--isolated` 로 띄워 사용자의 로그인 상태를 쓰지 않는다.
광고 관리자·스토어 관리자처럼 로그인 뒤에 있는 값은 **사용자가 내려받아 준다.**

### 「업데이트가 안 돼요」면 · 세 층을 나눈다

```
① 마켓플레이스   저장소에서 받아 온 목록      계정에 저장
      ↓
② 플러그인       그 목록에서 설치한 것        계정에 저장
      ↓
③ 대화          열 때 설치된 것을 읽는다      대화마다
```

| 결론 | 어떻게 |
|---|---|
| **③** | **이 스킬이 돌고 있으면 정상.** 더 볼 것 없다 |
| **②** | `plugin.json` 의 `version` 을 읽는다 |
| **①** | 같은 파일의 `repository` 에서 raw 주소를 만들어 저장소 최신과 비교. 못 읽으면 **결정하지 않는다** |

| 결과 | 사용자에게 |
|---|---|
| 같다 | 「최신입니다 (vX.Y.Z)」 |
| 설치본이 낮다 | 「저장소는 vA, 설치본은 vB. **마켓플레이스를 먼저 동기화**한 뒤 플러그인을 업데이트하세요」 |
| 못 읽음 | 「설치본은 vB. 최신인지는 확인하지 못했습니다」 |

⚠️ **「업데이트하세요」만 말하지 않는다.** 사용자는 플러그인 버튼부터 누르고,
그 버튼은 낡은 목록과 비교하므로 「새것 없음」으로 표시된다. **거기서 대부분 막힌다.**

| 증상 | 층 | 대처 |
|---|---|---|
| 담당이 하나도 안 보인다 | 플러그인 로드 실패 | ①의 7번부터 |
| 설치했지만 `/` 목록에 없다 | ③ | **새 대화**를 연다 |
| 되다가 안 되다가 한다 | ③ | 같음 |
| 「더 이상 마켓플레이스에 없습니다」 | ①–② 끊김 | 플러그인 제거 → **앱 재시작** → 마켓플레이스 동기화 → 재설치 → 새 대화 |
| 폴더로 열었지만 안 보인다 | `.claude/` 연결이 텍스트 파일로 풀림 (윈도우) | 그 파일을 지우고 `agents`·`skills` 를 `.claude/` 안으로 복사 |

**⛔ 마켓플레이스를 먼저 지우지 않는다.** 플러그인이 출처를 잃고 고아가 된다. 지울 때는 아래층부터.

### 「처음부터 다시 하고 싶어요」 · 완전 초기화

「지웠다 다시 깔았는데 옛날 것이 그대로다」는 **캐시가 남아서**다.
플러그인을 제거해도 **버전별 사본과 설치 기록이 남는다** (실측 2026-08-26 · 3.4MB · 466개 파일).
그래서 재설치해도 같은 버전을 다시 집는다.

**⚠️ 먼저 나눈다. 무엇을 리셋하려는 것인가.**

| 하고 싶은 것 | 해야 할 일 |
|---|---|
| **내 데이터만 새로** (처음 쓰는 것처럼) | **새 폴더를 하나 잡고 「구축하자」.** 그것뿐이다 |
| **최신 버전 받기** | 마켓플레이스 동기화 → 플러그인 업데이트 |
| **찌꺼기까지 전부** | 아래 순서 |

⛔ **대부분은 첫 줄이면 된다.** 플러그인은 읽기 전용이라 내 데이터를 갖고 있지 않다.
지웠다 깔아도 달라지는 것이 없다. **기억은 작업 폴더에 있다.**

**그래도 전부 밀어야 하면 · 순서를 지킨다**

```
① 플러그인 제거
② 마켓플레이스 제거          ← 여기를 건너뛰면 낡은 목록이 남아 옛 버전을 다시 집는다
③ 앱 재시작
④ 캐시·설치 기록 삭제 (아래)
⑤ 마켓플레이스 다시 추가 → 플러그인 설치
⑥ 새 대화
```

④는 **터미널이 있어야 한다.** 데스크톱 앱에는 없으므로 ①②③⑤⑥만 하고,
그래도 옛 버전이면 클로드 코드에서 ④를 하거나 지원에 문의한다.

```
~/.claude/plugins/cache/marketing-team/           버전별 사본 (제일 큰 찌꺼기)
~/.claude/plugins/data/marketing-team-*/          플러그인 데이터
~/.claude/plugins/installed_plugins.json          "marketing-team@marketing-team" 항목
~/.claude/plugins/known_marketplaces.json         "marketing-team" 항목
```

⛔ **뒤 두 JSON 은 다른 플러그인 기록도 함께 들어 있다. 파일째 지우지 않는다.**
해당 항목만 뺀다. 지우기 전에 **두 파일을 복사해 둔다.**

⚠️ **작업 폴더는 이 절차로 지워지지 않는다.** `brand` · `outputs` · `logs` 는 그대로 남는다.
**그것이 맞다.** 제품을 밀어도 내 데이터는 남아야 한다.
작업 데이터까지 버리려면 그 폴더를 직접 지우거나, **새 폴더에서 시작한다** (이쪽을 권한다).

## ② 작업 공간을 만든다

**팀은 패키지 안에 살고, 산출물은 내가 일하는 공간에 떨어진다.** 둘은 다른 곳이다.

| | 작업 공간 |
|---|---|
| 데스크톱 앱 | 접근을 허용한 폴더(설정의 「Trusted folders」) · 안 골랐으면 지금 이 작업이 파일을 만드는 곳 |
| 클로드 코드 | 지금 열어 둔 폴더 |
| 폴더로 클론했으면 | 그 저장소 폴더 |

거기에 넷이 없으면 **묻고 만든다** (⏸).

```
brand     내 브랜드 정보 · 우리 보완
outputs   산출물이 떨어지는 곳
logs      실적 원장
inputs    내 파일을 넣어 두는 곳
```

### 어디에 만드나 · 여기 바로냐, `marketing-team/` 안이냐

**지금 폴더를 보고 기본값을 정한 뒤 ⏸ 로 묻는다.** 고정하지 않는다.
데스크탑에 넷을 흩뿌리면 지저분하고, 전용 폴더에 한 겹을 더하면 군더더기다.

| 지금 폴더가 | 기본값 | 왜 |
|---|---|---|
| 비어 있거나 **이 일 전용**으로 보인다 | **여기 바로** | 한 겹이 늘면 경로만 길어진다 |
| 데스크탑·홈·**다른 것이 이미 많은 곳** | **`marketing-team/` 안** | 넷이 흩어지면 나중에 못 찾는다 |

```
여기에 작업 공간을 만듭니다. 어디에 둘까요?

  ① marketing-team/ 폴더를 만들고 그 안에      ← 데스크탑이라 이걸 권합니다
       marketing-team/brand · outputs · logs · inputs
  ② 여기 바로
       brand · outputs · logs · inputs
⏸
```

⚠️ **①을 골랐으면 반드시 한 줄 알린다.** 작업 폴더는 **넷이 있는 곳**이다.

```
✅ ~/Desktop/marketing-team/ 에 만들었습니다.
   앞으로는 데스크탑이 아니라 **이 폴더를 열고** 일해 주세요.
   여기서 일하지 않으면 산출물이 다른 곳에 쌓입니다.
```

이 말을 빠뜨리면 사용자가 계속 상위 폴더를 열고, **작업 공간을 못 찾아 또 만든다.**

### 무엇을 어디로 복사하나 · 이 표대로만 한다

⛔ **「빈 템플릿을 복사한다」로 끝내지 않는다.** 무엇을 어디에 놓을지 안 적으면
실행할 때마다 달라진다. **실측 (2026-08-25), `profile.md` 가 빠지고
`build-log-summary.md` 가 미리 생겼다.** 가장 중요한 것이 빠진 채 완주했다.

| 템플릿 (`brand-templates/`) | → 어디 | 언제 |
|---|---|---|
| `profile.md` | `brand/profile.md` | **항상**. ⚠️ 빠지면 사용자가 자기 정보를 넣을 양식이 없다 |
| `tone.md` | `brand/tone.md` | **항상** |
| `my-playbook.md` | `brand/my-playbook.md` | **항상** |
| `build-log.md` | `logs/build-log.md` | 없을 때만 (있으면 헤더만 본다 · 아래 「원장을 만든다」) |
| `memory/INDEX.md` | `brand/memory/INDEX.md` | 없을 때만. **빈 색인이다.** 있으면 그대로 둔다 |
| `build-log-summary.md` | - | ⛔ **손으로 만들지 않는다.** 세션 훅이 주마다 다시 만든다 |
| `skill-notes.md` | - | ⛔ **빈 것을 미리 만들지 않는다.** ③-d 초안이나 「계속 이렇게」를 사람이 승인할 때 생긴다 |
| `작업폴더-CLAUDE.md` | 작업 폴더 맨 위 `CLAUDE.md` | **③-d 에서만.** 우리 회사 정보를 넣었을 때만 만든다. 샘플이면 안 만든다 · 있으면 덮어쓰지 않는다 |
| `compliance-custom.md` | - | ⛔ **미리 만들지 않는다.** **AI 규제세팅**이 만든다 (사전에 없는 업종일 때 ⏸) |
| `업무-스킬-분해표.md` | - | ⛔ 참고 문서다. 복사하지 않는다 |

**셋(`profile`·`tone`·`my-playbook`)을 복사했으면 셋이라고 말한다.**

⚠️ **`brand/memory/` 는 폴더와 빈 색인만 만든다. 주제 폴더는 미리 만들지 않는다.**
빈 폴더 6개를 보면 채워야 할 것 같아진다. 첫 기억이 생길 때 `memory.mjs capture` 가 만든다
(정본 `docs/기억-운영.md`).
하나라도 못 했으면 어느 것을 왜 못 했는지 적는다. 조용히 넘어가지 않는다.

⚠️ **이미 있으면 덮어쓰지 않는다.** 사용자가 채운 것이 사라진다.

⚠️ **패키지 안에 쓰지 않는다.** 거기 쓰면 플러그인을 업데이트할 때 산출물이 통째로 날아간다.

### 원장을 만든다

```
없으면        brand-templates/build-log.md 를 복사한다
있으면        헤더를 본다
```

**헤더가 정본과 다르면**: 구형은 `| 일시 | 방법론 | 담당 | 산출물 | 게이트 | 보완 |` 6열이다.
⛔ **말없이 고치지 않는다.** 지난 기록이 사라진다. **보여주고 묻는다.**

```
실행 기록이 옛 형식입니다 (6열). 지금은 8열이라 저장 누락 점검이 안 돕니다.

  지금        일시 | 방법론 | 담당 | 산출물 | 게이트 | 보완
  새 형식     일시 | 스킬 ID | 요청 | 데이터 모드 | 산출물 경로 | 게이트 | 보완 횟수 | 상태

  옮기면 logs/build-log-{오늘}.bak.md 로 백업하고, 기존 {N}행은 아는 값만 채웁니다.
  (요청·데이터 모드·상태는 빈칸으로 두고 「구형 이관」이라 표시합니다)

⏸ 옮길까요? 그냥 두면 새 행부터 8열로 쌓입니다. 점검은 새 행만 봅니다.
```

열 순서는 정본 그대로 (`docs/공통규약.md §H`).

## ③ 우리 회사 정보 · 6묶음 · 건너뛸 수 있다

⏸ **먼저 묻는다. 이 질문은 여기서 한 번뿐이다.**

⛔ **아래 문안을 그대로 낸다. 줄이거나 바꾸지 않는다.** 실측 2026-08-31, 모델이 화면을
아끼려 선택지 문안을 임의로 요약했다. 이 문안은 사용자가 낱말 단위로 확정한 정본이다.
한 글자도 빼지 않는다. [틀]·스킬 유형 설명은 여기서 하지 않는다. 산출물이 스스로 설명한다.

```
어떤 회사 정보로 실습할까요?

  ① 준비된 샘플 정보로 실습한다 (권장)
     가상의 A브랜드(화장품) 자료가 이미 들어 있습니다. 바로 시작할 수 있습니다.
     결과 첫 줄에 [샘플] 이 붙습니다. 숫자와 고객이 우리 것은 아닙니다.

  ② 우리 회사 정보로 실습한다
     여섯 가지를 여쭙고 3분이면 끝납니다. 한 번 답하면 다시 묻지 않습니다.
     스킬 100개가 우리 것 15~30개로 줄고, 결과 첫 줄이 [실데이터] 로 바뀝니다.

  ③ 회사 정보 없이 스킬만 사용한다
     필요한 재료를 그때그때 확인합니다.
     핵심 메시지 한 줄이면 ②와 같은 결과가 나옵니다.

  ⭐ 업종 한 줄만 알려주셔도 규제 검사가 우리 업종 기준으로 달라집니다. 「우리는 반려동물 사료야」

  ① 을 고르셔도 나중에 「브랜드 정보 넣을래」 하시면 그때 채웁니다.
```

**①을 골라도 전 과정이 완주된다.** 나중에 「브랜드 정보 넣을래」 하면 그때 채운다.

### ⭐ 여섯을 묻되 · **답하는 방식은 강요하지 않는다**

⛔ **답을 칸에 맞춰 쓰라고 강요하지 않는다.** 묻는 것은 여섯이지만
**어떻게 답하든 받는다.** 한 줄이든, 줄글 한 덩이든, 상세페이지를 통째로 붙여넣든.

> 여섯 묶음 자체는 그대로 쓴다. **사용자는 마케터고**(규약 §0-a) 이 여섯은
> 마케터의 언어다. 「채널 비중」, 「경쟁사 고른 기준」, 「금기 표현」은 설명이 필요 없다.
> ⛔ 다만 **④ 숫자만 업태를 탄다.** 마진율은 물건 파는 사람의 말이라
> 로컬·B2B·구독이면 **「한 명 데려오는 데 얼마까지」**로 묻는다 (③-a).

**여섯을 한 화면에 다 보여준다.** 무엇을 물을지 미리 아는 편이 답하기 쉽다.
다만 **순서대로 답하라고 하지 않는다.**

```
우리 회사 얘기를 들려주세요. 여섯 가지를 여쭤보긴 할 텐데,
편하게 한 번에 말씀하셔도 되고 하나씩 답하셔도 됩니다.

  ① 브랜드·업종·주력   ② 타깃과 사는/떠나는 이유   ③ 굴러가는 채널과 비중
  ④ 숫자              ⑤ 경쟁사와 고른 기준        ⑥ 안 쓰는 표현

  ⭐ 더 빠른 길 · 상세페이지·소개글·리뷰를 그냥 붙여넣으셔도 됩니다.

  하나 더 여쭙니다. 만든 결과물은 누가 보시나요?
  「팀장님께 매주 월요일에 올려요」, 「대표라 혼자 봐요」, 「고객사에 매달 보내요」처럼 말씀해 주세요.
```

**마지막 질문이 역할이다.** 답에서 내 역할, 팀 규모, 보고받는 사람, 보고 주기를 읽어 `profile.md §8 우리 팀과 내 역할` 에 적는다.
⛔ 역할은 사실이라 대신 쓰지 않는다 (③-b 대상이 아니다). 답이 없으면 §8 을 비워 두고, 그러면 지금처럼 돈다.

- **줄글로 오면 그대로 §0 에 적고**, 거기서 읽어 §1~§6 을 채운다
- **하나씩 답하시면** ③-a 의 예시 한 줄을 붙여 순서대로 묻는다
- 어느 쪽이든 **이미 답이 나온 것은 다시 묻지 않는다**

**그중 셋은 반드시 확인하고 넘어간다.** 기계가 계산·매칭에 쓰는 값이다.

| 확인할 것 | 왜 | 이렇게 묻는다 |
|---|---|---|
| **업종** (§1) | **규제 사전 스위치**. 틀리면 다른 법이 걸린다 | 「화장품 맞을까요?」 한 단어 |
| **숫자 하나** (§4) | **광고 결론 기준선**. 계산에 들어간다 | 실물이면 마진율, 아니면 **「한 명 데려오는 데 얼마까지?」** |
| **금기 표현** (§6) | 게이트가 **문자로 잡는다** | 「쓰시면 안 되는 말 그대로 알려주세요」 |

- 이미 답이 나왔으면 **다시 묻지 않는다.** 읽어서 채우고 **맞는지만 보여준다**
- 나머지(고객·포지셔닝·채널·경쟁)는 **말한 그대로 §2·§3·§5 에 정리해 넣는다.**
  사용자가 표 모양으로 맞춰 쓸 필요는 없다
- **모른다고 하면 비우지 않는다. 대신 써 준다** (아래 ③-b)
- 얼마나 자세히 쓰면 되는지는 ③-a 가 기준이다



**아래 표는 「순서대로 물을 목록」이 아니라 「결국 채워질 자리」다.**
줄글에서 읽어 채우고, 안 채워진 것만 물으며, 그때도 ③-a 의 예시를 붙인다.

| # | 묶음 | 꼭 필요한 것 | 비면 |
|---|---|---|---|
| 1 | **기본** | 브랜드명 · **업종** · 핵심 제품 3 | 업종이 없으면 규제 사전이 공통(표시광고법)만 걸린다 |
| 2 | **고객** | 핵심 타깃 · 사는 이유 3 · 떠나는 이유 3 | 페르소나·카피가 일반론이 된다 |
| 3 | **채널** | 실제로 굴러가는 채널만 | 없는 채널을 적으면 안 도는 계획이 나온다 |
| 4 | **숫자** | 마진율 → **손익분기 ROAS(=1÷마진율)** · 월 예산 | 광고 결론이 전부 `[추정]` |
| 5 | **경쟁** | 경쟁사 3곳과 고른 기준 | 비교표의 기준이 흔들린다 |
| 6 | **금기** | 절대 쓰지 않는 표현 | 게이트가 공통 기준만 본다 |
| + | **우리 팀** (§8) | 내 역할 · 보고받는 사람 · 보고 주기 | 실무 담당 기준으로 나온다 (지금과 같다) |

> ⚠️ **4번을 특히 챙긴다.** 손익분기 ROAS 는 흑자·적자를 나누는 기준선이다.
> 없으면 ROAS 2.0이 좋은 건지 나쁜 건지 아무도 모른다.

**어느 정도로 받아야 하는지는 칸마다 다르다.** ③-a 가 그 기준이다.
②만 한 뼘 더 받고 나머지는 한 줄이면 된다.

**업종을 받으면 규제가 갈아 끼워진다**: 화장품법·건강기능식품법·식품표시광고법·약사법·금소법.

### ⛔ 사전에 **없는 업종**이면 · 여기서 끝내지 않는다

정본 사전이 덮는 것은 **다섯**뿐이다(화장품·건기식·일반식품·의약품/의료기기·금융).
반려동물 사료·주류·유아용품·렌탈·핀테크·리빙은 **공통(표시광고법)으로만** 걸린다.
그런데 이 카테고리들의 진짜 위험은 공통으로 **안 잡힌다**.
사료의 「면역력 개선」(동물용의약품 오인), 주류의 미성년 소구, 렌탈의 「월 OO원」 총액 미표시가 그렇다.

**그때는 `staff-compliance-setup`(AI 규제세팅) 을 부른다.**

```
「반려동물 사료」는 규제 사전에 따로 없어서 지금은 공통(표시광고법)만 걸립니다.
그런데 이 카테고리는 **동물용의약품 오인**을 조심해야 해서 공통만으로는 부족합니다.

  조심할 말 목록을 만들어 드릴까요? (2분 · 다음부터 발행할 때마다 함께 검사합니다)
```

- ⏸ **승인 후에만** `brand/compliance-custom.md` 로 남는다
- **초안이고 법률 자문이 아니라는 것**을 반드시 함께 말한다
- 사전에 **있는** 업종이면 부르지 않는다. 그 섹션이 이미 정본이다
- 우리만의 금기는 어느 경우든 같은 파일(`brand/compliance-custom.md`)에 쌓인다

받은 값은 `brand/profile.md` (톤은 `brand/tone.md`) 로 쓴다.
**이미 있으면 처음부터 다시 받지 않는다.** 지금 값을 표로 보여주고 **고칠 곳만** 손댄다.

## ③-a 어느 정도로 쓰나 · **묻는 자리에서 예시를 함께 낸다**

처음 쓰는 사람이 가장 많이 하는 질문이다. 「얼마나 자세히 써야 해요?」
**분량이 아니라 종류가 문제다.** 한 줄이면 충분하고, 그 한 줄이 **우리만 쓸 수 있는 말**이어야 한다.

⛔ **아래 표를 통째로 먼저 내밀지 않는다.** 3분이 깨지고, 6칸을 한꺼번에 보면 처음처럼 막힌다.
**묻는 칸의 「이렇게 답하면 됩니다」 한 줄만** 질문에 붙인다.

### 자가 점검 한 줄 · 이것만 기억하면 된다

> **경쟁사가 그대로 써도 말이 되는 문장이면, 다시 받는다.**

「저자극」은 그 업종 전부가 쓴다. 「다음 날 안 올라와서」는 우리만 쓴다.

### 칸마다 나누는 것이 다르다

| 묶음 | 결과를 나누는 것 | 길이 | 질문에 붙이는 예시 |
|---|---|---|---|
| ① 기본 | **업종 한 단어**: 규제 사전이 통째로 나뉜다 | 한 단어 | 「화장품」·「건기식」처럼 한 단어면 됩니다 |
| ② 고객 | **명사가 아니라 고객이 한 말** | **여기만 한 뼘 더** | 리뷰에 있는 말 그대로도 좋습니다 |
| ③ 채널 | **비중 숫자 + 죽은 채널 구분** | 한 줄 | 「자사몰 45 · 스토어 35 · 쿠팡 20, 블로그는 만들다 말았음」 |
| ④ 숫자 | **마진율 하나** · 정확도보다 존재 | 숫자 하나 | 「33% 정도」면 충분합니다 |
| ⑤ 경쟁 | 이름보다 **고른 기준** | 한 줄 | 「같은 가격대에서 자주 비교되는 곳」 |
| ⑥ 금기 | **실제 문자열** | 단어 나열 | 「완치」·「부작용 없음」처럼 **쓰는 말 그대로** |

### ② 만 한 뼘 더 받는다 · 여기가 결과를 가장 크게 나눈다

**프로필을 읽는 스킬은 100개이고, 그중 카피·상세페이지·광고가 이 칸을 문장째로 쓴다.**
명사로 받으면 그 업종 전부의 상세페이지와 똑같아진다.

| | |
|---|---|
| 🟡 **아쉽다** | 저자극 · 성분 공개 · 가벼운 사용감 |
| ✅ **좋다** | 다른 거 쓰면 다음 날 올라오는데 이건 안 올라와서<br>뒷면에 뭐 들었는지 다 적혀 있어서 믿고 샀다<br>여름에 발라도 안 미끈거려서 |

**리뷰에서 그대로 베끼는 것이 가장 빠르다.** 없으면 ③-b 로 초안을 내고 고르게 한다.

### ④ 는 정확도보다 **존재**다

「33% 정도」의 *정도*는 문제가 안 된다. **없는 것만 문제다.**

```
마진율 33%  →  손익분기 ROAS 3.0  →  월 400만원이면 1,200만원 팔아야 본전
```

이 한 줄이 **광고 결론의 기준선**이다. 1.61이든 1.60이든 결론은 안 바뀐다.
⛔ 그래서 ③-b 에서도 **이 값만은 대신 쓰지 않는다.** 지어내면 흑자·적자가 뒤집힌다.

### 업종이 다르면 **묻는 말이 바뀐다. 칸은 안 바뀐다**

⚠️ **아래 넷은 닫힌 목록이 아니고, 실제로는 자주 겹친다.**
정기배송 D2C 는 **실물이면서 구독**이고, 매장을 가진 브랜드는 **실물이면서 로컬**이며,
대행사 마케터는 **클라이언트마다 다른 칸**에 있다.
**업태를 분류하려 들지 않는다.** 겹치면 **둘 다 묻는다.**
이 표는 **줄글이 잘 안 나올 때 물어볼 말을 고르는 참고**다.

> 위 브랜드처럼 겹치면 **마진율(실물)과 유지 개월(구독)을 둘 다** 받는다.
> 정기배송에서 「몇 달 유지되나」는 마진율만큼 중요하다. 한 번 팔고 끝이 아니기 때문이다.


여섯 묶음은 업종을 안 탄다. 기본·고객·채널·숫자·경쟁·금기는 어디나 있다.
**바뀌는 것은 그 칸을 뭐라고 부르고 무슨 예를 드느냐**다.
「마진율」은 **실물을 파는 사람의 언어**고, 구독·B2B 마케터에게 물으면 답이 안 나온다.

⛔ **업종을 따로 묻지 않는다.** ①에서 이미 받았다. 거기서 업태를 짐작해
**애매할 때만 한 줄로 확인**한다. 「주로 온라인에서 물건을 파시는 게 맞을까요?」

| 업태 | ② 고객을 무엇으로 나누나 | ③ 채널 | ④ 숫자를 뭐라고 묻나 |
|---|---|---|---|
| **실물 판매**<br>이커머스·D2C·식품·화장품 | 나이·상황·고민 | 자사몰·스마트스토어·쿠팡·인스타 | **마진율** → 손익분기 ROAS |
| **로컬·매장**<br>오프라인 매장·지점을 가진 브랜드 | **상권·거리·방문 계기** | 네이버플레이스·지도·지역 타겟 광고 | **객단가 × 재방문 횟수** |
| **B2B·솔루션**<br>SaaS·대행·제조·용역 | **직무·회사 규모·결정권자** | 아웃바운드·전시회·레퍼런스·제안서 | **계약단가 × 유지 기간** |
| **구독·교육·콘텐츠** | **목표·수준·언제 그만두나** | 유튜브·뉴스레터·커뮤니티·앱 | **월 요금 × 유지 개월** |

### 어느 업태든 결국 같은 것을 묻는다

⭐ **「한 명 데려오는 데 얼마까지 쓸 수 있나」**. 이것만 있으면 광고 결론이 산다.
프로필 §4 의 **목표 CPA** 가 그 자리다. 위 표의 넷은 **거기에 이르는 서로 다른 길**이다.

```
실물     객단가 × 마진율            = 한 번 팔아 남는 돈
로컬     객단가 × 마진율 × 재방문    = 한 명이 평생 남기는 돈
B2B      계약단가 × 유지 기간 × 마진
구독     월 요금 × 유지 개월 × 마진
```

- **실물 판매만** 손익분기 ROAS 로 바로 간다 (`1 ÷ 마진율`). 광고 스킬 12개가 이 값을 읽는다
- **나머지 셋은 목표 CPA 를 직접 받는다.** 「한 명 모시는 데 3만원까지는 써도 남아요」면 충분하다
- ⛔ 둘 다 없으면 광고 스킬이 **`[추정]`** 으로 돈다. 멈추지는 않는다

### 금기(⑥)만은 업종법이 정한다

여기만 우리가 정하는 게 아니다. **업종을 받는 순간 규제 사전이 갈아 끼워진다**:
화장품법·건강기능식품법·식품표시광고법·약사법·금소법.
⑥ 에는 **그 위에 우리만의 금기**를 얹는다 (`brand/compliance-custom.md`).

⚠️ **사전이 덮는 것은 다섯 업종뿐이다.** 그 밖이면 공통(표시광고법)만 걸리므로
**`AI 규제세팅`을 부른다** (위 「사전에 없는 업종이면」). 같은 파일에 쌓인다.

### ⑥ 은 반드시 **쓰는 말 그대로** 받는다

게이트는 **문자로 잡는다.** 「과장 안 함」이라고 적으면 **아무것도 못 잡는다.**
「완치」, 「부작용 없음」처럼 실제 문자열이어야 한다.

### 그 밖

- **①의 주력 3개**: 제품마다 키워드·카피가 달라서 셋까지 받는다. **하나여도 완주한다**
- **⑤의 경쟁사**: 실전에서는 **실명**이 필요하다 (비교표·가격 포지셔닝이 이름으로 돈다).
  ⛔ 없다고 내가 지어내지 않는다 (규약 §L)
- **모르는 칸은 「모름」이라고 답하고 넘어가도 된다.** 그 자리는 ③-b 가 받는다


## ③-b 대신 써 드립니다 · **백지를 내밀지 않는다**

⛔ **여기가 사람들이 나가는 자리다.** 「고객이 사는 진짜 이유 3개」를 백지에서 쓰라고 하면
대부분 못 쓴다. 못 쓰는 게 아니라 **말로는 알지만 글로 정리해 본 적이 없는 것**이다.
빈칸으로 넘기면 그 항목은 **영원히 빈칸으로 남는다** (규약 §E 「빈칸은 셋 중 최악」).

### 언제 발동하나 · 묻기를 기다리지 않는다

| 신호 | 예 |
|---|---|
| 직접 묻는다 | 「이거 어떻게 써요?」 「무슨 뜻이에요?」 「예시 좀」 |
| 모른다고 한다 | 「모르겠어요」 「없어요」 「생각 안 해봤어요」 |
| 답이 한 단어다 | 「좋아서요」 「싸니까」. 그대로 적으면 카피가 일반론이 된다 |
| **두 묶음 연속 얕다** | 사용자가 지쳤다는 뜻이다. **묻지 않고 먼저 제안한다** |

### 무엇을 보고 쓰나 · 위에서부터 쓴다

| | 재료 | 무엇이 나오나 |
|---|---|---|
| **1** | **이미 받은 것**: 브랜드명·업종·제품 3 | 여기서 이미 §2 고객·§3 포지셔닝 초안이 나온다 |
| **2** | **가진 글을 붙여넣게 한다** ⭐ | 상세페이지·소개글·리뷰 몇 개. **가장 정확하다** |
| **3** | 공식 채널 URL | 열리는 곳만 본다. ⛔ 로그인 뒤는 대부분 막히니 **붙여넣기를 먼저 권한다** |
| **4** | 아무것도 없으면 업종 통념 | 초안으로 내되 **반드시 `[초안]`** |

> 「상세페이지 글 한 덩이만 붙여넣어 주세요」가 **20개 질문보다 낫다.**
> 거기에 고객·포지셔닝·톤·금기가 전부 들어 있다.

### 어떻게 내나 · **고르는 것이 쓰는 것보다 10배 쉽다**

백지를 다시 내밀지 않는다. **3개를 써서 보여주고 고치게 한다.**

```
「고객이 사는 진짜 이유」· 제가 셋 써 봤습니다. 맞는 것만 남기고 고쳐 주세요.

  ① 다른 걸 써봤는데 트러블이 나서 · 성분을 직접 확인하고 싶다
  ② 가격은 좀 되지만 한 번 사면 오래 쓴다고 들었다
  ③ 후기에 「자극 없다」가 반복돼서 믿고 샀다

  맞는 것 번호만 · 「2번은 아니고 배송이 빨라서요」처럼 말씀하셔도 됩니다
```

**한 번에 한 묶음.** 여섯을 한꺼번에 내밀면 처음과 똑같이 막힌다.

### ⛔ 말은 대신 쓴다. **사실은 대신 만들지 않는다**

| | 대신 쓰나 | 왜 |
|---|---|---|
| §2 고객 · §3 포지셔닝 · 톤 | ✅ **쓴다** | 문장이다. 틀리면 고치면 된다 |
| §6 금기 (업종분) | ✅ **쓴다** | 업종 규제에서 자동으로 나온다 |
| **§4 숫자** (마진율·객단가·예산) | ⛔ **안 쓴다** | **손익분기 ROAS 가 여기서 나온다.** 지어낸 마진율은 광고 결과 전부를 틀리게 한다 |
| **§3 경쟁사 실명** | ⛔ **안 쓴다** | 실존 이름을 지어내지 않는다 (규약 §L) |
| **§5 채널** | ⛔ **안 쓴다** | 없는 채널을 적으면 **안 도는 계획**이 나온다 |

⛔ 안 쓰는 셋은 **비우고 넘기지도 않는다.** 어디서 보면 나오는지를 말한다.

```
마진율은 제가 못 씁니다. 틀리면 광고를 흑자로 볼지 적자로 볼지가 뒤집힙니다.
  어디서   스마트스토어 → 정산관리 → 정산내역, 또는 「팔 때 받는 돈 − 원가·수수료·배송비」
  없으면   §4 를 비워 두고 갑니다. 광고 결정만 [추정] 으로 나오고 나머지는 정상입니다
```

### 쓴 값에는 표를 남긴다

⛔ **내가 쓴 값과 사용자가 준 값을 섞지 않는다.** 프로필 표 칸 끝에 `[초안]` 을 붙인다.

```
| 고객이 사는 진짜 이유 (Top 3) | ① 성분을 직접 확인하고 싶다 … `[초안]` |
```

- 사용자가 「맞아요」라고 하면 **그 자리에서 뗀다.** 확인된 값이다
- 남아 있는 `[초안]` 은 **추정이다.** 규약 §0-b 가 그 산출물을 `[추정]` 으로 낸다
- ③ 을 마칠 때 **몇 칸이 `[초안]` 인지 말한다.** 조용히 두지 않는다


## ③-c 회사 자료, 쓰시던 양식과 자료가 있으면 받는다

**③ 에서 ② 우리 회사 정보를 골랐을 때만** 묻는다. ① 샘플이나 ③ 스킬만이면 묻지 않는다.
여섯 묶음과 역할을 받은 뒤 **한 화면에서 한 번만** 묻고, 없다고 하면 바로 ③-d 로 간다.
받는 자료는 세 가지이고, 쓰는 법이 서로 다르다.

```
가지고 계신 회사 자료가 있으면 넣어 주세요. 없는 것은 건너뛰셔도 됩니다.

  ① 양식      쓰시던 보고서, 제안서, 기획서 → inputs/양식/
              결과물이 그 모양(절, 표, 순서)대로 나옵니다
  ② 회사 자료  회사 소개서, 브랜드 가이드, 반응이 좋았던 콘텐츠, 실적 자료, CS 정책 → inputs/
              결과물의 내용 근거가 됩니다
  ③ 디자인    로고 파일, 브랜드 색, 서체, 디자인 가이드 → brand/디자인/
              보고서와 제안서가 우리 색과 서체로 나옵니다

  .docx, .pptx, .xlsx, .pdf, 캡처 모두 됩니다. 없으시면 「없어요」 하시면 됩니다.
```

- **① 양식은 모양만** 쓴다. 아래 짝짓기로 스킬과 잇는다
- **② 회사 자료는 내용 근거**로 쓴다. 파일을 열어 무엇인지 보고, 프로필에 옮길 사실이 있으면 ③-b 처럼 보여 주고 고르게 한다.
  ⛔ 확인 안 된 내용은 사실로 확정하지 않는다 (`[초안]`). 과거 제안서의 고객 실명, 견적, 성과는 지금 업무에 옮기지 않는다
- **③ 디자인**은 `brand/디자인/` 에 둔다 (예: `가이드.md`, `tokens.css`, 로고 파일). 있으면 배포 디자인보다 먼저 쓴다 (`docs/공통규약.md §H` 「회사 디자인이 있으면 그것이 먼저다」).
  색과 서체를 글로만 주셨으면 `가이드.md` 한 장에 적어 보여 주고 ⏸ 로 받는다. ⛔ 패키지 `brand-templates/디자인시스템/tokens.css` 는 고치지 않는다
- 받은 자료마다 **기준일과 대상**(어느 브랜드, 제품, 기간)을 한 줄로 확인한다. 날짜를 모르면 모른다고 적는다 (규약 §0-b 「회사 자료는 두 가지로 쓴다」)
- 지금 다 받지 못해도 된다. 업무를 시킬 때 그 업무에 필요한 것만 다시 요청한다 (`skills/ai-marketer/참조/G1-파악.md` 의 요청 기준 표)

- `inputs/양식/` 이나 `brand/디자인/` 이 없으면 만들고 만들었다고 한 줄 알린다
- 파일을 **하나씩 열어** 절 제목과 표 머리를 본다. ⛔ 이름만 보고 짝짓지 않는다 (아래 「넘긴다」의 실측 2026-09-15 와 같은 이유다)
- 무슨 문서인지 보고 맞는 스킬과 짝을 짓는다

| 월간 성과 보고 | 스킬 067 · 월간 마케팅 성과 분석 |

  「이 양식 그대로 나만의 스킬 만들기(스킬 092)로 새 스킬을 만들 수 있습니다」를 한 줄 권한다
- 짝지은 파일 이름을 `profile.md §8` 의 「자주 쓰는 회사 양식」 칸에 적는다
- ⛔ 양식 파일은 고치지 않는다. 고객사 실명이나 단가가 들어 있으면 그렇다고 한 줄 알리고, 결과물에는 모양만 옮긴다

## ③-d 마무리, 작업 폴더 CLAUDE.md 와 우리 보완 초안

⛔ **우리 회사 정보를 넣었을 때만** 한다. `brand/profile.md` 가 `빈`(없음, 0바이트, 주석과 안내뿐, 템플릿 그대로)이거나 ① 샘플로 구축했으면
아래를 통째로 건너뛴다. CLAUDE.md 도 `skill-notes` 도 만들지 않는다.
책 실습은 빈 프로필과 샘플로 돌아야 원고와 같은 결과가 나오기 때문이다.

둘을 만들어 **한 화면에 보여 주고 ⏸ 한 번에** 받는다. 승인한 것만 저장한다.

```
마무리로 두 가지를 만들었습니다. 저장해도 될지 봐 주세요.

  ① 작업 폴더 CLAUDE.md ({n}줄)   우리 회사 요약입니다. 정본은 brand/profile.md 입니다
  ② 우리 보완 초안 {n}개
     스킬 067 · 월간 마케팅 성과 분석   월간보고_2026.pptx 양식대로, 첫 장은 대표 보고용
     스킬 045 · 광고 주간 성과 분석     매주 월요일 기준 지난 7일

  「전부 저장」, 「①만」, 「저장 안 함」 중에 말씀해 주세요.
⏸
```

### (a) 작업 폴더 CLAUDE.md

- 템플릿 `brand-templates/작업폴더-CLAUDE.md` 의 `{ }` 자리를 프로필 값으로 채운다. 맨 위 주석 줄은 옮기지 않는다. 30~40줄이다
- 빈 칸은 「비어 있음」으로 적는다. 지어내지 않는다. `[초안]` 이 붙은 값은 `[초안]` 을 그대로 둔다
- 작업 폴더 맨 위(`brand` 옆)에 `CLAUDE.md` 로 쓴다. ⛔ 이미 있으면 덮어쓰지 않는다. 지금 것을 보여 주고 맨 아래에 우리 회사 절을 붙일지 묻는다
- **프로필이 바뀌면 다시 쓴다.** 「브랜드 정보 넣을래」로 프로필을 고쳤으면 끝에서 (a) 만 다시 만들어 ⏸ 로 묻는다
- ⚠️ 클로드 코드는 작업 폴더의 CLAUDE.md 를 대화마다 읽는다. **코워크(데스크톱 앱)가 읽는지는 실측 전이다** `[추정]`.
  그래서 정본은 언제나 `brand/profile.md` 이고, 이 파일이 없어도 팀은 똑같이 돈다

### (b) 우리 보완 초안 `brand/skill-notes/{번호}.md`

**무엇을 만드나.** ③-c 에서 양식을 짝지은 스킬 전부와, 역할과 업종으로 자주 쓸 스킬 3~5개다.

| `profile.md §8` 내 역할 | 자주 쓸 스킬 |
|---|---|
| 팀장 | 067 월간 마케팅 성과 분석 · 045 광고 주간 성과 분석 · 095 마케팅 예산 설계 · 098 주간 업무 정리 |
| 실무 담당 | 아래 「넘긴다」의 업태별 첫 스킬 · 006 소비자 리뷰 분석 · 043 메타 광고 카피 작성 |
| 1인 대표 | 061 판매 데이터 분석 · 045 광고 주간 성과 분석 · 098 주간 업무 정리 |
| 대행사 담당 | 084 제안서 작성 · 067 월간 마케팅 성과 분석 · 045 광고 주간 성과 분석 |

업태(실물·B2B·구독·매장)에 맞지 않는 스킬은 뺀다. 채널을 안 하면 그 채널 스킬도 뺀다 (§5 채널 현황).

**무엇을 적나.** `brand-templates/skill-notes.md` 형식으로 **그 스킬에서만 바뀌는 것만** 적는다.

- 양식을 짝지은 스킬은 맨 위에 `형식: {확장자}` 와 `양식 원본: inputs/양식/{파일}` 두 줄을 쓴다
- 역할로 고른 스킬은 `docs/공통규약.md §0-a` 표에서 **그 스킬의 결과물에 해당하는 것**만 적는다 (예: 067 의 첫 장, 045 의 기간)
- ⛔ 역할과 보고 대상 자체는 적지 않는다. 그건 `profile.md §8` 에 있고 100개가 함께 읽는다 (규약 「다른 스킬에서도 쓰나」)
- `정한 날` 대신 `만든 날 {날짜} (구축 초안)` 을 쓴다. 실데이터로 처음 돌릴 때 양식에서 고칠 점을 묻는 자리가 남는다 (`docs/G3-분기절차.md §11`)

## 넘긴다 · 「마케팅 팀 업무 시작하자」

**구축은 3단계로 끝난다.** 여기서 스킬을 돌리지 않는다.
결과물을 만드는 것은 `ai-marketer` 의 일이고, 이 스킬은 **부를 말을 알려 주고 끝낸다.**

⛔ **여기서 스킬을 실행하지 않는다.** 권하고 넘긴다.

**별도의 조립 단계는 없다.** 프로필을 채운 순간 스킬 100개가 그 값을 읽고 돈다.
손익분기 ROAS, 업종 규제 사전, 기본 채널, 페르소나가 자동으로 들어간다.

⭐ **넘길 때 무엇부터 하면 좋은지 한 줄 권한다.** 사용자가 말한 것이 있으면 그것으로 권한다.
⛔ **`inputs` 의 파일을 권하는 이유로 들려면 파일 이름만 보지 않는다.** 열어서 머리 행이 그 스킬의 재료(리뷰면 본문·별점)인지 본 뒤에 적는다. 다르면 그 파일로 권하지 않고, 이름과 내용이 다르다고 한 줄 알린다 (실측 2026-09-15 코워크 · 「자사몰 리뷰 데이터.xlsx」는 쿠팡 광고 보고서였다. 그런데도 「바로 돌릴 수 있습니다」라고 권했다).

**없으면 업태에 맞는 것으로 권한다.** ⛔ 업태 불문 `001` 로 보내지 않는다.
B2B 마케터에게 키워드 리서치를 권하면 「내 일이 아니네」로 읽힌다.

| 업태 | 먼저 권할 것 | 왜 |
|---|---|---|
| **실물·D2C** | `001 키워드 리서치` | 입력이 가장 적고 결과가 눈에 보인다 |
| **B2B·솔루션** | `002 경쟁사 분석` | 리드가 없어도 오늘 나온다 |
| **구독·앱** | `006 소비자 리뷰 분석` (데이터 없으면 `012 제품 차별점 정리`) | 유지가 핵심이라 고객 말이 먼저다 |
| **매장 브랜드** | `031 인스타 피드 기획` | 매장 유입이 소셜에서 온다 |

⚠️ 애매하면 **묻지 말고 `001`** 을 권한다. 고르게 하지 말고 하나를 대 준다.

## 주기 점검으로 쓸 때

이미 `brand/profile.md` 가 차 있으면 ③을 건너뛰고 ①만 실행한 뒤 아래를 확인한다.

**먼저 스크립트를 실행한다. 사람이 손으로 집계하면 빠뜨린다.**

```
node ${CLAUDE_PLUGIN_ROOT}/scripts/ledger-stats.mjs
```

> 📒 **세션이 열릴 때 이미 한 번 본다.** SessionStart 훅이 7일에 한 번 조용히 확인하고,
> 롤오버가 필요하거나 신호가 있을 때만 알린다 (`docs/원장-운영.md` §3).
> 사용자가 그 알림을 보고 왔으면 **여기서 전체를 다시 돌려** 처방까지 낸다.

한 번에 부피·스킬별 집계·진단 신호가 나온다. 아래 표는 그 출력을 읽는 법이다.

| 기계가 내는 신호 | 무슨 뜻인가 | 무엇을 묻나 |
|---|---|---|
| 🔕 무호출 | 90일째 안 돌았다 | 상시에서 내릴지 묻는다 |
| 🔁 재작업 | 평균 보완 2회 이상. **한 번에 안 나오는 스킬**이다 | 그 스킬의 `inputs`·브리핑이 부실하다 |
| ⛔ 차단 | 차단률 30% 이상 | 표현 규칙을 프롬프트에 미리 넣는다 |
| 📄 샘플 | 샘플률 80% 이상 | 실데이터가 안 붙어 있다. 프로필·MCP 확인 |
| 💾 저장실패 | 착지가 실패했다 | 회수 가능한지 본다 (아래 저장 누락 점검) |
| 🗣 라우팅 | **같은 말이 다른 스킬로 나뉘었다** (⛔ **체인은 뺀다.** 요청 한 줄이 스킬 4개로 가는 건 설계다) | 부를 말이 겹친다. 트리거를 나눈다 |
| 📁 착지실패 | 원장엔 있는데 **파일이 없다** | 「저장 안 된 거 있어?」로 회수한다 |
| 🚪 게이트기록 | 게이트는 탔는데 **`gate.md` 가 없다** | 결과 근거가 안 남았다 |
| 📊 형식위반 | **`writes_to` 와 다른 확장자**로 냈다 | 체인이 그 경로를 못 찾는다 |
| 🟡 롤오버 필요 | 800행 초과거나 연도가 바뀌었다 | 아래 「원장 롤오버」로 간다 |

**위 열은 전부 「이상」이다. 잘 쓰는 사람에겐 평생 표시되지 않는다.** 그것만 있으면
시스템이 먼저 말을 걸 일이 없다. 아래 셋은 이상이 아니라 **때가 된 것**이라
**훅이 먼저 꺼낸다** (다른 신호는 물어볼 때만 답한다).

| 재방문 신호 | 무슨 뜻인가 | 무엇을 묻나 |
|---|---|---|
| ⏰ 주기도래 | **평소 간격의 1.5배**를 넘겼다 (주기는 선언이 아니라 원장에서 계산한다) | 「이번에도 돌릴까요?」 ⏸ |
| 📌 미완 | 중단·차단된 뒤 **같은 스킬로 완료된 적이 없다** | 막힌 재료가 왔는지 · 고쳐서 다시 낼지 |
| 📎 플레이북 | 완료가 5건을 넘었지만 `my-playbook` 이 **빈 템플릿 그대로** | 091 진단을 돌릴지 묻는다. 097·098 이 이걸 읽는다 |

⛔ **꺼내되 가로채지 않는다.** 사용자가 다른 일을 말했으면 그 일을 먼저 하고
끝에 한 줄로 붙인다. 그리고 **멋대로 실행하지 않는다.** 「돌릴까요?」로 묻는다.

**기억도 함께 확인한다** (`docs/기억-운영.md` §7).

```
node ${CLAUDE_PLUGIN_ROOT}/scripts/memory.mjs doctor
```

| 신호 | 무슨 뜻인가 | 무엇을 묻나 |
|---|---|---|
| `인용없음` | 손으로 쓴 줄이다. 출처를 모른다 | 어느 실행에서 나왔는지 찾거나 지운다 |
| `끊긴링크` | 상대 페이지가 아직 없다 | **급하지 않다.** 그 주제를 다음에 남길 때 채워진다 |
| `비대` · `낡음` | 40줄 초과 · 180일 갱신 없음 | 묶어 줄일지 · 아직 참인지 |
| `고아` | 90일째 아무도 안 부르고 아는 것 1줄 이하 | **지울까요?** ⏸ (⛔ 점검이 지우지 않는다) |

⛔ **기억이 0쪽이어도 이상이 아니다.** 업무를 몇 건 마쳐야 생긴다.
다만 **완료가 10건을 넘었고 기억이 0쪽이면** G5 의 기억 단계가 안 돌고 있는 것이다. 그것만 짚는다.

기계가 집계하지 못하는 것은 손으로 본다.

| 확인하는 것 | 어디서 | 신호 |
|---|---|---|
| 승인이 막혀 있나 | ⏸ 에서 멈춘 채 끝난 건 | 3건 이상이면 브리핑이 무겁다 |
| 게이트가 도나 | `게이트` 열 | 발행물의 게이트 칸이 비어 있으면 건너뛴 것 |
| 결과가 파일로 남았나 | `outputs` | 원장엔 있고 파일이 없으면 **착지 실패** |

⛔ **스크립트가 없거나 노드가 없으면** 그 사실을 말하고 손으로 확인한다. **조용히 건너뛰지 않는다.**
확인하지 않고 「이상 없음」이라고 하면 점검을 한 것이 아니다.

고칠 지점은 **3개 이내**로 돌려준다. 10개를 적으면 하나도 안 고쳐진다.

### 저장 누락 점검 · 「저장 안 된 거 있어?」

**가장 조용히 새는 자리다.** 화면에 결과가 예쁘게 나오면 파일이 없는 줄 모른다.
그래서 **묻지 않아도 주기 점검에서 이것부터 확인한다.**

1. `logs/build-log.md` 의 **최근 8주** 행에서 **일시, 스킬 ID, 상태, 산출물 경로**를 읽는다
   (원장을 통째로 읽지 않는다. 날짜로 grep 하거나 tail 로 끊는다. `docs/공통규약.md §A`.
   그 기간의 행이 롤오버됐으면 `logs/archive/` 에서도 해당 기간만 읽는다. 「최근 8주만 봤다」고 말한다)
2. **완료 행에 기록된 실제 산출물 파일을 하나씩 확인한다.** 작업 폴더를 기준으로 경로를 읽고,
   날짜와 스킬 번호로 새 경로를 짐작하지 않는다. **폴더나 `plan.json`, `run.json` 만 남은 것은 산출물 저장이 아니다.**
   여러 파일을 냈으면 실행 기록(`run.json`)의 산출물 목록도 읽어 각 파일을 확인한다.
3. 없는 파일의 **건수와 실제 경로**를 낸다. 경로가 비었으면 「경로 기록 누락」으로 알린다.
   `저장실패` 행은 따로 알리고, `중단`, `차단됨` 행을 완료 산출물이 없다는 이유로 저장 누락에 넣지 않는다.

```
확인할 산출물 12개 중 파일 10개가 있습니다. 2개가 없습니다.

  2026-08-20  광고 주간 리포트(045)
    outputs/2026-08-20/045-weekly-ads-report/045-weekly-ads-report.html
  2026-08-18  상세페이지 카피(051)          ⚠️ 고객이 볼 글인데 규제 검사 기록도 없습니다
    outputs/2026-08-18/051-detail-page-24/051-detail-page-24.docx

  대화 기록이 남아 있으면 「방금 거 저장해줘」로 옮길 수 있고,
  아니면 다시 돌려야 합니다. 다시 돌릴까요?
```

**저장 경로는 사용자 설정과 실행 종류를 함께 본다.** `brand/profile.md §7` 의 저장 설정과
체인의 프로젝트 폴더 규칙을 먼저 확인한다 (`docs/공통규약.md §H`). 날짜별 기본 경로와
다르다는 이유만으로 저장 실패라고 하거나 이동을 제안하지 않는다.

```
outputs/2026-08-22/045-weekly-ads-report/…   ← 단일 스킬의 기본 경로
outputs/2026-08-신제품런칭/01-…/…            ← 체인의 프로젝트 경로
```

파일은 있지만 **사용자가 정한 경로와 실행 계획에 모두 어긋난 경우에만** 경로 불일치로 따로 알리고,
옮기고 원장을 고칠지 묻는다. 파일이 없는 저장 누락과 별도로 집계한다.

⛔ **0건이면 「0건」이라고 말한다.** 조용히 넘어가면 점검을 한 건지 알 수 없다.

### 원장 롤오버 · 「원장이 두꺼워졌습니다」

원장은 지우지 않고 쌓는다. 그래서 언젠가 반드시 커진다.
문제는 디스크가 아니라 **매 작업 앞에서 읽는 비용**이다. 원장이 두꺼우면 일이 느려진다.

**여기가 원장 부피를 집계하는 유일한 자리다.** 그리고 **집계는 기계가 한다.** 위 `ledger-stats.mjs` 가 이미 결정해 준다.

```
✅ 부피 정상        아무 말도 하지 않는다
🟡 롤오버 필요      ⏸ 로 제안한다 (800행 초과 또는 연도 변경)
```

```
실행 기록이 1,240줄까지 늘었습니다 (2026-01-04 ~ 2026-12-28).
작업할 때마다 이걸 다 읽으면 느려집니다.

  2026년 기록 1,240건  →  logs/archive/build-log-2026.md
  logs/build-log.md  →  헤더만 남기고 2027년부터 새로 쌓습니다
  logs/build-log-summary.md  →  스킬별 최종 실행일·누적 건수로 갱신 (90일 점검이 이걸 봅니다)

  옮기는 것이지 지우는 것이 아닙니다. 아카이브는 그대로 남습니다.

⏸ 옮길까요?
```

승인받으면 순서대로 한다.

1. `logs/archive/` 가 없으면 만든다
2. **데이터 행만** 잘라 `logs/archive/build-log-{연도}.md` 로 옮긴다. 헤더·스키마는 원장과 **같게** 복사한다
3. `logs/build-log.md` 는 머리말과 표 헤더만 남긴다
4. 요약 원장을 갱신한다. **손으로 집계하지 않는다.** 기계가 아카이브까지 합쳐 다시 집계한다

   ```
   node ${CLAUDE_PLUGIN_ROOT}/scripts/ledger-stats.mjs --summary
   ```
5. 옮긴 행 수와 아카이브 경로를 말한다. **몇 건을 어디로 옮겼는지 말하지 않으면 지운 것과 구별되지 않는다**

⛔ **묻지 않고 옮기지 않는다.** ⛔ **행을 지우지 않는다.** ⛔ **아카이브의 열 순서를 바꾸지 않는다.**

> 롤오버 뒤에도 지난 기록은 찾을 수 있다. 「작년에 뭐 했지」는 `logs/archive/` 를 grep 하면 된다.
> 정본 규칙은 `docs/원장-운영.md` §2.
