# 마케팅 팀 구축하기 · 쓸 수 있게 만든다

> ⚠️ **경로 규칙은 `docs/공통규약.md §0` 이다.**
> `100-skills/` · `docs/` · `sample-data/` · `brand-templates/` 는 **패키지 안**
> (플러그인이면 `${CLAUDE_PLUGIN_ROOT}` 아래, 폴더로 열었으면 현재 폴더).
> `brand` · `outputs` · `logs` · `inputs` 는 **언제나 현재 작업 폴더**다.

**3단계고, 멈추는 곳은 두 번뿐이다** (우리 회사 정보를 넣었으면 ③-d 마무리에서 한 번 더). 설명하지 않는다. 검사하고, 받고, 넘긴다.
「이게 뭔가」, 「무엇을 시킬 수 있나」는 `marketing-team-tasks` 가 맡는다. 여기서 다시 설명하지 않는다.

## ⓪ 여는 화면 · 무엇을 할지 먼저 보인다

**첫 화면에서 무언가를 요구하지 않는다.** 무엇을 할지 3가지로 보이고 **건너뛸 수 있다고 먼저 말한다.**
사용자가 첫 화면에서 요구를 받으면 거기서 닫는다.

⭐ **①을 먼저 확인하고, 그 값을 넣어 이 화면을 낸다.** 확인하기 전에 내지 않는다.

```
마케팅 팀을 구축하겠습니다. 3단계면 끝납니다.

  ① 설치 점검   진입 스킬 {n} · 판정·세팅 담당 {n} · 업무 스킬 {n}
  ② 작업 공간   brand · inputs · outputs · logs
  ③ 회사 정보   제품 · 고객 · 채널 · 숫자 · 경쟁 · 금기

③까지 채우면 스킬 100개가 우리 회사 기준으로 돌아갑니다.
③은 건너뛰어도 됩니다. 샘플로 돌리거나, 스킬만 단독으로 쓰실 수 있습니다.

다 되면 「마케팅 팀 업무 시작하자」 하고 불러 주세요.
```

⛔ **여기서 멈추고 묻지 않는다.** 보여 주고 바로 ②로 간다.
멈추는 곳은 **③의 세 가지 선택**과 **③-b** 뿐이다. 우리 회사 정보를 넣었을 때만 **③-d** 에서 한 번 더 멈춘다.

⛔ **①이 확인하는 7가지 가운데 3가지만 낸다.** 나머지 4가지(폴더 구조·머리말·명부·설정)는
**어긋났을 때만** 한 줄로 말한다. 다 맞았으면 7줄을 늘어놓지 않는다.

⛔ **숫자를 지어내지 않는다.** 어긋나면 어긋난 값을 그대로 넣는다 (①).

## ① 제대로 깔렸나 · 하나씩 확인한다

**있다고 말하지 않고 확인한다.**

⛔ **터미널부터 찾지 않는다. 파일을 직접 읽어 확인한다.**
**데스크톱 앱에는 터미널이 없다.** 승인을 요구하며 멈추면 사용자는 첫 화면에서 막힌다.
`ls` · `find` · `node` 없이 **파일을 열어 보는 것만으로 아래 7개를 전부 확인할 수 있다.**
**② 작업 공간과 `CLAUDE.md` 를 볼 때도 같다.** 없는 파일을 `ls` 로 보면 명령이 「실패」로 뜨고,
사용자는 설치가 깨진 줄 안다 (실측 2026-10-29 코워크 · 아직 없는 게 정상인 `ls CLAUDE.md` 가 Exit code 2).
셸을 꼭 써야 하면 없는 것이 실패로 끝나지 않게 쓴다 (`[ -e CLAUDE.md ] && echo 있음 || echo 없음`).

> 클로드 코드에서 **더 꼼꼼히 보고 싶을 때만** `node "${CLAUDE_PLUGIN_ROOT}/scripts/verify.mjs"` 를
> 제안한다. **먼저 확인해 결과를 보여준 뒤에** 권한다. 승인을 기다리며 멈추지 않는다.

| # | 확인하는 것 | 통과 |
|---|---|---|
| 1 | `agents/` 의 `.md` 파일 수 | **3** (결론 둘 · 세팅 하나) |
| 2 | `agents/` 에 하위 폴더가 있나 | **없어야** 한다. 있으면 그 담당은 스캔되지 않는다 |
| 3 | `agents/` 의 모든 `.md` 에 frontmatter | 전부. 없으면 **유령 담당** |
| 4 | `skills/` 폴더마다 `SKILL.md` | **3개**: `marketing-team-setup` · `ai-marketer` · `marketing-team-tasks` |
| 5 | `100-skills/` 의 `SKILL.md` | **100** |
| 6 | `100-skills/ROUTING.md` 가 열리나 | 열려야 한다 |
| 7 | `.claude-plugin/plugin.json` 의 `repository` | **문자열**. 객체면 플러그인 전체가 로드 실패 |

**숫자가 어긋나면 그 숫자를 그대로 말한다.** 「100개가 있습니다」라고 지어내지 않는다.

> ⚠️ **스킬 100개는 등록되지 않는다. 의도된 설계다.** 전부 등록하면 매 세션 약 1만 5천 토큰이 항상 실린다.
> 명부 한 장만 보고 본문은 매칭된 순간에 연다. 그래서 `/` 목록에 **셋만** 보이는 것이 정상이다.

### 바깥 도구 · 7개 항목에 넣지 않는다

브라우저 도구(`playwright`)와 문서 스킬(`.pptx`·`.docx`·`.xlsx`·`.pdf`)은 **플러그인 밖에서 붙는다.**
「여덟 항목」이라고 말하지 않는다. **안 붙어도 구축을 멈추지 않는다.**
붙었는지 볼 때와 없을 때 낼 문안은 [참조/바깥-도구.md](참조/바깥-도구.md) 를 통째로 읽고 따른다 (「문서 스킬」 절 포함).

### 고칠 때 · 업데이트와 초기화

「업데이트가 안 돼」·「옛날 버전이 그대로야」·「처음부터 다시 하고 싶어」·「초기화」면
[참조/고칠-때.md](참조/고칠-때.md) 를 통째로 읽고 그 순서대로 한다.
⛔ **마켓플레이스를 먼저 지우지 않는다.** ⛔ 작업 폴더(`brand` · `outputs` · `logs`)는 지우지 않는다.

## ② 작업 공간을 만든다

**팀은 패키지 안에 살고, 산출물은 내가 일하는 공간에 떨어진다.** 둘은 다른 곳이다.

| | 작업 공간 |
|---|---|
| 데스크톱 앱 | 접근을 허용한 폴더(설정의 「Trusted folders」) · 안 골랐으면 지금 이 작업이 파일을 만드는 곳 |
| 클로드 코드 | 지금 열어 둔 폴더 |
| 폴더로 클론했으면 | 그 저장소 폴더 |

거기에 넷이 없으면 **묻고 만든다** (⏸).

```
brand     내 브랜드 정보 · 우리 보완
outputs   산출물이 떨어지는 곳
logs      실적 원장
inputs    내 파일을 넣어 두는 곳
```

### 어디에 만드나 · 여기 바로냐, `marketing-team/` 안이냐

**지금 폴더를 보고 기본값을 정한 뒤 ⏸ 로 묻는다.** 고정하지 않는다.
데스크탑에 넷을 흩뿌리면 지저분하고, 전용 폴더에 한 겹을 더하면 군더더기다.

| 지금 폴더가 | 기본값 | 왜 |
|---|---|---|
| 비어 있거나 **이 일 전용**으로 보인다 | **여기 바로** | 한 겹이 늘면 경로만 길어진다 |
| 데스크탑·홈·**다른 것이 이미 많은 곳** | **`marketing-team/` 안** | 넷이 흩어지면 나중에 못 찾는다 |

```
여기에 작업 공간을 만듭니다. 어디에 둘까요?

  ① marketing-team/ 폴더를 만들고 그 안에      ← 데스크탑이라 이걸 권합니다
       marketing-team/brand · outputs · logs · inputs
  ② 여기 바로
       brand · outputs · logs · inputs
⏸
```

⚠️ **①을 골랐으면 반드시 한 줄 알린다.** 작업 폴더는 **넷이 있는 곳**이다.

```
✅ ~/Desktop/marketing-team/ 에 만들었습니다.
   앞으로는 데스크탑이 아니라 **이 폴더를 열고** 일해 주세요.
   여기서 일하지 않으면 산출물이 다른 곳에 쌓입니다.
```

이 말을 빠뜨리면 사용자가 계속 상위 폴더를 열고, **작업 공간을 못 찾아 또 만든다.**

### 무엇을 어디로 복사하나 · 이 표대로만 한다

⛔ **「빈 템플릿을 복사한다」로 끝내지 않는다.** 무엇을 어디에 놓을지 안 적으면
실행할 때마다 달라진다. **실측 (2026-08-25), `profile.md` 가 빠지고
`build-log-summary.md` 가 미리 생겼다.** 가장 중요한 것이 빠진 채 완주했다.

| 템플릿 (`brand-templates/`) | → 어디 | 언제 |
|---|---|---|
| `profile.md` | `brand/profile.md` | **항상**. ⚠️ 빠지면 사용자가 자기 정보를 넣을 양식이 없다 |
| `tone.md` | `brand/tone.md` | **항상** |
| `my-playbook.md` | `brand/my-playbook.md` | **항상** |
| `build-log.md` | `logs/build-log.md` | 없을 때만 (있으면 헤더만 본다 · 아래 「원장을 만든다」) |
| `memory/INDEX.md` | `brand/memory/INDEX.md` | 없을 때만. **빈 색인이다.** 있으면 그대로 둔다 |
| `build-log-summary.md` | - | ⛔ **손으로 만들지 않는다.** 세션 훅이 주마다 다시 만든다 |
| `skill-notes.md` | - | ⛔ **빈 것을 미리 만들지 않는다.** ③-d 초안이나 「계속 이렇게」를 사람이 승인할 때 생긴다 |
| `작업폴더-CLAUDE.md` | 작업 폴더 맨 위 `CLAUDE.md` | **③-d 에서만.** 우리 회사 정보를 넣었을 때만 만든다. 샘플이면 안 만든다 · 있으면 덮어쓰지 않는다 |
| `compliance-custom.md` | - | ⛔ **미리 만들지 않는다.** **AI 규제세팅**이 만든다 (사전에 없는 업종일 때 ⏸) |
| `업무-스킬-분해표.md` | - | ⛔ 참고 문서다. 복사하지 않는다 |

**셋(`profile`·`tone`·`my-playbook`)을 복사했으면 셋이라고 말한다.**

⚠️ **`brand/memory/` 는 폴더와 빈 색인만 만든다. 주제 폴더는 미리 만들지 않는다.**
빈 폴더 6개를 보면 채워야 할 것 같아진다. 첫 기억이 생길 때 `memory.mjs capture` 가 만든다
(정본 `docs/기억-운영.md`).
하나라도 못 했으면 어느 것을 왜 못 했는지 적는다. 조용히 넘어가지 않는다.

⚠️ **이미 있으면 덮어쓰지 않는다.** 사용자가 채운 것이 사라진다.

⚠️ **패키지 안에 쓰지 않는다.** 거기 쓰면 플러그인을 업데이트할 때 산출물이 통째로 날아간다.

### 원장을 만든다

```
없으면        brand-templates/build-log.md 를 복사한다
있으면        헤더를 본다
```

**헤더가 정본과 다르면**: 구형은 `| 일시 | 방법론 | 담당 | 산출물 | 게이트 | 보완 |` 6열이다.
⛔ **말없이 고치지 않는다.** 지난 기록이 사라진다. **보여주고 묻는다.**

```
실행 기록이 옛 형식입니다 (6열). 지금은 8열이라 저장 누락 점검이 안 돕니다.

  지금        일시 | 방법론 | 담당 | 산출물 | 게이트 | 보완
  새 형식     일시 | 스킬 ID | 요청 | 데이터 모드 | 산출물 경로 | 게이트 | 보완 횟수 | 상태

  옮기면 logs/build-log-{오늘}.bak.md 로 백업하고, 기존 {N}행은 아는 값만 채웁니다.
  (요청·데이터 모드·상태는 빈칸으로 두고 「구형 이관」이라 표시합니다)

⏸ 옮길까요? 그냥 두면 새 행부터 8열로 쌓입니다. 점검은 새 행만 봅니다.
```

열 순서는 정본 그대로 (`docs/공통규약.md §H`).

## ③ 우리 회사 정보 · 6묶음 · 건너뛸 수 있다

⏸ **먼저 묻는다. 이 질문은 여기서 한 번뿐이다.**

⛔ **아래 문안을 그대로 낸다. 줄이거나 바꾸지 않는다.** 실측 2026-08-31, 모델이 화면을
아끼려 선택지 문안을 임의로 요약했다. 이 문안은 사용자가 낱말 단위로 확정한 정본이다.
한 글자도 빼지 않는다. [틀]·스킬 유형 설명은 여기서 하지 않는다. 산출물이 스스로 설명한다.

```
어떤 회사 정보로 실습할까요?

  ① 준비된 샘플 정보로 실습한다 (권장)
     가상의 A브랜드(화장품) 자료가 이미 들어 있습니다. 바로 시작할 수 있습니다.
     결과 첫 줄에 [샘플] 이 붙습니다. 숫자와 고객이 우리 것은 아닙니다.

  ② 우리 회사 정보로 실습한다
     여섯 가지를 여쭙고 3분이면 끝납니다. 한 번 답하면 다시 묻지 않습니다.
     스킬 100개가 우리 것 15~30개로 줄고, 결과 첫 줄이 [실데이터] 로 바뀝니다.

  ③ 회사 정보 없이 스킬만 사용한다
     필요한 재료를 그때그때 확인합니다.
     핵심 메시지 한 줄이면 ②와 같은 결과가 나옵니다.

  ⭐ 업종 한 줄만 알려주셔도 규제 검사가 우리 업종 기준으로 달라집니다. 「우리는 반려동물 사료야」

  ① 을 고르셔도 나중에 「브랜드 정보 넣을래」 하시면 그때 채웁니다.
```

**①을 골라도 전 과정이 완주된다.** 나중에 「브랜드 정보 넣을래」 하면 그때 채운다.

### ⭐ 여섯을 묻되 · **답하는 방식은 강요하지 않는다**

⛔ **답을 칸에 맞춰 쓰라고 강요하지 않는다.** 묻는 것은 여섯이지만
**어떻게 답하든 받는다.** 한 줄이든, 줄글 한 덩이든, 상세페이지를 통째로 붙여넣든.

> 여섯 묶음 자체는 그대로 쓴다. **사용자는 마케터고**(규약 §0-a) 이 여섯은
> 마케터의 언어다. 「채널 비중」, 「경쟁사 고른 기준」, 「금기 표현」은 설명이 필요 없다.
> ⛔ 다만 **④ 숫자만 업태를 탄다.** 마진율은 물건 파는 사람의 말이라
> 로컬·B2B·구독이면 **「한 명 데려오는 데 얼마까지」**로 묻는다 (③-a).

**여섯을 한 화면에 다 보여준다.** 무엇을 물을지 미리 아는 편이 답하기 쉽다.
다만 **순서대로 답하라고 하지 않는다.**

```
우리 회사 얘기를 들려주세요. 여섯 가지를 여쭤보긴 할 텐데,
편하게 한 번에 말씀하셔도 되고 하나씩 답하셔도 됩니다.

  ① 브랜드·업종·주력   ② 타깃과 사는/떠나는 이유   ③ 굴러가는 채널과 비중
  ④ 숫자              ⑤ 경쟁사와 고른 기준        ⑥ 안 쓰는 표현

  ⭐ 더 빠른 길 · 상세페이지·소개글·리뷰를 그냥 붙여넣으셔도 됩니다.

  하나 더 여쭙니다. 만든 결과물은 누가 보시나요?
  「팀장님께 매주 월요일에 올려요」, 「대표라 혼자 봐요」, 「고객사에 매달 보내요」처럼 말씀해 주세요.
```

**마지막 질문이 역할이다.** 답에서 내 역할, 팀 규모, 보고받는 사람, 보고 주기를 읽어 `profile.md §8 우리 팀과 내 역할` 에 적는다.
⛔ 역할은 사실이라 대신 쓰지 않는다 (③-b 대상이 아니다). 답이 없으면 §8 을 비워 두고, 그러면 지금처럼 돈다.

- **줄글로 오면 그대로 §0 에 적고**, 거기서 읽어 §1~§6 을 채운다
- **하나씩 답하시면** ③-a 의 예시 한 줄을 붙여 순서대로 묻는다
- 어느 쪽이든 **이미 답이 나온 것은 다시 묻지 않는다**

**그중 셋은 반드시 확인하고 넘어간다.** 기계가 계산·매칭에 쓰는 값이다.

| 확인할 것 | 왜 | 이렇게 묻는다 |
|---|---|---|
| **업종** (§1) | **규제 사전 스위치**. 틀리면 다른 법이 걸린다 | 「화장품 맞을까요?」 한 단어 |
| **숫자 하나** (§4) | **광고 결론 기준선**. 계산에 들어간다 | 실물이면 마진율, 아니면 **「한 명 데려오는 데 얼마까지?」** |
| **금기 표현** (§6) | 게이트가 **문자로 잡는다** | 「쓰시면 안 되는 말 그대로 알려주세요」 |

- 이미 답이 나왔으면 **다시 묻지 않는다.** 읽어서 채우고 **맞는지만 보여준다**
- 나머지(고객·포지셔닝·채널·경쟁)는 **말한 그대로 §2·§3·§5 에 정리해 넣는다.**
  사용자가 표 모양으로 맞춰 쓸 필요는 없다
- **모른다고 하면 비우지 않는다. 대신 써 준다** (③-b · [참조/회사정보-쓰는-법.md](참조/회사정보-쓰는-법.md))
- 얼마나 자세히 쓰면 되는지는 ③-a 가 기준이다



**아래 표는 「순서대로 물을 목록」이 아니라 「결국 채워질 자리」다.**
줄글에서 읽어 채우고, 안 채워진 것만 물으며, 그때도 ③-a 의 예시를 붙인다.

| # | 묶음 | 꼭 필요한 것 | 비면 |
|---|---|---|---|
| 1 | **기본** | 브랜드명 · **업종** · 핵심 제품 3 | 업종이 없으면 규제 사전이 공통(표시광고법)만 걸린다 |
| 2 | **고객** | 핵심 타깃 · 사는 이유 3 · 떠나는 이유 3 | 페르소나·카피가 일반론이 된다 |
| 3 | **채널** | 실제로 굴러가는 채널만 | 없는 채널을 적으면 안 도는 계획이 나온다 |
| 4 | **숫자** | 마진율 → **손익분기 ROAS(=1÷마진율)** · 월 예산 | 광고 결론이 전부 `[추정]` |
| 5 | **경쟁** | 경쟁사 3곳과 고른 기준 | 비교표의 기준이 흔들린다 |
| 6 | **금기** | 절대 쓰지 않는 표현 | 게이트가 공통 기준만 본다 |
| + | **우리 팀** (§8) | 내 역할 · 보고받는 사람 · 보고 주기 | 실무 담당 기준으로 나온다 (지금과 같다) |

> ⚠️ **4번을 특히 챙긴다.** 손익분기 ROAS 는 흑자·적자를 나누는 기준선이다.
> 없으면 ROAS 2.0이 좋은 건지 나쁜 건지 아무도 모른다.

**어느 정도로 받아야 하는지는 칸마다 다르다.** ③-a 가 그 기준이다.
②만 한 뼘 더 받고 나머지는 한 줄이면 된다.

**업종을 받으면 규제가 갈아 끼워진다**: 화장품법·건강기능식품법·식품표시광고법·약사법·금소법.

### ⛔ 사전에 **없는 업종**이면 · 여기서 끝내지 않는다

정본 사전이 덮는 것은 **다섯**뿐이다(화장품·건기식·일반식품·의약품/의료기기·금융).
반려동물 사료·주류·유아용품·렌탈·핀테크·리빙은 **공통(표시광고법)으로만** 걸린다.
그런데 이 카테고리들의 진짜 위험은 공통으로 **안 잡힌다**.
사료의 「면역력 개선」(동물용의약품 오인), 주류의 미성년 소구, 렌탈의 「월 OO원」 총액 미표시가 그렇다.

**그때는 `staff-compliance-setup`(AI 규제세팅) 을 부른다.**

```
「반려동물 사료」는 규제 사전에 따로 없어서 지금은 공통(표시광고법)만 걸립니다.
그런데 이 카테고리는 **동물용의약품 오인**을 조심해야 해서 공통만으로는 부족합니다.

  조심할 말 목록을 만들어 드릴까요? (2분 · 다음부터 발행할 때마다 함께 검사합니다)
```

- ⏸ **승인 후에만** `brand/compliance-custom.md` 로 남는다
- **초안이고 법률 자문이 아니라는 것**을 반드시 함께 말한다
- 사전에 **있는** 업종이면 부르지 않는다. 그 섹션이 이미 정본이다
- 우리만의 금기는 어느 경우든 같은 파일(`brand/compliance-custom.md`)에 쌓인다

받은 값은 `brand/profile.md` (톤은 `brand/tone.md`) 로 쓴다.
**이미 있으면 처음부터 다시 받지 않는다.** 지금 값을 표로 보여주고 **고칠 곳만** 손댄다.

## ③-a · ③-b 어느 정도로 쓰나 · 대신 써 드립니다

**③에서 값을 받을 때마다** [참조/회사정보-쓰는-법.md](참조/회사정보-쓰는-법.md) 를 통째로 읽고 따른다.

- **③-a** 칸마다 어느 정도로 받나 · 업태별로 묻는 말 · 묻는 자리에서 예시를 함께 낸다
  - 자가 점검 한 줄 · 경쟁사가 그대로 써도 말이 되면 다시 받는다
- **③-b** 모른다고 하면 비우지 않고 초안을 고르게 한다
  - ⛔ 말은 대신 쓴다. **사실(숫자 · 경쟁사 실명 · 채널)은 대신 만들지 않는다**
  - 대신 쓴 값에는 `[초안]` 을 붙이고, ③을 마칠 때 몇 칸이 `[초안]` 인지 말한다

## ③-c 회사 자료, 쓰시던 양식과 자료가 있으면 받는다

**③ 에서 ② 우리 회사 정보를 골랐을 때만** 묻는다. ① 샘플이나 ③ 스킬만이면 묻지 않는다.
여섯 묶음과 역할을 받은 뒤 **한 화면에서 한 번만** 묻고, 없다고 하면 바로 ③-d 로 간다.
받는 자료는 세 가지이고, 쓰는 법이 서로 다르다.

```
가지고 계신 회사 자료가 있으면 넣어 주세요. 없는 것은 건너뛰셔도 됩니다.

  ① 양식      쓰시던 보고서, 제안서, 기획서 → inputs/양식/
              결과물이 그 모양(절, 표, 순서)대로 나옵니다
  ② 회사 자료  회사 소개서, 브랜드 가이드, 반응이 좋았던 콘텐츠, 실적 자료, CS 정책 → inputs/
              결과물의 내용 근거가 됩니다
  ③ 디자인    로고 파일, 브랜드 색, 서체, 디자인 가이드 → brand/디자인/
              보고서와 제안서가 우리 색과 서체로 나옵니다

  .docx, .pptx, .xlsx, .pdf, 캡처 모두 됩니다. 없으시면 「없어요」 하시면 됩니다.
```

- **① 양식은 모양만** 쓴다. 아래 짝짓기로 스킬과 잇는다
- **② 회사 자료는 내용 근거**로 쓴다. 파일을 열어 무엇인지 보고, 프로필에 옮길 사실이 있으면 ③-b 처럼 보여 주고 고르게 한다.
  ⛔ 확인 안 된 내용은 사실로 확정하지 않는다 (`[초안]`). 과거 제안서의 고객 실명, 견적, 성과는 지금 업무에 옮기지 않는다
- **③ 디자인**은 `brand/디자인/` 에 둔다 (예: `가이드.md`, `tokens.css`, 로고 파일). 있으면 배포 디자인보다 먼저 쓴다 (`docs/공통규약.md §H` 「회사 디자인이 있으면 그것이 먼저다」).
  색과 서체를 글로만 주셨으면 `가이드.md` 한 장에 적어 보여 주고 ⏸ 로 받는다. ⛔ 패키지 `brand-templates/디자인시스템/tokens.css` 는 고치지 않는다
- 받은 자료마다 **기준일과 대상**(어느 브랜드, 제품, 기간)을 한 줄로 확인한다. 날짜를 모르면 모른다고 적는다 (규약 §0-b 「회사 자료는 두 가지로 쓴다」)
- 지금 다 받지 못해도 된다. 업무를 시킬 때 그 업무에 필요한 것만 다시 요청한다 (`skills/ai-marketer/참조/G1-파악.md` 의 요청 기준 표)

- `inputs/양식/` 이나 `brand/디자인/` 이 없으면 만들고 만들었다고 한 줄 알린다
- 파일을 **하나씩 열어** 절 제목과 표 머리를 본다. ⛔ 이름만 보고 짝짓지 않는다 (아래 「넘긴다」의 실측 2026-09-15 와 같은 이유다)
- 무슨 문서인지 보고 맞는 스킬과 짝을 짓는다

| 양식 | 짝지을 스킬 |
|---|---|
| 월간 성과 보고 | 스킬 067 · 월간 마케팅 성과 분석 |
| 주간 광고 보고 | 스킬 045 · 광고 주간 성과 분석 |
| 제안서 | 스킬 084 · 제안서 작성 (제휴면 스킬 087 · 제휴 제안서 작성) |
| 보도자료 | 스킬 083 · 보도자료 작성 |
| 회의록 | 스킬 093 · 회의록 정리 |
| 예산안 | 스킬 095 · 마케팅 예산 설계 |
| 외주 요청서 | 스킬 094 · 외주 요청서 작성 |
| 이벤트 기획서 | 스킬 035 · 이벤트 기획 |
| 상세페이지 기획서 | 스킬 051 · 상세페이지 기획 |
| 월간 콘텐츠 계획 | 스킬 021 · 월간 콘텐츠 기획 |

- 표에 없는 문서면 `100-skills/ROUTING.md` 에서 가장 가까운 스킬을 찾는다. 맞는 스킬이 없으면 짝을 짓지 않고
  「이 양식 그대로 나만의 스킬 만들기(스킬 092)로 새 스킬을 만들 수 있습니다」를 한 줄 권한다
- 짝지은 파일 이름을 `profile.md §8` 의 「자주 쓰는 회사 양식」 칸에 적는다
- ⛔ 양식 파일은 고치지 않는다. 고객사 실명이나 단가가 들어 있으면 그렇다고 한 줄 알리고, 결과물에는 모양만 옮긴다

## ③-d 마무리, 작업 폴더 CLAUDE.md 와 우리 보완 초안

⛔ **우리 회사 정보를 넣었을 때만** 한다. `brand/profile.md` 가 `빈`(없음, 0바이트, 주석과 안내뿐, 템플릿 그대로)이거나 ① 샘플로 구축했으면
아래를 통째로 건너뛴다. CLAUDE.md 도 `skill-notes` 도 만들지 않는다.
책 실습은 빈 프로필과 샘플로 돌아야 원고와 같은 결과가 나오기 때문이다.

둘을 만들어 **한 화면에 보여 주고 ⏸ 한 번에** 받는다. 승인한 것만 저장한다.

```
마무리로 두 가지를 만들었습니다. 저장해도 될지 봐 주세요.

  ① 작업 폴더 CLAUDE.md ({n}줄)   우리 회사 요약입니다. 정본은 brand/profile.md 입니다
  ② 우리 보완 초안 {n}개
     스킬 067 · 월간 마케팅 성과 분석   월간보고_2026.pptx 양식대로, 첫 장은 대표 보고용
     스킬 045 · 광고 주간 성과 분석     매주 월요일 기준 지난 7일

  「전부 저장」, 「①만」, 「저장 안 함」 중에 말씀해 주세요.
⏸
```

### (a) 작업 폴더 CLAUDE.md

- 템플릿 `brand-templates/작업폴더-CLAUDE.md` 의 `{ }` 자리를 프로필 값으로 채운다. 맨 위 주석 줄은 옮기지 않는다. 30~40줄이다
- 빈 칸은 「비어 있음」으로 적는다. 지어내지 않는다. `[초안]` 이 붙은 값은 `[초안]` 을 그대로 둔다
- 작업 폴더 맨 위(`brand` 옆)에 `CLAUDE.md` 로 쓴다. ⛔ 이미 있으면 덮어쓰지 않는다. 지금 것을 보여 주고 맨 아래에 우리 회사 절을 붙일지 묻는다
- **프로필이 바뀌면 다시 쓴다.** 「브랜드 정보 넣을래」로 프로필을 고쳤으면 끝에서 (a) 만 다시 만들어 ⏸ 로 묻는다
- ⚠️ 클로드 코드는 작업 폴더의 CLAUDE.md 를 대화마다 읽는다. **코워크(데스크톱 앱)가 읽는지는 실측 전이다** `[추정]`.
  그래서 정본은 언제나 `brand/profile.md` 이고, 이 파일이 없어도 팀은 똑같이 돈다

### (b) 우리 보완 초안 `brand/skill-notes/{번호}.md`

**무엇을 만드나.** ③-c 에서 양식을 짝지은 스킬 전부와, 역할과 업종으로 자주 쓸 스킬 3~5개다.

| `profile.md §8` 내 역할 | 자주 쓸 스킬 |
|---|---|
| 팀장 | 067 월간 마케팅 성과 분석 · 045 광고 주간 성과 분석 · 095 마케팅 예산 설계 · 098 주간 업무 정리 |
| 실무 담당 | 아래 「넘긴다」의 업태별 첫 스킬 · 006 소비자 리뷰 분석 · 043 메타 광고 카피 작성 |
| 1인 대표 | 061 판매 데이터 분석 · 045 광고 주간 성과 분석 · 098 주간 업무 정리 |
| 대행사 담당 | 084 제안서 작성 · 067 월간 마케팅 성과 분석 · 045 광고 주간 성과 분석 |

업태(실물·B2B·구독·매장)에 맞지 않는 스킬은 뺀다. 채널을 안 하면 그 채널 스킬도 뺀다 (§5 채널 현황).

**무엇을 적나.** `brand-templates/skill-notes.md` 형식으로 **그 스킬에서만 바뀌는 것만** 적는다.

- 양식을 짝지은 스킬은 맨 위에 `형식: {확장자}` 와 `양식 원본: inputs/양식/{파일}` 두 줄을 쓴다
- 역할로 고른 스킬은 `docs/공통규약.md §0-a` 표에서 **그 스킬의 결과물에 해당하는 것**만 적는다 (예: 067 의 첫 장, 045 의 기간)
- ⛔ 역할과 보고 대상 자체는 적지 않는다. 그건 `profile.md §8` 에 있고 100개가 함께 읽는다 (규약 「다른 스킬에서도 쓰나」)
- `정한 날` 대신 `만든 날 {날짜} (구축 초안)` 을 쓴다. 실데이터로 처음 돌릴 때 양식에서 고칠 점을 묻는 자리가 남는다 (`docs/G3-분기절차.md §11`)

## 넘긴다 · 「마케팅 팀 업무 시작하자」

**구축은 3단계로 끝난다.** 여기서 스킬을 돌리지 않는다.
결과물을 만드는 것은 `ai-marketer` 의 일이고, 이 스킬은 **부를 말을 알려 주고 끝낸다.**

⛔ **여기서 스킬을 실행하지 않는다.** 권하고 넘긴다.

**별도의 조립 단계는 없다.** 프로필을 채운 순간 스킬 100개가 그 값을 읽고 돈다.
손익분기 ROAS, 업종 규제 사전, 기본 채널, 페르소나가 자동으로 들어간다.

⭐ **넘길 때 무엇부터 하면 좋은지 한 줄 권한다.** 사용자가 말한 것이 있으면 그것으로 권한다.
⛔ **`inputs` 의 파일을 권하는 이유로 들려면 파일 이름만 보지 않는다.** 열어서 머리 행이 그 스킬의 재료(리뷰면 본문·별점)인지 본 뒤에 적는다. 다르면 그 파일로 권하지 않고, 이름과 내용이 다르다고 한 줄 알린다 (실측 2026-09-15 코워크 · 「자사몰 리뷰 데이터.xlsx」는 쿠팡 광고 보고서였다. 그런데도 「바로 돌릴 수 있습니다」라고 권했다).

**없으면 업태에 맞는 것으로 권한다.** ⛔ 업태 불문 `001` 로 보내지 않는다.
B2B 마케터에게 키워드 리서치를 권하면 「내 일이 아니네」로 읽힌다.

| 업태 | 먼저 권할 것 | 왜 |
|---|---|---|
| **실물·D2C** | `001 키워드 리서치` | 입력이 가장 적고 결과가 눈에 보인다 |
| **B2B·솔루션** | `002 경쟁사 분석` | 리드가 없어도 오늘 나온다 |
| **구독·앱** | `006 소비자 리뷰 분석` (데이터 없으면 `012 제품 차별점 정리`) | 유지가 핵심이라 고객 말이 먼저다 |
| **매장 브랜드** | `031 인스타 피드 기획` | 매장 유입이 소셜에서 온다 |

⚠️ 애매하면 **묻지 말고 `001`** 을 권한다. 고르게 하지 말고 하나를 대 준다.
