# 주기 점검 · 저장 누락 · 원장 롤오버

> `SKILL.md` 끝 절에서 떼어 냈다 (2026-11-13 · 본문 500줄 기준). 글은 그대로 옮겼다.
> **`brand/profile.md` 가 이미 차 있어 점검으로 불렸을 때 · 「저장 안 된 거 있어?」 · 「원장이 두꺼워졌습니다」** 이 파일을 통째로 읽고 나서 그 단계를 한다. 기억으로 하지 않는다.

**목차**
- 주기 점검으로 쓸 때 · 스크립트 출력 읽는 법 · 재방문 신호
- 저장 누락 점검 · 「저장 안 된 거 있어?」
- 원장 롤오버 · 「원장이 두꺼워졌습니다」

## 주기 점검으로 쓸 때

이미 `brand/profile.md` 가 차 있으면 ③을 건너뛰고 본체 ①만 실행한 뒤 아래를 확인한다.

**먼저 스크립트를 실행한다. 사람이 손으로 집계하면 빠뜨린다.**

```
node ${CLAUDE_PLUGIN_ROOT}/scripts/ledger-stats.mjs
```

> 📒 **세션이 열릴 때 이미 한 번 본다.** SessionStart 훅이 7일에 한 번 조용히 확인하고,
> 롤오버가 필요하거나 신호가 있을 때만 알린다 (`docs/원장-운영.md` §3).
> 사용자가 그 알림을 보고 왔으면 **여기서 전체를 다시 돌려** 처방까지 낸다.

한 번에 부피·스킬별 집계·진단 신호가 나온다. 아래 표는 그 출력을 읽는 법이다.

| 기계가 내는 신호 | 무슨 뜻인가 | 무엇을 묻나 |
|---|---|---|
| 🔕 무호출 | 90일째 안 돌았다 | 상시에서 내릴지 묻는다 |
| 🔁 재작업 | 평균 보완 2회 이상. **한 번에 안 나오는 스킬**이다 | 그 스킬의 `inputs`·브리핑이 부실하다 |
| ⛔ 차단 | 차단률 30% 이상 | 표현 규칙을 프롬프트에 미리 넣는다 |
| 📄 샘플 | 샘플률 80% 이상 | 실데이터가 안 붙어 있다. 프로필·MCP 확인 |
| 💾 저장실패 | 착지가 실패했다 | 회수 가능한지 본다 (아래 저장 누락 점검) |
| 🗣 라우팅 | **같은 말이 다른 스킬로 나뉘었다** (⛔ **체인은 뺀다.** 요청 한 줄이 스킬 4개로 가는 건 설계다) | 부를 말이 겹친다. 트리거를 나눈다 |
| 📁 착지실패 | 원장엔 있는데 **파일이 없다** | 「저장 안 된 거 있어?」로 회수한다 |
| 🚪 게이트기록 | 게이트는 탔는데 **`gate.md` 가 없다** | 결과 근거가 안 남았다 |
| 📊 형식위반 | **`writes_to` 와 다른 확장자**로 냈다 | 체인이 그 경로를 못 찾는다 |
| 🟡 롤오버 필요 | 800행 초과거나 연도가 바뀌었다 | 아래 「원장 롤오버」로 간다 |

**위 열은 전부 「이상」이다. 잘 쓰는 사람에겐 평생 표시되지 않는다.** 그것만 있으면
시스템이 먼저 말을 걸 일이 없다. 아래 셋은 이상이 아니라 **때가 된 것**이라
**훅이 먼저 꺼낸다** (다른 신호는 물어볼 때만 답한다).

| 재방문 신호 | 무슨 뜻인가 | 무엇을 묻나 |
|---|---|---|
| ⏰ 주기도래 | **평소 간격의 1.5배**를 넘겼다 (주기는 선언이 아니라 원장에서 계산한다) | 「이번에도 돌릴까요?」 ⏸ |
| 📌 미완 | 중단·차단된 뒤 **같은 스킬로 완료된 적이 없다** | 막힌 재료가 왔는지 · 고쳐서 다시 낼지 |
| 📎 플레이북 | 완료가 5건을 넘었지만 `my-playbook` 이 **빈 템플릿 그대로** | 091 진단을 돌릴지 묻는다. 097·098 이 이걸 읽는다 |

⛔ **꺼내되 가로채지 않는다.** 사용자가 다른 일을 말했으면 그 일을 먼저 하고
끝에 한 줄로 붙인다. 그리고 **멋대로 실행하지 않는다.** 「돌릴까요?」로 묻는다.

**기억도 함께 확인한다** (`docs/기억-운영.md` §7).

```
node ${CLAUDE_PLUGIN_ROOT}/scripts/memory.mjs doctor
```

| 신호 | 무슨 뜻인가 | 무엇을 묻나 |
|---|---|---|
| `인용없음` | 손으로 쓴 줄이다. 출처를 모른다 | 어느 실행에서 나왔는지 찾거나 지운다 |
| `끊긴링크` | 상대 페이지가 아직 없다 | **급하지 않다.** 그 주제를 다음에 남길 때 채워진다 |
| `비대` · `낡음` | 40줄 초과 · 180일 갱신 없음 | 묶어 줄일지 · 아직 참인지 |
| `고아` | 90일째 아무도 안 부르고 아는 것 1줄 이하 | **지울까요?** ⏸ (⛔ 점검이 지우지 않는다) |

⛔ **기억이 0쪽이어도 이상이 아니다.** 업무를 몇 건 마쳐야 생긴다.
다만 **완료가 10건을 넘었고 기억이 0쪽이면** G5 의 기억 단계가 안 돌고 있는 것이다. 그것만 짚는다.

기계가 집계하지 못하는 것은 손으로 본다.

| 확인하는 것 | 어디서 | 신호 |
|---|---|---|
| 승인이 막혀 있나 | ⏸ 에서 멈춘 채 끝난 건 | 3건 이상이면 브리핑이 무겁다 |
| 게이트가 도나 | `게이트` 열 | 발행물의 게이트 칸이 비어 있으면 건너뛴 것 |
| 결과가 파일로 남았나 | `outputs` | 원장엔 있고 파일이 없으면 **착지 실패** |

⛔ **스크립트가 없거나 노드가 없으면** 그 사실을 말하고 손으로 확인한다. **조용히 건너뛰지 않는다.**
확인하지 않고 「이상 없음」이라고 하면 점검을 한 것이 아니다.

고칠 지점은 **3개 이내**로 돌려준다. 10개를 적으면 하나도 안 고쳐진다.

### 저장 누락 점검 · 「저장 안 된 거 있어?」

**가장 조용히 새는 자리다.** 화면에 결과가 예쁘게 나오면 파일이 없는 줄 모른다.
그래서 **묻지 않아도 주기 점검에서 이것부터 확인한다.**

1. `logs/build-log.md` 의 **최근 8주** 행에서 **일시, 스킬 ID, 상태, 산출물 경로**를 읽는다
   (원장을 통째로 읽지 않는다. 날짜로 grep 하거나 tail 로 끊는다. `docs/공통규약.md §A`.
   그 기간의 행이 롤오버됐으면 `logs/archive/` 에서도 해당 기간만 읽는다. 「최근 8주만 봤다」고 말한다)
2. **완료 행에 기록된 실제 산출물 파일을 하나씩 확인한다.** 작업 폴더를 기준으로 경로를 읽고,
   날짜와 스킬 번호로 새 경로를 짐작하지 않는다. **폴더나 `plan.json`, `run.json` 만 남은 것은 산출물 저장이 아니다.**
   여러 파일을 냈으면 실행 기록(`run.json`)의 산출물 목록도 읽어 각 파일을 확인한다.
3. 없는 파일의 **건수와 실제 경로**를 낸다. 경로가 비었으면 「경로 기록 누락」으로 알린다.
   `저장실패` 행은 따로 알리고, `중단`, `차단됨` 행을 완료 산출물이 없다는 이유로 저장 누락에 넣지 않는다.

```
확인할 산출물 12개 중 파일 10개가 있습니다. 2개가 없습니다.

  2026-08-20  광고 주간 리포트(045)
    outputs/2026-08-20/045-weekly-ads-report/045-weekly-ads-report.html
  2026-08-18  상세페이지 카피(051)          ⚠️ 고객이 볼 글인데 규제 검사 기록도 없습니다
    outputs/2026-08-18/051-detail-page-24/051-detail-page-24.docx

  대화 기록이 남아 있으면 「방금 거 저장해줘」로 옮길 수 있고,
  아니면 다시 돌려야 합니다. 다시 돌릴까요?
```

**저장 경로는 사용자 설정과 실행 종류를 함께 본다.** `brand/profile.md §7` 의 저장 설정과
체인의 프로젝트 폴더 규칙을 먼저 확인한다 (`docs/공통규약.md §H`). 날짜별 기본 경로와
다르다는 이유만으로 저장 실패라고 하거나 이동을 제안하지 않는다.

```
outputs/2026-08-22/045-weekly-ads-report/…   ← 단일 스킬의 기본 경로
outputs/2026-08-신제품런칭/01-…/…            ← 체인의 프로젝트 경로
```

파일은 있지만 **사용자가 정한 경로와 실행 계획에 모두 어긋난 경우에만** 경로 불일치로 따로 알리고,
옮기고 원장을 고칠지 묻는다. 파일이 없는 저장 누락과 별도로 집계한다.

⛔ **0건이면 「0건」이라고 말한다.** 조용히 넘어가면 점검을 한 건지 알 수 없다.

### 원장 롤오버 · 「원장이 두꺼워졌습니다」

원장은 지우지 않고 쌓는다. 그래서 언젠가 반드시 커진다.
문제는 디스크가 아니라 **매 작업 앞에서 읽는 비용**이다. 원장이 두꺼우면 일이 느려진다.

**여기가 원장 부피를 집계하는 유일한 자리다.** 그리고 **집계는 기계가 한다.** 위 `ledger-stats.mjs` 가 이미 결정해 준다.

```
✅ 부피 정상        아무 말도 하지 않는다
🟡 롤오버 필요      ⏸ 로 제안한다 (800행 초과 또는 연도 변경)
```

```
실행 기록이 1,240줄까지 늘었습니다 (2026-01-04 ~ 2026-12-28).
작업할 때마다 이걸 다 읽으면 느려집니다.

  2026년 기록 1,240건  →  logs/archive/build-log-2026.md
  logs/build-log.md  →  헤더만 남기고 2027년부터 새로 쌓습니다
  logs/build-log-summary.md  →  스킬별 최종 실행일·누적 건수로 갱신 (90일 점검이 이걸 봅니다)

  옮기는 것이지 지우는 것이 아닙니다. 아카이브는 그대로 남습니다.

⏸ 옮길까요?
```

승인받으면 순서대로 한다.

1. `logs/archive/` 가 없으면 만든다
2. **데이터 행만** 잘라 `logs/archive/build-log-{연도}.md` 로 옮긴다. 헤더·스키마는 원장과 **같게** 복사한다
3. `logs/build-log.md` 는 머리말과 표 헤더만 남긴다
4. 요약 원장을 갱신한다. **손으로 집계하지 않는다.** 기계가 아카이브까지 합쳐 다시 집계한다

   ```
   node ${CLAUDE_PLUGIN_ROOT}/scripts/ledger-stats.mjs --summary
   ```
5. 옮긴 행 수와 아카이브 경로를 말한다. **몇 건을 어디로 옮겼는지 말하지 않으면 지운 것과 구별되지 않는다**

⛔ **묻지 않고 옮기지 않는다.** ⛔ **행을 지우지 않는다.** ⛔ **아카이브의 열 순서를 바꾸지 않는다.**

> 롤오버 뒤에도 지난 기록은 찾을 수 있다. 「작년에 뭐 했지」는 `logs/archive/` 를 grep 하면 된다.
> 정본 규칙은 `docs/원장-운영.md` §2.
