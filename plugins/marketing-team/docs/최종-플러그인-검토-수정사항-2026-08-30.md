## 3. P0 · 승인 전 스크립트 실행 범위 축소

### 문제

`scripts/runtime-guard.mjs`의 `isPluginScript()`가 `${CLAUDE_PLUGIN_ROOT}/scripts/` 아래의
모든 `.mjs`를 허용한다. 승인 전 분기에서도 이 함수가 참이면 Bash 호출이 통과한다.

따라서 상태 확인용 스크립트뿐 아니라 다음처럼 파일을 바꾸는 스크립트도 승인 전에 호출될 수 있다.

- `bootstrap.mjs`
- `build-routing.mjs`
- `build-catalog.mjs`
- `build-stats.mjs`
- `sync-skills.mjs`
- `eval-routing.mjs --update-baseline`
- `run-receipt.mjs start`

### 수정 원칙

경로 단위 허용을 **스크립트 파일명 + 하위 명령 + 현재 승인 상태** 허용 목록으로 바꾼다.

| 상태 | 허용할 명령 | 차단할 명령 |
|---|---|---|
| 승인 전 | 읽기 전용 Bash · `router.mjs` 후보 조회 · `chain-compiler.mjs check/list` · `plan-compiler.mjs compile/check` | `run-receipt start/review/finalize` · 생성 스크립트 · 동기화 스크립트 |
| 문장 승인 후·계획 봉인 전 | `plan-compiler.mjs approve/check` · `plan.json` 수정 | 산출물 생성·영수증 시작 |
| 계획 해시 승인 후 | 계획에 필요한 `run-receipt.mjs` 명령 · 읽기 조회 | 빌드·동기화·기준선 갱신 · 임의 Node 스크립트 |

운영 중 필요한 스크립트만 명시한다. `scripts/`에 새 파일이 생겼다는 이유만으로 자동 허용하지 않는다.
빌드·카탈로그·동기화 스크립트는 개발자 명령이며 마케팅 실행 훅의 허용 대상이 아니다.

### 필수 회귀 테스트

- 승인 전 `plan-compiler compile`은 통과한다.
- 승인 전 `run-receipt start`는 차단된다.
- 승인 전 `bootstrap.mjs`는 차단된다.
- 승인 전 `build-routing.mjs`는 차단된다.
- 승인 전 `sync-skills.mjs`는 차단된다.
- 문장 승인 후 `plan-compiler approve`는 통과한다.
- 계획 봉인 후 `run-receipt start`는 통과한다.
- 계획 봉인 후에도 `python3`, heredoc, 임의 Node 파일 실행은 차단된다.

완료 기준: **승인 전 작업 폴더·플러그인 패키지 변경 0건**.

## 4. P1 · 재실행 산출물 1:1 계약

### 문제

`plan-compiler.mjs`와 `run-receipt.mjs`는 `결과-2.md`를 정본 `결과.md`의 재실행 파일로 인정한다.
현재 방식은 `결과.md`와 `결과-2.md`를 한 실행의 outputs에 동시에 넣어도 둘 다 같은 계약에
매칭될 가능성이 있다.

### 수정 원칙

1. 실제 파일명을 정본 파일명으로 정규화한다.
2. 정본 산출물 하나에 실제 파일이 **정확히 하나** 대응하는지 센다.
3. 같은 정본에 2개 이상 대응하면 중복 산출물로 차단한다.
4. 한 실행의 모든 재실행 산출물은 같은 순번을 사용하게 한다.

예시:

| outputs | 판정 |
|---|---|
| `result.md` | 통과 |
| `result-2.md` | 통과 |
| `result.md` + `result-2.md` | 차단 |
| `result-2.md` + `guide-3.md` | 차단 · 실행 순번 불일치 |
| `result-final.md` | 차단 · 계약 밖 이름 |

### 필수 회귀 테스트

- 단일 정본 파일 통과
- `-2` 파일 단독 통과
- 정본과 `-2` 동시 입력 차단
- 다중 산출물의 재실행 순번 불일치 차단
- `writes_to`에 없는 숫자·확장자 변형 차단

완료 기준: **정본 산출물과 실제 산출물의 대응이 항상 1:1**.

## 5. P1 · 체인 단계 간 입력 연결 강제

### 문제

`chain-compiler.mjs`는 계획에 workspace 입력이나 `depends_on`이 적혀 있을 때 연결을 검사한다.
다음 단계가 앞 단계 산출물을 입력에서 아예 생략하면 정본 순서만 맞고 입력 연결이 없는 계획이
통과할 수 있다.

### 수정 원칙

- 이름 있는 정본 체인은 선택된 변형을 기준으로 순차 의존 간선을 생성한다.
- 2단계부터는 직전 단계 산출물 중 최소 하나가 현재 단계 입력에 있어야 한다.
- 직전 단계가 아니라 더 앞 단계의 산출물을 직접 쓰는 구조는 `depends_on`으로 명시한다.
- 병렬 가능한 단계는 정본 체인 메타데이터에 병렬임을 선언하지 않은 이상 임의로 병렬 처리하지 않는다.
- 사용자 지정 역순은 자동 교정하지 않고 위험을 `plan.risks`에 남겨 다시 승인받는다.

### 필수 회귀 테스트

- 정본 체인의 정상 입력 전달 통과
- 중간 단계 누락 차단
- 순서는 맞지만 앞 산출물 입력 누락 차단
- 존재하지 않는 `depends_on` 차단
- 역방향·순환 의존 차단
- 선택 분기 `(022|024)`, `041(042)` 각각 통과

완료 기준: **체인 순서뿐 아니라 실제 산출물 전달 경로가 그래프로 확인됨**.

## 6. P2 · 라우터와 이벤트의 실제 연결

### 6-1. 라우터

현재 `router.mjs`는 존재하지만 AI 마케터의 G1 실행 절차에서 직접 호출되지 않는다.
또한 `routing-eval.jsonl` 문장을 운영 후보 색인에도 사용하므로 같은 문장으로 테스트하면 결과가
과대평가될 수 있다.

다음 중 하나를 선택한다.

1. **정식 사용:** G1에서 라우터를 호출하고, 운영 색인은 `triggers/name/description/when_to_use`만
   사용한다. `routing-eval.jsonl`은 평가에만 사용한다.
2. **보조 도구 유지:** 실제 라우팅은 AI+`ROUTING.md`가 담당한다고 명시하고, `router.mjs`를
   제품 정확도 근거에서 제외한다.

평가셋은 학습·색인용과 홀드아웃 검증용을 분리한다.

### 6-2. 이벤트

현재 이벤트는 `run.started`부터 시작한다. 계획 문서의 목표인 라우팅→승인→실행 전체 이력을
얻으려면 다음 이벤트가 추가로 필요하다.

```text
route.completed
plan.compiled
plan.approved
run.started
step.started / step.completed
review.recorded
run.completed / run.stopped
```

`router.mjs`와 `plan-compiler.mjs`가 이벤트를 직접 남기거나, 공통 오케스트레이터 명령이 세 도구를
호출하며 기록하도록 한다. 동일 실행을 묶을 `plan_id` 또는 상관 ID가 필요하다.

완료 기준: 한 번의 `summary`로 **라우팅부터 완료까지** 시간순으로 확인 가능.

### 결함 1 · `ledger-stats` 결합 옵션 우회

`runtime-guard.mjs`의 `pluginScriptCall()`은 첫 번째 인수만 `sub`로 추출한다. 허용 목록은
`ledger-stats.mjs: ['--check']`지만 다음 명령은 첫 인수가 `--check`라 허용된 뒤 실제 파일을 쓸 수 있다.

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/ledger-stats.mjs" --check --summary
node "${CLAUDE_PLUGIN_ROOT}/scripts/ledger-stats.mjs" --check --hook
```

수정 기준:

- 첫 인수만 비교하지 말고 전체 인수 조합을 검증한다.
- 승인 전과 승인 후 모두 `ledger-stats`는 순수 `--check` 호출만 허용한다.
- `--summary`, `--hook` 및 이 둘을 `--check`와 섞은 호출은 차단한다.
- `--check --summary`, `--check --hook`, `--check --dir <경로> --summary` 실패 회귀를 추가한다.
- 따옴표 우회 `--check "--summary"`, `--check '--hook'`도 차단한다. 공백 분리 후 `startsWith('--')`만
  보는 구현은 이 두 호출을 놓치므로, 셸 인수를 안전하게 토큰화하거나 허용 명령 전체 형식을 엄격히 대조한다.
- 정상 `--check` 허용 회귀는 유지한다.
