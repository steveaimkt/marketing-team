# 팀 헌장 · 이 조직이 왜 이 모양인가

> 규약(무엇을 지키나)은 [공통규약.md](공통규약.md) 에, 검토 절차는 [검토-절차.md](검토-절차.md) 에 있다.
> 이 문서는 **왜 그렇게 짰는가** 를 적는다.

## 1. 이것은 부조종사가 아니라 팀이다

부조종사는 사용자가 조종간을 잡고 있을 때 옆에서 돕는다.
이 팀은 요청을 접수해 담당을 찾고, 계획을 브리핑하고, 위임하고, 검열하고,
결과를 확인받고, 장부에 적고, 다음 일을 제안한다.

**사용자에게 남는 것은 조종간이 아니라 결재선이다.**

## 2. 사람이 개입하는 곳은 두 번뿐이다

요청 하나는 여덟 단계를 지난다 (디렉터 §2). 그중 ⏸ 는 둘이다.

| ⏸ | 무엇을 정하나 |
|---|---|
| **브리핑 게이트** | 무엇을 만들지 — 실행 **전에** 결과물의 형태를 합의한다 |
| **결과 확인 게이트** | 만들어진 것이 맞나 — 건네고 끝내지 않는다 |

나머지 여섯은 팀이 한다. **방향은 사람이 정하고, 반복은 팀이 지킨다.**

브리핑 게이트가 있는 이유는 하나다 — 다 만들어 놓고 「이게 아닌데」를 반복하는 것이
가장 비싼 낭비이기 때문이다. 형태를 먼저 합의하면 그 낭비가 사라진다.

## 2-a. 모드는 사용자가 채운 파일이 정한다

설치하면 담당 14명이 뜬다. **그런데 처음부터 일하지는 않는다.**

```
brand/profile.md 비었다   → ① 스킬        혼자 · 샘플로
brand/profile.md 찼다     → ② 내 에이전트  혼자 · 내 데이터로 · 기록이 쌓인다
brand/my-team.md 있다     → ③ 팀          위임 · 감사관 경유
```

**왜 파일로 정하나** · 사용자에게 「어떤 모드로 쓰시겠어요?」를 묻지 않기 위해서다.
모드를 고르는 것은 결정이고, 결정은 부담이다. 대신 **채운 만큼 올라간다.**
브랜드 정보를 채우면 저절로 ②가 되고, 팀을 짜면 저절로 ③이 된다.

**그리고 만들지 않은 조직이 일하지 않는다.** 편성 전에 팀장이 호출되면
사용자가 승인하지 않은 사람이 자기 브랜드 일을 한 것이 된다. 그건 팀이 아니라 사고다.

## 2-b. 디렉터는 메인 대화에 있다

디렉터는 **서브에이전트가 아니라 스킬**이다. 팀장·스태프만 서브에이전트다.

```
메인 대화 = 디렉터
   ├─ 팀장 호출 → 결과 회수
   ├─ 감사관 호출 → 판정 회수
   └─ 조립 · ⏸ · 기록
```

서브에이전트가 다시 서브에이전트를 부르는 것은 **기술적으로는 된다**(실측 확인).
그런데도 그렇게 두지 않는 이유는 셋이다.

1. **맥락이 두 겹으로 접힌다** — 팀장이 받은 요약을 다시 요약해 올린다. 근거가 두 번 깎인다
2. **⏸ 가 사용자에게 닿지 않는다** — 승인을 물어야 하는 자리는 대화가 살아 있는 곳이다
3. **비용이 겹친다** — 같은 브랜드 컨텍스트를 층마다 다시 싣는다

**내려가는 단계는 언제나 한 단이다.**

## 3. 만든 자가 검사하지 않는다

| 층 | 누구 | 못 하는 것 |
|---|---|---|
| 제작 | 팀장 10 | 자기 산출물의 규제 통과를 스스로 판정 |
| 품질 판정 | `staff-reviewer` | 제작 |
| 규제 판정 | `staff-gate-auditor` | 제작 |
| 스킬 제작 | `staff-skill-builder` | 실행 |

**감사관의 ⛔ 를 뒤집을 수 있는 것은 디렉터가 아니라 사용자뿐이다.**
디렉터가 뒤집을 수 있으면 게이트는 장식이 된다.

## 4. 팀장 10명은 스킬 100과 1:1이다

카테고리 10개 × 스킬 10개 = 100. 팀장도 10명. **이 대응은 고정이다.**

편성이 몇 팀이든 **파일 10개는 그대로 둔다.** 편성과 정원은 다른 층이다.
지금 안 쓰는 팀장은 **대기**로 두고, 켜는 조건을 한 줄 적는다.
대기 팀장을 지우면 다음에 그 업무를 시작할 때 처음부터 다시 만들어야 한다.

## 5. 담당은 평탄하게 둔다

`agents/` 아래에 `leads/` · `staff/` 같은 하위 폴더를 만들고 싶어진다. **만들지 않는다.**

플러그인으로 설치하면 **하위 폴더는 스캔되지 않는다.** 폴더로 열면 되는데
플러그인으로는 팀이 통째로 사라지는 일이 실제로 있었다.
정리는 **파일 이름의 접두사**로 한다 — `lead-*` · `staff-*`.

같은 이유로 **규약 문서는 `agents/` 에 두지 않는다.** 거기 있는 `.md` 는 전부 담당으로 등록된다.
README 가 담당으로 잡혀 명부에 뜨는 것을 본 적이 있다. 그래서 `docs/` 가 있다.

## 6. 기본값은 단일 담당이다

팀 소집은 **승급이지 기본이 아니다.** 같은 업무를 여럿이 돌리면 비용이 배로 든다.

> **산출물이 하나로 정해지는 일이면 단일, 판단이 갈릴 수 있는 일이면 여럿.**

여럿을 붙일 때는 표준 편성 셋 중에서 고른다. 즉흥 편성을 만들지 않는다.

| 편성 | 성격 | 언제 |
|---|---|---|
| 협업 릴레이 | 이어받는다 | 여러 팀이 이어달릴 때 |
| 검수 토론 패널 | 부딪힌다 | 판정이 갈릴 때 |
| 리서치 스웜 | 흩어진다 | 넓게 훑을 때 |

## 7. 파일로 남지 않으면 하지 않은 것이다

화면에만 뜨고 사라진 산출물은 다음 주에 없다.
**반환보다 파일이 먼저다.** 팀원은 파일을 쓴 뒤에만 요약을 반환하고,
리더는 결과가 안 와도 기다리지 않고 **먼저 파일을 확인한다.**

로그도 같다. **착지 기록이 없으면 실패로 본다.** 붙었을 것 같아도 적지 않는다.

## 8. 없는 것을 있다고 하지 않는다

- 스킬이 100개가 아니면 실제 개수를 말한다
- 실측 도구가 없으면 `[추정]` 을 붙인다
- 브랜드 정보가 없으면 `[샘플]` 을 붙인다
- 저장하지 못했으면 못 했다고 적는다

**못 한 일을 못 했다고 말하는 것도 산출물의 일부다.**
