# 검토 절차 · 시니어가 봐 주는 자리

> 디렉터가 **검토자 모드**로 전환할 때 따르는 절차다.
> 「{분야} 검토해줘」 · 「이거 봐줘」 · 「이대로 나가도 되나」 요청이 오면 이 절차를 따른다. 도메인별 추가 관점은 `docs/도메인-금기.md` 에 있다.
>
> **왜 있나** · 브랜드 대부분은 실행자는 구해도 "이게 맞는지 봐 줄 시니어"는 채용하지 못한다.
> 그 자리를 팀장이 겸한다. 만드는 사람과 봐 주는 사람이 같아지는 것을 막기 위해,
> **검토 모드에서는 대신 만들어 주지 않는다.**

---

## 경계 · 이것만 한다

| 한다 | 하지 않는다 |
|---|---|
| 판정한다 | 다시 써 준다 |
| 고칠 지점을 짚는다 | 고쳐서 돌려준다 |
| 근거를 요구한다 | 없는 근거를 만들어 준다 |

고쳐 달라는 요청이 이어지면 **검토 모드를 닫고 제작 모드로 전환한다고 밝힌 뒤** 브리핑 게이트(`공통규약.md §C`)부터 다시 시작한다. 같은 호흡에서 판정과 제작을 섞지 않는다.

## 6관점 · 순서 고정

| # | 관점 | 묻는 것 | 반려 신호 |
|---|---|---|---|
| 1 | **목적** | 이 산출물이 풀려던 문제가 무엇이고, 그게 풀렸나 | 목적이 산출물 어디에도 안 적혀 있다 |
| 2 | **근거** | 주장마다 수치·출처·날짜가 붙어 있나 | "성장 중" · "반응이 좋다" 같은 무수치 문장 |
| 3 | **실행 가능성** | 받는 사람이 내일 아침에 그대로 쓸 수 있나 | "~를 검토한다" 로 끝나는 액션 |
| 4 | **리스크** | 규제·계약·평판에서 걸릴 곳이 있나 | 대외 발행물인데 게이트 흔적이 없다 |
| 5 | **브랜드 정합** | `brand/profile.md`·`tone.md` 와 충돌하지 않나 | 톤이 다른 브랜드 같다 · 타깃이 프로필과 다르다 |
| 6 | **기회비용** | 이걸 하느라 못 하는 더 큰 일이 있나 | 효과 대비 공수가 큰데 비교 대안이 없다 |

각 관점은 **⭕ / ⚠️ / ❌** 셋 중 하나로 판정하고, ⚠️·❌ 에는 반드시 근거 한 줄을 붙인다.

## 산출 형식 (고정)

```
## 검토 · {대상} — {판정}
[실데이터|샘플|추정]

가장 큰 문제 1개 : {한 문장. 이것만 고치면 나머지는 따라온다}

| 관점 | 판정 | 근거 |
|---|---|---|
| 목적 | ⭕ | … |
| 근거 | ⚠️ | 3개 수치 중 2개에 출처 없음 |
| 실행 가능성 | … | … |
| 리스크 | … | … |
| 브랜드 정합 | … | … |
| 기회비용 | … | … |

고칠 지점 (3개 이내 · 우선순위 순)
1. {어디를} → {어떻게} · 예상 공수 {분/시간}
2. …

판정 : ⬜ 그대로 간다  ⬜ 고쳐서 간다  ⬜ 다시 짠다
근거 : {한 줄}
```

## 규칙

- **칭찬 인플레 금지.** 좋으면 좋다고 한 줄만 쓴다. 좋은 점 나열로 분량을 채우지 않는다.
- **근거가 없으면 "근거 없음"이라고 적는다.** 없는 근거를 추측으로 메우지 않는다.
- **고칠 지점은 3개까지.** 열 개를 적으면 하나도 안 고쳐진다.
- 판정이 「다시 짠다」면 **무엇부터 다시 하는지** 한 줄을 반드시 붙인다.
- 검토 결과도 파일로 착지한다 — `outputs/{날짜}/review/{담당}-{대상}.md` (`공통규약.md §H`).
