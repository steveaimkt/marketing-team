> `skills/ai-marketer/SKILL.md` 에서 떼어 냈다. **본체는 결정 나무의 뼈대**이고,
> 여기 절들은 **그 조건이 실제로 걸렸을 때만** 필요하다.

## 1. 물어서 좁힌다

「마케팅 업무 시작하자」·「일 시작하자」·「뭐부터 할까」처럼 **일이 특정되지 않은 채** 들어오면
스킬 이름을 나열하지 않는다. **하려는 일을 묻는다.**

```
어떤 일부터 하실까요?

  ① 알아보기    시장 규모 · 경쟁사 · 고객 유형 · 트렌드 · 리뷰
  ② 만들기      콘텐츠 · 광고 카피 · 상세페이지 · 보도자료 · 제안서
  ③ 돌아보기    판매 데이터 · 광고 성과 · 채널 · 월간 성과
  ④ 손보기      고객 여정 · 리뷰 관리 · 이탈 고객 되찾기 · 고객 응대
  ⑤ 정하기      가격 · 컨셉 · 예산 · 우선순위

  그냥 하고 싶은 걸 말씀하셔도 됩니다. ‘리뷰 분석해줘’처럼.
```

**분야 이름(시장조사·CRM)이 아니라 동사로 묶는다.** 사용자는 부서를 모르지 사고 싶은 것은 안다.

고르면 **그 안에서 2~3개만** 내민다. 열 개를 늘어놓지 않는다.

```
「알아보기」 시군요. 이 중 어느 쪽인가요?

  001  키워드 수요 조사   어떤 검색어로 들어오는지
  002  경쟁사 분석        경쟁 브랜드와 우리 차이
  006  소비자 리뷰 분석   고객이 뭘 불만스러워하는지

  다른 것도 있습니다. 「알아보기 전부 보여줘」
```

- **두 번 물어 끝낸다.** 세 번째 질문이 나오면 그냥 가장 가까운 것으로 시작하고 나중에 바꾼다.
- 고르면 ② 로 간다. **거기서부터는 평소와 같다.**
- 브랜드 프로필이 있으면 **안 하는 채널의 스킬은 후보에서 뺀다.**
  유튜브를 안 하면 「만들기」에 유튜브 대본을 올리지 않는다.

## 2. 스킬 밖이면 · 돌려보내지 않는다 (D4)

**100개는 자원이지 한계가 아니다.** 「그건 스킬에 없습니다」는 답이 아니다.
**넷 중 하나로 간다. 어느 것인지 사용자에게 밝힌다.**

| 결론 | 언제 | 무엇을 |
|---|---|---|
| **① 조합** | 여러 스킬을 이으면 된다 | 완주한다 · **어떤 번호를 왜 이었는지** 밝힌다 |
| **② 보완** | 스킬은 맞는데 우리 상황에 안 맞는다 | `brand/skill-notes/{번호}.md` · ⏸ 「계속 이렇게 할까요?」 |
| **③ 생성** | 100개에 없고 **반복될 일**이다 | `092` 로 **직접 만든다** — ⏸ 승인 후 · 제안만 하고 끝내지 않는다 |
| **④ 직접** | 한 번짜리라 만들 필요가 없다 | 내가 한다 · 산출물 첫 줄에 **`[절차없음]`** |

```
「우리 브랜드 컬러 팔레트 정해줘」

  100개에 색 팔레트 스킬은 없습니다. 제가 직접 하겠습니다. [절차없음]
  브랜드 스토리 작성(081)과 톤(brand/tone.md)에서 방향을 잡고,
  경쟁사 3곳(002 산출물)과 겹치지 않게 고르겠습니다.

  ⓘ 이 일이 또 생기면 스킬로 만들어 두겠습니다 (092).
```

⛔ **어느 경우에도 게이트·착지·원장은 그대로다.**
스킬 밖이라고 검사가 없어지지 않는다 — **명부 밖일수록 검사가 필요하다.**
발행물이면 `staff-gate-auditor` 를 부르고, 파일로 착지시키고, 원장에 1행 남긴다.

⚠️ **`[절차없음]` 을 숨기지 않는다.** 검증된 절차로 만든 것과 그때그때 만든 것은
다음 달에 재현될지가 다르다. 사용자가 그것을 알아야 한다.

**2와 3은 순서가 아니라 한 동작이다.** 「먼저 본다」로 두면 샌다 —
`ROUTING.md` 를 열 때 `INDEX.md` 도 같이 연다. 파일이 없으면 그냥 넘어간다.

| 상황 | 무엇을 고르나 |
|---|---|
| 사용자 문장이 `INDEX.md` 의 **등록 트리거와 정확히 일치** | **사용자 스킬** |
| **의미상만** 겹친다 | **공식 스킬** — 검증된 절차가 있다 |
| 둘을 구분할 정보가 없다 | **한 번 묻는다.** 임의로 고르지 않는다 |

⛔ **`brand/my-skills/` 의 스킬은 `gate:` 가 없으면 `true` 로 본다.**
명부 밖이라 G 열이 없다. 내부 문서임이 `gate: false` 로 명시됐을 때만 건너뛴다.
**명부 밖 스킬일수록 검사가 없어지면 안 된다.**

## 3. 회수 · 안 남았을 때

**파일이 안 남는 일이 있다.** 화면에만 냈거나, 쓰기 권한이 없었거나, 엉뚱한 곳에 갔거나.
그때 **결과물은 대화창에 아직 살아 있다.** 다시 만들지 말고 **옮긴다.**

| 사용자가 말하면 | 하는 일 |
|---|---|
| 「방금 거 저장해줘」 | 직전 산출물을 **그대로** 올바른 경로에 쓴다. **다시 만들지 않는다** |
| 「파일 어디 갔어?」 | `outputs` 를 훑어 **규칙 밖 경로**에 있는 것을 찾아 옮기고 원장을 고친다 |
| 「저장 안 된 거 있어?」 | `logs/build-log.md` 의 **최근 8주** 행과 실제 파일을 **대조**해 빠진 것을 목록으로 낸다 (통독하지 않는다 · 「최근 8주만 봤다」고 말한다) |

```
실행 기록에는 3건인데 실제 파일은 2건입니다. 1건이 비었습니다
  045 광고 주간 성과 분석 (2026-08-20)  ← 대화 기록에 남아 있으면 옮기고, 없으면 다시 돌립니다
```

⛔ **회수도 못 하면 그 사실을 적는다.** 「대화 기록에 없어 다시 돌려야 합니다」.

## 4. 형식과 바깥 능력 · 그릇을 고르고 공식 스킬에 넘길 때

### ⭐ 산출물 형식도 **묻고 정한다** (2026-09-01)

**기본 형식은 스킬이 정한다**(`writes_to`). 다만 **같은 내용을 다른 그릇에 담는 편이 나은 때**가 있다.
표로 볼 것인지 문서로 볼 것인지는 **쓰는 사람이 안다.** 만든 뒤에 「이 형식이 아닌데」가 되면 다시 만들어야 한다.

**계획에 두 줄을 낸다.**

```
  나오는 형식   문서 .md  ← 기본
  다른 그릇     표 .csv 로 받으시려면 「진행 승인. csv 로」
                ↑ 받으면 계획의 `형식` 에 적고 승인과 함께 봉인한다
```

**그릇은 성격이 정한다. 전부 `.md` 로 뭉치지 않는다.**

| 무엇이 나오나 | 그릇 | 왜 |
|---|---|---|
| **행이 많은 표**, 30일 캘린더, 건별 분류, 키워드 100개 | **`.csv`** | 엑셀에서 **정렬·필터**해야 쓸 수 있다. `.md` 표는 읽기만 된다 |
| **읽는 글**, 해설, 판단, 제안 | **`.md`** | 사람이 위에서 아래로 읽는다 |
| **보는 것**, 대시보드, 시안 | **`.html`** | 브라우저에서 바로 열린다 |
| **발표하는 것**, 제안서, 덱 | **`.pptx`** | 공식 스킬에 넘긴다 (없으면 `.md`) |

⭐ **표와 해설이 함께 나오면 두 파일로 낸다.** 표는 `.csv`, 해설은 `.md`.
한 파일에 섞으면 **표를 쓰려고 잘라내야 한다.** 이미 그렇게 도는 스킬이 열넷이다.

⛔ **「저장 파일(.md)」이라고 적혀 있다고 `.md` 만 내지 않는다.** 스킬의 `writes_to` 가 정본이다.
⛔ **그릇을 안 밝히고 넘어가지 않는다.** 계획의 「나오는 형식」은 **비워 둘 수 없는 줄**이다.

- **하나만 제안한다.** 고를 것을 셋씩 늘어놓으면 승인이 늦어진다.
- **성격에 맞을 때만 낸다.** 카피 10안에 대시보드를 권하지 않는다.
- **별도 형식 요청 없이 계획을 승인하면 기본 형식으로 간다.** 승인 뒤 같은 형식을 다시 묻지 않는다.
- 🔴 **못 만드는 형식을 적지 않는다.** `.pptx` 처럼 공식 스킬이 있어야 만드는 것은
  **깔려 있는지 먼저 보고** 적는다 (§공식 스킬 인계). 없으면 `.md` 로 내고 그렇게 말한다.

#### 어떤 형식으로 나오는지도 여기서 **확인받는다**

**만든 뒤에 「이 형식이 아닌데」가 되면 다시 만들어야 한다.** 형식은 실행 전에 확인한다.

⛔ **`document-skills`(xlsx·docx·pptx) 설치 여부는 `[실행 계획]`을 내기 전에 확인한다.** 승인을 받은 뒤에 미설치를 발견하면 계획 해시가 바뀌어 재승인을 한 번 더 받아야 한다(실측 2026-09-13 · 076·067). 미설치면 **처음부터** 「나오는 형식」 줄에 대체 형식(`.csv` 등)을 적어 낸다. **한 번의 `진행 승인`으로 끝낸다.**

⛔ **무엇을 몇 개 내는지는 스킬의 `writes_to` 가 정한다.** 실행 중 파일을 더하거나 빼지 않는다.

⭐ **다만 그릇은 사용자가 고른다 (2026-09-02).** 「csv 로 주세요」, 「워드로 받을게요」는
G2 에서 받아 **계획과 `run.json` 의 `형식` 에 적고 승인과 함께 봉인한다.**
이름 줄기는 그대로고 **확장자만** 바뀐다. 같은 이름의 `.md`가 겹치면 그 한 파일에 합친다.

```json
"형식": { "091-work-audit.xlsx": "csv" }
```

어느 정본을 무엇으로 바꾸는지 **이름으로 짚는다.** 같은 이름에 여러 그릇이 걸린 스킬이 있어서,
「csv 로」만 적으면 표를 바꾸라는 것인지 해설을 바꾸라는 것인지 갈리지 않는다.
받는 그릇은 7가지다. `.md` `.csv` `.xlsx` `.html` `.docx` `.pptx` `.pdf`.

⛔ **실행 중에는 안 바꾼다.** 다 만든 뒤 다른 그릇이 필요하면 **별도 계획과 승인**으로 간다.
한 실행에 끼워 넣으면 검토 범위와 완료 조건이 흐려진다.

**G2 는 이미 멈추는 자리다. 여기에 정본 형식과 후속 변환 필요 여부를 함께 올린다.**

```
  나오는 형식   표 .xlsx, 화면 .html, 해설 .md
  다른 그릇     표를 csv 로 받으시려면 「진행 승인. 표는 csv 로」 라고 답해주세요
  더 맞는 형식  대시보드 .html, 필요하면 완료 뒤 별도 계획으로 제안

  [승인 요청]
  ⏸ 이대로 갈까요?   진행하려면 `진행 승인`이라고 답해주세요.
```

**더 맞는 형식이 있으면 하나만 제안한다.** 이번 실행의 허용 파일과 섞지 않는다.

**완성물 요청은 초안부터 최종까지 한 실행이다.** G2에서 정한 형식으로 계획을 봉인하고,
영수증은 처음부터 `"단계": "최종"`으로 시작한다. `.md` 초안을 먼저 쓴 뒤 승인한 최종 파일을
만들며 형식을 다시 묻지 않는다. 초안만 요청받았다면 계획도 `.md`만 내도록 정하고
`"단계": "초안"`으로 실행한다. 그 뒤의 변환은 새 계획·승인·영수증으로 분리한다.
정본은 `docs/실행-영수증.md §0-a`다.

### 바깥 능력은 여기서 정한다, 스킬이 아니라 **지금 환경**이 정한다 (2026-09-01)

바깥 연결(MCP, 웹 조사, GA4)과 **공식 스킬**(pptx, docx, xlsx)은 성격이 같다.
둘 다 **실행 시점에만 알 수 있는 것**이라 스킬 100개에 각자 적지 않는다.
스킬은 **무엇이 필요하고 무엇을 내는지**만 안다 (`inputs`, `outputs`, `sample_fallback`).
**지금 무엇이 붙어 있는지 보고 정하는 일은 여기서 한 번만 한다.**

**계획을 낼 때 셋을 한다.**

| | 무엇 |
|---|---|
| **본다** | 이 일에 필요한 것이 지금 붙어 있나, 연결, 공식 스킬 |
| **정한다** | 있으면 실측으로. 없으면 4단 사다리로 (`docs/데이터-가져오기.md`) |
| **밝힌다** | 계획의 **「근거로 쓰는 것」, 「나오는 형식」** 줄에 한 줄로 적는다 |

```
  근거로 쓰는 것    네이버 데이터랩이 연결돼 있어 실측합니다 (상대지수).
                    절대 검색량은 [추정] 으로 표기합니다
  나오는 형식       발표자료 .pptx, 내용은 제가 쓰고 파일은 공식 pptx 스킬이 만듭니다
```

⛔ **없는 연결을 있는 척하지 않는다.** 「연결돼 있습니다」는 **확인한 뒤에만** 쓴다.
⛔ **연결이 없다고 멈추지 않는다.** 연습용 자료로 완주하고 `[샘플]` 을 붙인다.

**공식 스킬 인계, 만드는 일만 넘긴다.**

| 계획의 「나오는 형식」이 | 어떻게 |
|---|---|
| `.pptx` (제안서 작성 084, 영업 발표자료 작성 085, 제휴 제안서 작성 087) | **내용은 우리가 만들고** 파일로 바꾸는 일만 공식 pptx 스킬에 넘긴다 |
| `.docx`, `.xlsx` | 같은 방식으로 넘긴다 |
| 공식 스킬이 **안 깔려 있다** | 표(`.xlsx`)는 `.csv`, 문서(`.docx`·`.pptx`)는 `.md` 로 계획의 「형식」에서 바꾸고 **그렇게 말한다**, 「pptx 로 받으시려면 …」 한 줄. 같은 이름 `.md` 가 이미 있으면 **그 한 파일에 합친다** |

**대부분 이미 깔려 있다.** 없을 때만 이 두 줄을 안내한다. 한 번 깔면 계속 쓴다.

```
/plugin marketplace add anthropics/skills
/plugin install document-skills@anthropic-agent-skills
```

`document-skills` 는 4가지다. `pptx`(발표자료), `docx`(워드), `xlsx`(엑셀), `pdf`.
**받는 쪽에도 쓴다.** 사용자가 주는 제안요청서·공고문·견적서·회의 녹취록이
PDF, 워드로 오면 이것이 있어야 읽는다 (제안서 작성 084, 수상·인증 지원서 작성 090,
견적 비교 분석 096, 회의 결과 정리 086).

⚠️ **한글(HWP) 은 여기 없다.** 공공 공고문이 한글 파일이면 **다른 이름으로 저장(PDF, 워드)** 을 안내한다.
⛔ **설치를 강요하지 않는다.** 없으면 `.md` 로 내고 완주한다.

⛔ **넘겨도 줄어드는 절차는 없다.** 규제 검사, 실행 영수증, 파일 착지, 원장 그대로다.
⛔ **`.pptx` 라고 적어 놓고 `.md` 를 내지 않는다.** 못 만들면 **계획에서 미리 형식을 바꾼다.**
🔴 만드는 일을 넘길 뿐 **판단을 넘기지 않는다.** 무엇을 쓸지는 우리가 정한다.

| 결과물이 이러면 | 권하는 형식 | 왜 |
|---|---|---|
| 숫자·추이·비교가 중심 | **대시보드 `.html`** | 표로 읽는 것보다 한눈에 들어온다 |
| 행이 많고 다시 계산할 것 | **데이터 `.csv`** | 엑셀에서 이어서 만진다 |
| 남에게 **보고·발표**한다 | **`.pptx`** | 문서를 옮겨 붙이는 일이 사라진다 |
| **사내 회람·주석**을 받는다 | **`.docx`** | 변경 이력과 메모가 워드에서 돈다 |
| 읽고 고칠 글 (카피·기획서·보도자료) | **문서 `.md`** | 그대로 복사해 쓴다 |

- **`.pptx`, `.docx` 를 후속으로 제안하기 전에 만들 수단을 확인한다** (`docs/공통규약.md §H`).
  없으면 「수단 없음, `.md` 개요 변환 가능」이라고 밝힌다.
- ⛔ **승인한 최종 파일과 보존할 `.md` 초안만 낸다.** 계약 밖 파일과 이름 변경은 `run-receipt start`가 거부한다.
- **확장자는 사용자가 고르면 바꾼다**. 계획과 `run.json` 의 `형식` 에 적는다 (§어떤 형식으로 나오는지도 여기서 확인받는다).
- 다른 형식이 필요하면 현재 실행을 완료한 뒤 **새 계획, 새 승인, 새 실행 영수증**으로 분리한다.
- **체인이면 한 번만 묻는다.** 4단계마다 묻지 않는다. 단계별 기본 형식을 한 화면에 보이고
  「이대로 갈까요?」로 한 번에 받는다.

**🎨 이미지는 한 겹 더 멈춘다.** 프롬프트가 초안이고 그림이 최종이다.
`025` · `031` · `043` · `052` 넷이 해당한다. 생성할 **개수와 대상이 미정이면**
「썸네일 3안 중 몇 번을 만들까요?」처럼 함께 묻는다. 사용자가 이미 대상과 개수를 지정해
생성을 요청했다면 같은 내용을 다시 묻지 않는다.
도구가 없으면 프롬프트까지가 끝이고, 그것도 완주다.

⚠️ **`writes_to` 는 「반드시」가 아니라 「고르지 않으면」이다.**
사용자가 고른 그릇은 계획의 `형식` 에 적히고 영수증 계약이 그것으로 바뀐다.

## 5. 계획보다 먼저 묻는 질문 · 스킬 자체 게이트가 실행 경로를 정할 때

⛔ **단, 스킬 자신의 게이트가 "무엇을 다시 실행할지" 자체를 가르는 질문이면 계획 각주로 접지 않는다.**
   위 표의 **「있으면 좋은 것」**(없어도 그대로 진행, 무엇이 덜 나오는지만 밝히면 되는 것)과 이 경우는 다르다.
   대상 스킬의 `SKILL.md`에 자체 「게이트」 표(예: Phase 1 ⏸)로 **"앞 스킬을 먼저 돌릴지 말지"** 같이
   실행 경로 자체가 갈리는 질문이 적혀 있으면, 그 질문은 `[실행 계획]`보다 **먼저** 제 turn으로 낸다.
   답은 **자유 문장**으로 받는다. "그대로 진행해줘." 같은 자연스러운 답이면 충분하고, 이때는
   `진행 승인` 같은 정확한 문구를 요구하지 않는다. 답이 정해진 뒤에야 그 결과를 반영한
   `[실행 계획]`을 내고 `[승인 요청]`으로 평소대로 정확한 「진행 승인」을 받는다.
   실측 2026-09-14 · 076, 065 산출물이 없을 때 묻는 질문("등급 분석을 먼저 하시겠어요?")을
   계획 화면 안 각주("065를 먼저 돌려 RFM 기반으로 나누고 싶으시면 알려주세요")로 접어 넣었더니,
   사용자의 자연스러운 답("그대로 진행해줘.")이 「진행 승인」 문구와 달라 거부되고 정확한
   문구를 다시 요구했다. 데이터가 있는지 없는지를 알리는 것과, 그 결과로 무엇을 실행할지가
   갈리는 질문은 다르다. 뒤엣것만 따로, 먼저 묻는다.

## 6. 전제가 무너지면 G2 로 되돌린다

#### ⛔ 담당은 안 바꾼다. 그러나 **전제가 무너지면 G2 로 되돌린다**

**위의 「계획과 달라지면」은 못 한 경우다.** 한 것이 **틀린 경우**는 다르다.
「다시 고르지 않는다」는 **스킬 번호**에 대한 것이고, **결론의 전제**는 그 규칙 밖이다.

실행 중에 아래 3가지 중 하나가 드러나면 **그 자리에서 멈추고 G2 로 되돌린다.**

```
입력이 G1 에서 말한 것과 다르다           기간·행수·매체가 어긋난다
결론선이 바뀐다                          프로필 §4 를 읽었더니 손익분기가 계획과 다르다
앞 단계의 결론이 뒤 단계의 전제를 부순다    체인
```

되돌릴 때는 **무엇이 어떻게 달라졌는지 한 줄**과 **바뀐 계획 3줄**이면 된다.

```
계획은 7월 1일~31일이었습니다. 그런데 CSV 는 7월 15일부터입니다. 반달치입니다.
  1  광고 주간 리포트(스킬 045)를 7/15~7/31 로 좁혀서 돌립니다
  2  전월 대비는 못 냅니다. 비교할 6월치가 없습니다
  3  나머지는 계획 그대로입니다
⏸ 이대로 갈까요?
```

**실제 화면은 G2 와 같은 표식·승인 문구로 낸다.** 되돌린 계획도 계획이다. 같은 형식으로 다시 승인받는다.

- ⛔ **말없이 맞춰서 돌지 않는다.** 실측 2026-08-30 의 순서 바꿔치기와 같은 실패다.
  사용자는 시킨 것과 다른 결과를 받고, **왜 다른지도 모른다.**
- ⛔ **스킬 번호는 그대로다.** 전제가 바뀌었다고 담당을 다시 고르지 않는다.
  번호까지 틀렸다면 그것은 되돌림이 아니라 **G1 부터 다시**이고, 그때도 ⏸ 로 묻는다.
- **셋에 안 걸리면 되돌리지 않는다.** 더 나은 생각이 났다는 것은 되돌림 사유가 아니다.
  그것은 G5 의 「다음」에 적는다.
- 되돌려서 승인받았으면 **`run.json` 초안의 입력·기간을 고쳐 다시 `start` 한다.**
  옛 초안 위에 결과만 얹지 않는다 (`docs/실행-영수증.md`).

## 7. 여러 데이터 파일을 한 결론에 합칠 때

**여러 데이터 파일을 한 결론에 합칠 때는 먼저 기간표를 만든다.** 직접 비교·비율 계산은
모든 파일이 겹치는 공통 기간만 쓴다. 더 긴 파일은 추세 참고로만 쓰고, 결론의 기간과 섞지 않는다.
기간 열이 없으면 `[기간 미확인]` 으로 표시해 비교 계산에서 뺀다. 고객 단위 결합은 공통 키가
실재할 때만 하며, 이름·이메일 같은 개인정보를 새 결합 키로 만들지 않는다.

⛔ **공통 기간만으로 합치지 않는다.** 겹치는 지표의 정의와 합계도 먼저 대조한다. 같은 정의인데
합계가 다르면 `[자료 충돌]`로 표시하고 어느 자료가 기준인지 정하기 전까지 파일 사이의 합산·나눗셈·
전환율 계산을 금지한다. 각 파일 안에서 완결되는 비율만 쓴다. 플러그인 샘플을 둘 이상 쓰면
`sample-data/README.md`의 조합 가능 여부를 먼저 읽는다.

## 9. 개인 데이터 · `pii: true` 스킬일 때

#### ⛔ `pii: true` 는 담당보다 **기계가 먼저** 확인한다

**실측 2026-08-30**, 065 산출물이 무염 SHA-256 앞 8자를 「되돌릴 수 없는 대체키」라고 적었다.
**880개 전부 1초 만에 복원됐다.** 사업검토자는 「이 관점 밖」이라며 넘겼고, 규제검토자는
`gate: false` 라 불리지 않았다. 고친 뒤에도 **검토 보고서가 원문 ID를 되풀이해 다시 새어 나왔다.**
승인·봉인·`verify` 를 전부 통과한 산출물에 식별자가 살아 있었다.

**복원 가능 여부는 판단할 일이 아니라 계산으로 확인할 일이다.** 그래서 두 층으로 나눈다.

| 층 | 무엇이 | 무엇을 |
|---|---|---|
| **기계** | `run.json` 의 `pii` 블록 → `finalize`·`verify` 가 자동으로 | ① 원문 식별자 인용 ② 대체키 복원 가능성 ③ 원문↔대체키 대응표 잔존 |
| **담당** | `staff-gate-auditor` | 기계가 확인하지 못하는 것, 조합 재식별 위험, 수집 범위, 보관 기간 |

**`pii: true` 스킬을 돌리면 `run.json` 에 `pii` 블록을 반드시 넣는다.**

```json
"pii": {
  "source": "plugin:sample-data/A브랜드-고객마스터.csv",
  "id_columns": ["고객ID"],
  "surrogate_column": "대체키"
}
```

블록이 없으면 기계 검사가 **조용히 건너뛴다.** 그것이 가장 나쁘다.
`verify` 가 초록이어도 아무도 안 본 것이다. 정본은 `docs/실행-영수증.md`.

## 10. 기억 남기기 · 새로 알게 된 것이 있을 때

### 새로 알게 된 것이 있으면 남긴다 ⏸, `brand/memory/`

⚠️ **원장에 남는 것은 「무엇을 했나」뿐이다.** 이번에 알아낸 **경쟁사 가격, 고객 반응,
채널 특성**은 적지 않으면 증발한다. 석 달 뒤 같은 일을 할 때 처음부터 다시 알아내게 된다.

**판단하는 한 문장, 「다음에 같은 일을 할 때 이걸 몰라서 다시 찾게 될까?」**

| 남긴다 | 남기지 않는다 |
|---|---|
| 경쟁사가 8월에 가격을 12% 내렸다 | 이번 표 3행 값이 12,400원이다 |
| 이 고객군은 성분보다 가격에 먼저 반응한다 | 카피 20안 중 7안을 골랐다 |
| 경쟁 인하에는 예산보다 소재를 먼저 본다 | 스킬 046 을 돌렸다 (← 원장이 안다) |

**⛔ 0건이면 묻지 않는다.** 새로 안 것이 없는 실행이 대부분이다. 매번 물으면 잔소리다.

있으면 **G4 보고 뒤에 한 번** 보여주고 ⏸ 로 받는다. **최대 3건이다.**

```
이번에 남길 것 2건
  ① 경쟁사/올리브영, 8월 초 주력 라인 가격 -12%
  ② 교훈/가격인하-대응, 경쟁 인하에는 예산보다 소재를 먼저 본다

남길까요?  (전부 / ① 만 / 안 함)          ⏸
```

예라고 하면 **초안 json 을 쓰고** 스크립트를 부른다. 손으로 md 를 만들지 않는다.

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/memory.mjs" capture --file outputs/{날짜}/{폴더}/memory.json
```

```json
{ "schema": "marketing-team.memory/v1",
  "run": { "receipt": "workspace:outputs/{날짜}/{폴더}/run.json" },
  "notes": [{ "slug": "경쟁사/올리브영", "title": "올리브영",
              "facts": ["8월 초 주력 라인 가격을 12% 내렸다"],
              "timeline": "경쟁 가격 인하가 ROAS 하락의 주원인으로 확인됐다",
              "links": ["교훈/가격인하-대응"] }] }
```

- ⛔ **`[출처: …]` 를 직접 쓰지 않는다.** 쓰면 거부된다. 스킬·날짜·**데이터 모드**를
  영수증에서 읽어 기계가 붙인다. 그래야 석 달 뒤에 「샘플로 안 것」이 실데이터로 둔갑하지 않는다.
- **주제는 여섯뿐**, `경쟁사`, `고객`, `채널`, `제품`, `캠페인`, `교훈`. 지어내면 거부된다.
- **자리는 주어가 정한다.** 046 으로 알아낸 경쟁사 가격은 `경쟁사/` 다. `캠페인/` 이 아니다.
- ⛔ **산출물 전문을 복사하지 않는다.** 한 줄 사실 + 원본 링크다. 정본은 언제나 `outputs` 다.
- 자리가 헷갈리거나 「점검해줘」가 오면 **`docs/기억-운영.md` 를 통째로 읽고** 한다.

## 11. 방식 남기기 · `my-playbook §3`

### 방식을 정했으면 남긴다, `my-playbook §3`

⚠️ **원장은 「무엇을 했나」만 담는다.** `요청` 열에 들어가는 것은 **부른 말**(「리뷰 분석해줘」)이지
G1, G2 에서 정한 **조건**이 아니다. 브리핑 게이트 ⏸ 앞에서 나온 「별점 3점짜리만 보자」 같은 말은
**적지 않으면 증발한다.** 다음 달에 같은 일을 할 때 처음부터 다시 정하게 된다.

**실행 중 방식 조건이 나왔으면 G5 에서 한 번 묻는다.**

```
이번엔 별점 3점짜리 리뷰만 보고 했습니다.
다음에도 같은 방식으로 할까요?          ⏸
```

예라고 하면 `brand/my-playbook.md` **§3 쌓인 규칙**에 1행 적는다.

```
| 스킬 | 정한 것 | 정한 날 |
|---|---|---|
| 소비자 리뷰 분석(006) | 별점 3점짜리만 따로 본다 | 2026-08-25 |
```

- **스킬 ID 가 원장과 이어 주는 열쇠다.** 번호 표기를 원장과 똑같이 쓴다. `이름(번호)`.
  ⚠️ 이것은 **장부 키**다. 화면 표기(`스킬 043 · 이름`)와 다르다. 장부는 기계가 괄호 번호를 읽는다.
- 그래서 §② 다시 확인이 두 겹이 된다. 원장에서 **「지난달에 했다」**, playbook 에서 **「그때 이렇게 하기로 했다」**.
- ⛔ **묻지 않고 적지 않는다.** 한 번 쓴 조건이 다음부터 기본값이 되는 것은 사용자가 정할 일이다.
- **조건이 안 나온 업무면 묻지 않는다.** 매번 물으면 잔소리다.
