# 기준본 · 저자가 실제로 돌려 확인한 결과물

> **여기 있는 파일은 원고에 실린 결과다.** 두 가지로 쓴다 (`docs/공통규약.md §H`).
> - **책 실습(샘플 자료 + 빈 프로필):** `scripts/run-receipt.mjs book` 이 이 폴더의 파일을 그대로 착지에 놓고 `화면.md` 를 낸다. 독자는 원고와 같은 결과를 받는다
> - **독자 자료나 브랜드 정보를 넣었으면:** 모양과 깊이의 본으로만 쓴다. 아래 「무엇을 보나」를 따른다

## 여러 턴으로 이어지는 장 · `대본/{체인}/`

8~13장처럼 계획 승인 뒤에도 사람 말이 이어지는 장은 `대본/{체인}/대본.json` 에 턴마다 사람 말 · 원고 답변 · 놓을 파일을 적고, 파일은 `files/` 에 둔다.
- 사람이 말을 보내면 `scripts/team-context.mjs` 가 다음 턴과 대 보고, 맞으면 그 턴의 파일을 `outputs/{월}-{체인}/` 에 놓고 원고 답변을 넘긴다
- 원고에 없는 말이 오면 대본을 끝내고 평소대로 돈다 · 브랜드 프로필을 채웠거나 독자 자료가 섞여도 대본은 돌지 않는다
- 이미지 차례는 새로 생성하지 않고 원고 이미지를 놓는다. 힉스필드 연결은 확인하고, 화면 맨 위에 「[샘플] 책 실습이라 원고 이미지를 그대로 놓았습니다」 한 줄을 붙인다 (저자 결정 2026-10-12)
- 원고 답변 가운데 그 작업 환경에서만 생긴 말(파일 지문 미확인, 내려받기 실패, 삭제 권한 없음)은 뺀다

## 무엇이 들어오나

- 스킬 하나에 **원고 결과 한 묶음**. 착지 파일 전부(`writes_to` 와 같은 이름)와 대화창에 낸 완료 화면 `화면.md`
- 파일 안의 실행 날짜 경로는 `{날짜}` 로 둔다. `book` 이 그날 날짜로 바꾼다
- 원고 작업 폴더에만 있던 사정(그 폴더의 다른 파일 이야기 등)은 `화면.md` 에서 뺀다
- 폴더 이름은 스킬의 착지 경로와 같다 · `{번호}-{슬러그}/`
- 언제·어느 판으로 돌렸는지는 `출처.md` 에 적는다 (착지에 놓지 않는다 · 결과 파일 첫 줄에 적지 않는다)

## 무엇을 보나

| 본다 | 안 본다 |
|---|---|
| 절 구성과 순서 · 표의 열 · 결론을 몇 줄로 쓰나 | 숫자와 브랜드 이름 (샘플 A브랜드의 값이다) |
| 근거를 어디까지 밝히나 · `[샘플]`·`[추정]`·`[증거 필요]` 를 다는 자리 | 문장 그대로 베끼기 |
| 「채우면 살아나는 것」 표에 무엇을 적나 | 날짜·경로 |

⛔ **독자 자료로 돌릴 때는 기준본의 문장을 산출물에 옮겨 적지 않는다.** 독자의 자료로 같은 자리를 채우는 것이 일이다.
⛔ **기준본을 입력 자료로 쓰지 않는다.** 읽을 자료는 `sample-data/` 의 나머지와 `inputs` 다.

## 어떻게 갱신하나

1. 고친 플러그인으로 다시 돌린다
2. 산출물 검사를 통과한 `.md` 만 가져온다 (`scripts/output-checks.mjs`)
3. 같은 파일을 스킬의 `example/output.md` 에도 반영한다 · 사람이 보는 예시와 기계가 보는 기준을 하나로 둔다
