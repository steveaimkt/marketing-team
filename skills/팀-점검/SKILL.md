# 팀 점검 · 있다고 말하지 않고 세어 본다

> **없는 것을 있다고 말하지 않는다.** 개수를 세고, 안 되는 것은 안 된다고 말한다.

> ⚠️ **경로 규칙은 `docs/공통규약.md §0` 이다.**
> `100-skills/` · `docs/` · `sample-data/` 는 **패키지 안** (플러그인이면 `${CLAUDE_PLUGIN_ROOT}` 아래, 폴더로 열었으면 현재 폴더).
> `brand/` · `outputs/` · `logs/` · `inputs/` 는 **언제나 현재 작업 폴더**다.

## 0. 작업 폴더부터 만든다 · 플러그인으로 설치했다면 특히

**팀은 패키지 안에 살고, 산출물은 지금 열려 있는 폴더에 떨어진다.** 둘은 다른 곳이다.

먼저 지금 폴더에 이 넷이 있는지 본다. 없으면 **묻고 만든다** (⏸).

```
brand/     내 브랜드 정보 · 팀 편성      ← 없으면 빈 템플릿을 만든다
outputs/   산출물이 떨어지는 곳
logs/      실적 원장 · 팀 소집 로그
inputs/    내 파일을 넣어 두는 곳
```

- **폴더로 클론해 열었다면** 이미 넷 다 있다. 그냥 넘어간다.
- **플러그인으로 설치했다면** 지금 폴더는 비어 있을 것이다. 이때 만든다.
  빈 템플릿은 패키지의 `brand/` 에서 복사해 온다 (`${CLAUDE_PLUGIN_ROOT}/brand/`).
- ⚠️ **패키지 안에 쓰지 않는다.** 거기 쓰면 플러그인을 업데이트할 때 산출물이 통째로 날아간다.

만들고 나면 한 줄로 알린다 — 「이 폴더가 앞으로 산출물이 쌓일 곳입니다: {경로}」

## 1. 기계 점검 · 먼저 돌린다

```bash
node scripts/verify.mjs
```

이 스크립트가 보는 것은 **"폴더로 열면 되는데 플러그인으로 설치하면 안 되는"** 함정 네 가지다.

| 검사 | 왜 |
|---|---|
| `plugin.json` 의 `repository` 가 문자열인가 | 객체면 **플러그인 전체가 로드되지 않는다** |
| `agents/` 에 하위 폴더가 없는가 | 하위 폴더의 담당은 플러그인에서 **통째로 사라진다** |
| `agents/` 의 모든 `.md` 에 frontmatter 가 있는가 | 없으면 그 문서가 **유령 담당**으로 등록된다 |
| `skills/` 가 한 단계인가 | 2단계 아래 스킬은 스캔되지 않는다 |

추가로 **참조 무결성**을 본다 — 담당·스킬이 가리키는 문서가 실제로 있는지.
(팀장 10명이 없는 파일을 가리키고 있어도 아무 에러가 안 나던 문제가 실제로 있었다.)

🔴 가 하나라도 있으면 **거기서 멈추고 고친다.** 고친 뒤 다시 돌린다.

## 2. 눈으로 확인 · 실제로 뜨는가

스크립트는 파일을 볼 뿐이다. **런타임에 실제로 등록됐는지**는 따로 본다.

```
/agents     → 15명이 나오는가 (디렉터 1 · 팀장 10 · 스태프 4)
/skills     → 4개가 나오는가
```

플러그인으로 설치한 경우엔 이렇게도 볼 수 있다.

```bash
claude plugin details marketing-team
```

| 증상 | 원인 | 대처 |
|---|---|---|
| 담당이 하나도 안 뜬다 | 플러그인 자체가 로드 실패 | `verify.mjs` 의 매니페스트 검사부터 |
| 팀장 10명만 없다 | `agents/leads/` 같은 하위 폴더에 있다 | 최상위로 올린다 |
| 모르는 담당이 섞여 있다 | `agents/` 에 규약 문서가 들어 있다 | `docs/` 로 옮긴다 |
| 방법론을 불러도 안 걸린다 | 방법론 100개는 **등록되지 않는다.** 원래 그렇다 | `방법론찾기` 가 명부를 열어 찾는다. 번호로 불러도 된다 (「046 돌려줘」) |

> ⚠️ **방법론 100개는 Claude Code 에 스킬로 등록되지 않는다. 의도된 설계다.**
> 100개를 다 등록하면 매 세션 약 1만 5천 토큰이 항상 실린다.
> 대신 명부 한 장(`100-skills/ROUTING.md`)만 보고, 본문은 매칭된 순간에 연다.

## 3. 무엇이 있는지 보여준다

```
담당 15명
  디렉터 1   · 입구 하나
  팀장 10    · 방법론 100개를 10으로 나눠 맡는다
  스태프 4   · 규제 감사관 · 관점 검수관 · 방법론 제작관 · 자문단

방법론 100개
  001~010 시장조사   011~020 제품기획   021~030 콘텐츠
  031~040 소셜       041~050 광고       051~060 커머스
  061~070 데이터     071~080 CRM        081~090 브랜드·세일즈
  091~100 운영
  · 게이트 32개 (대외 발행물 · 발행 전 규제 검사)
  · 상태변경 7개 (예약·발행·예산 · 실행 전 ⏸ 승인)
  · 체인 15종 (「{체인 이름} 돌려줘」)
```

## 4. 브랜드 정보 · 안 채워도 된다

`brand/profile.md` 를 본다. **여기서 멈추지 않는다.**

- **비어 있다** → 정상이다. 이렇게 알린다.
  「안 채우셔도 다 됩니다. `sample-data/` 로 돌고 산출물에 **[샘플]** 이 붙습니다.
  내 브랜드로 바꾸면 그때부터 **[실데이터]** 가 됩니다.」
- **채워져 있다** → 브랜드명·업종을 한 줄로 확인시킨다

## 5. 첫 업무를 같이 돌린다 · 생략 불가

**설명으로 끝내지 않는다.** 하나를 실제로 돌려 산출물 파일을 보여준다.

무엇을 돌릴지 묻되, 답이 없으면 `001 키워드 리서치` 로 간다 (입력이 가장 적고 결과가 눈에 보인다).
끝나면 **산출물 경로**와 **첫 줄의 출처 태그**를 같이 보여준다.

## 주기 점검으로 쓸 때

이미 `brand/my-team.md` 가 있으면 위 1~2만 돌리고 아래를 센다.

| 세는 것 | 어디서 | 신호 |
|---|---|---|
| 누가 실제로 일했나 | `logs/build-log.md` | 90일 무호출 팀장 → 대기 검토 |
| 승인이 막혀 있나 | ⏸ 에서 멈춘 채 끝난 건 | 3건 이상이면 브리핑이 너무 무겁다 |
| 게이트가 도나 | `게이트` 열 | 대외 발행물인데 열이 비어 있으면 게이트를 건너뛴 것 |
| 결과가 파일로 남았나 | `outputs/` | 원장에는 있는데 파일이 없으면 착지 실패 |

고칠 지점은 **3개 이내**로 돌려준다. 열 개를 적으면 하나도 안 고쳐진다.
